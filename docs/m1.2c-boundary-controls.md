# Boundary controls: partial acceptance

The runner deliberately returns `blocked` with `writer_quiescence_unsupported`
after otherwise successful execution. No accepted export is returned: the tmpfs
archive is collected before pause, and therefore cannot establish a quiescent
submission. Execution uses bounded tmpfs storage; copy and execution phases have
separate deadlines, not one whole-call deadline. Permission preservation remains
incomplete.

Actual Docker controls passed with 16 tests, 96 assertions, zero failures/errors/
skips using pinned Alpine and agent image
`sha256:cbc8bd81c7ede30f09de318df230452f4d3a05e1e8aa9f08a4d46b7f24f437f1`.

Initial reviewer observation: 16 tests, 95 assertions, one failure because the
Python test did not explicitly override the agent image HOME/XDG declarations;
effective environment validation rejected it. The test now supplies the reviewed
SandboxOpenCodeLaunch HOME/XDG paths; production environment validation was not
relaxed. A subsequent probe exposed the test's assumption that Python lives at
`/usr/local/bin/python3`; the agent image uses a different location. The control
now resolves `python3` through the image's reviewed PATH. The resulting run passed
16 tests and 96 assertions with no skips.

Controls use synthetic canaries only: host file/socket positive calibration,
shell/Python absolute and traversal denial, private-layout/environment absence,
unsafe tree/export rejection, quota exhaustion, timeout/cancellation cleanup,
inspect-before-execution, unknown-image failure, descriptor directory replacement
race, and concurrent parent-cwd stability. These are not full OpenCode/native
three-arm acceptance or a proof of quiescent export.
