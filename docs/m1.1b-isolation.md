## Native procedure constraints

Cached `openhands/post_processor.py:265-295` writes a Dockerfile based on the
mutable task image tag and overlays candidate `workspace` onto `/workspace`.
`openhands/post_processor.py:518-532` removes listed packaging/test paths from the
candidate before building and executing native commands. An overlay cannot prove
that implementation files omitted by a candidate are absent from the result.

`openhands/post_processor.py:429-480` counts printable `N passed` text from pytest
commands. That is historical native behavior, not authoritative evidence. The
task's `pip install -e .` command also executes candidate packaging code. A JSON
report written by that Python process is no more independently authoritative than
stdout. Do not describe same-process reporting as attestation.

The current trusted helper allowlist names `/opt/agru/bin/grade-nl2repo`; its
existence in a verified task image has not been established. Its read-only root
and submission policy also cannot directly run native editable installation in
`/submission`. A task-specific writable implementation area and dependency policy
must be designed explicitly rather than silently relaxing the generic runner.

   can execute arbitrary trusted Ruby/Python/package code; neither structured

   `lib/agent_runtime/benchmarks/nl2repo_grader.rb`; reuse Store snapshots and
   existing adapter/experiment interfaces. Do not replace the generic framework.
   Define evidence binding for task/spec/tests/procedure/image/platform/submission

6. Before implementation, extend tests for approved API: omitted original source,
   forged stdout/structured report, evaluator crash/truncation, cleanup, frozen
   procedure identity and no host fallback. Execute reference, empty and incorrect
   controls only after assets and independent observations are available; persist
   each real attempt and regrade the same immutable submission.
