## Hook and veto semantics

V2 plugins use `@opencode/plugin` and
`export default Plugin.define({ id, setup(ctx) { ... } })`. The docs require
awaiting hook registration. V2 plugin discovery accepts package directories;
legacy single-file/V1 plugin assumptions cannot be carried over unchanged.

### Model selection is not the final wire identity

`packages/core/src/session/runner/model.ts:75-125` resolves a selected session
model, otherwise calls the resolver fallback. Missing explicit models fail with
`Model unavailable: <provider>/<model>`. The
`experimental.model.resolve` event can replace the resolved route within the
same provider and does not rewrite the session's selected model.

`packages/core/src/session/model-request.ts:278-305` associates each request
with `sessionID`, agent, model reference and kind. Kinds are `primary`,
`compaction`, `title`, and `generate`. The model reference is useful audit
context; inspect the serialized HTTP body too, because hooks/provider routing
can change the effective request.

`packages/core/src/session/model-request.ts:360-374` runs `model.request` before
transport creation. Its event permits base URL and header replacement. This is
not a request counter, a documented allow/deny result, or proof that there will
be only one HTTP attempt.

### Native HTTP interception is before/after actual dispatch

`packages/core/src/session/model-request.ts:375-405` installs native HTTP
middleware when either HTTP hook exists:

1. Convert the native request to a Web `Request`.
2. Await `http.request` at line 382.
3. Preserve the original body if the hook kept the same Request; otherwise
   rebuild from the replacement Request at lines 385-394.
4. Execute **`const res = yield* handler(sent)`** at line 395.
5. Await `http.response` at lines 396-403, then return the replacement response.

Therefore `http.response` is too late to prevent spending. Request and response
bodies are one-shot; clone before reading. To change the request body reliably,
replace the Request rather than consuming the original in place.

**Thrown-hook behavior:** `packages/plugin/src/promise/adapter.ts:629-632`
wraps a Promise callback with
`Effect.promise(() => Promise.resolve(callback(event)))`.
`packages/core/src/plugin/hooks.ts:88-94` invokes each matching callback and
**`yield* result`**, without a catch-and-continue wrapper. Consequently a thrown
or rejected `http.request` callback becomes an Effect defect and interrupts this
middleware before `handler(sent)`. It is **not** a typed, documented veto:
`packages/core/src/plugin/hooks.ts:23-29` gives session hooks a `never` failure
channel; only the tool execute-before hook has a declared failure channel.

This source ordering supports a pre-dispatch abort, but installed-binary
fixtures must establish defect propagation, error reporting, and absence of
outer recovery or additional attempts. The sibling native-HTTP fixture now proves
zero mock dispatch on throw for its pinned route; see the matrix below. Do not claim failure logging necessarily
continues the request: the inspected dispatcher does not do that. Conversely,
do not claim a security boundary merely because a callback can throw.

## Transports, retries and auxiliary work

- **WebSocket bypass:** docs and
  `packages/core/src/session/model-request.ts:407-420` distinguish native HTTP
  from `experimental.ws.handshake`. Native WS traffic does not pass through
  `http.request`/`http.response`; the handshake hook runs per model call before
  selecting a reusable connection. The HTTP fallback path does pass through
  HTTP middleware. `packages/core/src/session/model-transport.ts` implements
  connection reuse, stream-failure fallback and message-too-large fallback.
  An HTTP-only guard must not permit an unexamined WS route.
- **Legacy/AI-SDK boundary:**
  `packages/core/src/v1/config/migrate.ts:176-179` converts npm specifiers to
  `aisdk:` packages unless already native. `packages/core/src/aisdk-native.ts`
  subsequently maps supported SDK configurations to native providers;
  `@ai-sdk/openai-compatible` is in its mapping table. The actual resolved route
  depends on provider settings/model context. Existing npm metadata alone does
  not prove native-hook coverage; fixture-test the installed configuration or
  use an independently enforcing loopback proxy. Separate `aisdk` hook families
  exist and must not be conflated with native session HTTP hooks.
- **Retries:** `packages/core/src/model-retry.ts:22-34` defaults to ten retries
  after the original attempt, with exponential delay starting at two seconds,
  nominally capped at ten seconds per gap, plus jitter. Provider-requested
  retry-after delays are bounded at fifteen minutes (`:11-18`). Unreachable
  network errors have a separate one-hour retry window and thirty-second gap
  cap (`:38-60`), not the ordinary ten-retry allowance.
  `packages/core/src/session/runner/retry.ts:37-50` obtains the policy decision,
  runs the session retry hook, and honors `event.decision.retry === false`.
  This controls the runner retry decision, not every possible SDK, gateway,
  transport, title fallback or provider-side retry. A request ceiling belongs
  at the actual forwarding boundary.
- **Titles:** `packages/core/src/session/context.ts:99-133` selects the title
  agent's explicit model, a small model in the primary provider, or a lower
  reasoning variant. `packages/core/src/session/title.ts:144-148` can retry title
  generation on the primary model when a different selected model fails.
  `packages/core/src/session/model-request.ts:292-305` supplies default output
  limits to primary/compaction but leaves title/generate provider defaults.
  A primary `--model` and output cap are insufficient to bound title work.
- **Compaction:** docs say automatic compaction is enabled by default; disabling
  auto compaction does not disable an explicit compact operation. It has its
  own request kind and hooks. Do not confuse context-management completion with
  evaluation success.
- **Subagents/generate:** child sessions and transient generate calls are extra
  request-producing paths. `packages/core/src/session/generate.ts` and request
  kind coverage confirm generate exists; tool/subagent policy, ancestry and
  process-wide accounting still require installed-runtime fixtures. A
  single-agent CLI selection does not prove child spawning is impossible.
- **Fallback:** an explicit unavailable primary model is rejected by runner
  resolution, but absent selection permits a resolver fallback, title selection
  has its own fallback, and WS has transport fallback. Do not merge these into
  one claim such as “fallback disabled.”

## Pilot guard requirements, not a provider-call authorization

Before any separately authorized live request, the runner should establish:

1. Isolated configuration and private server; only the exact allowed model,
   provider and loopback gate are usable. Verify actual loaded configuration,
   rather than assuming `--model` erases inherited provider/plugin settings.
2. An independent forwarding gate that checks method, endpoint and exact body
   model; atomically reserves a conservative budget **before** forwarding; and
   covers every process/session/auxiliary attempt. Reject unknown usage/price
   representations rather than estimating a favorable value.
3. No alternate native/AI-SDK/WS/child-process egress. Config/tool isolation is
   operational separation, not a security sandbox. Solver shell/network tools
   must not provide an alternate request path or access to credentials.
4. Fixtures using the installed binary demonstrate title/compaction/generate,
   subagent, retry, fallback and thrown-hook behavior, including that denial
   causes zero upstream forwards. Stub/local requests are not live validation.
5. Evidence records binary/config/plugin/gate identities, actual forwarded
   upstream ID and request count, reservation/settlement, redacted transport
   receipts, execution status and separate evaluation verdict.

No secret-bearing config should be copied into solver workspaces, logs,
manifests or evidence bundles. The credential mechanism should be provided only
to the trusted forwarding component, not to a model-controlled subprocess.

## Independent launcher source audit (2026-11-15)

Inspected `lib/agent_runtime/execution/opencode_launch.rb:15-76` and
`test/opencode_launch_test.rb:5-29`; no production changes made by this audit.
Graph coverage reported generation `2026-11-15T08:45:54Z`, both paths
`no_recorded_issue`/`metadata_match` (best effort, not completeness proof).

Positive source findings:

- Executable hash is checked at construction and immediately before creating
  the environment (`:29`, `:44`, `:63-65`). This reduces accidental binary drift,
  but is not atomic execution-by-file-descriptor identity.
- The CLI selects the exact model and `--standalone`, with an explicit title
  (`:27-28`). Generated config sets both `model` and `smallModel` to the exact
  selector, native compatible provider, HTTP transport, one configured model,
  empty plugins and MCP (`:68-71`). No output/context limit is fabricated.
- Temporary HOME/XDG/config/cache/data/state paths, project-config disable and
  automatic-fetch/update disable flags are provided (`:46-56`). The config file
  uses mode `0600` and an environment placeholder rather than the secret value.
- Permissions default to deny, allowing only workspace read/edit (`:72-74`).
  This is intended to deny shell/network/subagent tools; actual tool permission
  enforcement and path pattern semantics still need installed-binary tests.
  V2 uses ordered `permissions` rules, not a legacy `tools` Boolean map.

Limits/blockers to stronger claims:

- The endpoint is the real local gateway, not an independently reserving proxy
  (`:12`, `:70`). The class explicitly reports `financial_exposure` as
  `not_hard_bounded` (`:38`). Do not relabel this launch as an enforced budget.
- `OMNIROUTE_API_KEY` is deliberately in the OpenCode process environment
  (`:52`). That is secret-free config persistence, **not** secret isolation from
  any subprocess the process can spawn. Denied tools reduce the intended access
  surface but are not an OS sandbox.
- The caller must actually clear inherited environment (`:41-42`); returning a
  small environment hash does not itself do so. The subsequently inspected
  `lib/agent_runtime/adapters/open_code_cli.rb:149-152` uses
  `ENV.to_h.transform_values { nil }.merge(environment)` before calling its
  runner, which clears the parent's currently present keys for the spawn.
  Effective runner spawning still deserves separate test evidence.
- Explicit primary/small selectors do not prove no alternate provider discovery,
  agent-specific override, title fallback or auxiliary call. The class does not
  install a per-request model/body enforcement gate. Its plugin list is empty,
  so the HTTP-hook fixtures do not imply a hook guards this launch.
- The current launch tests assert config construction/cleanup and digest denial;
  they do not prove effective installed config, denied tool calls, no child
  requests, no fallback, actual HTTP body model or credential non-inheritance.

The launcher is therefore appropriately described as trusted-local
configuration isolation with unbounded-by-this-class financial exposure, not
complete mediation or a secret-isolated solver boundary.

### Final source gate review: lexical read boundary

The final reviewed config changed to `read: "*"`/`edit: "*"` permissions with
separate policies denying skills, plugins, MCP, other providers and absolute
edit routes (`lib/agent_runtime/execution/opencode_launch.rb:67-80`). This
supersedes the workspace-pattern permission description above.

**Do not infer a filesystem boundary from outside-path denial alone.** Matching
upstream `packages/core/src/file-access.ts:90-100` determines internal paths by
lexical containment of either `location.directory` **or**
`location.project.directory`. `packages/core/src/file-access.ts:144-154` asks for
external-directory permission only after this classification, then accepts the
read permission. There is no canonical/symlink check in that classification.
An internal symlink pointing outside can therefore avoid the external-directory
check; a parent project worktree also enlarges the internal scope. A denied
`/etc/hosts` test does not cover those cases.

The NL2Repo preparation inspected at
`lib/agent_runtime/benchmarks/adapters/nl2repo.rb:117-127` creates an empty
repository and runs `git init -q`, writing only the public instruction outside
it. That is positive evidence against pre-existing hidden-test copies or
symlinks in this path, not a general guarantee for arbitrary solver workspaces.
Before the pilot, verify the actual prepared repository is independently rooted,
contains no links escaping it, and has no hidden procedure/test material. The
independent review requested a loopback internal-symlink-to-outside sentinel
probe from the fixture owner; that result remained pending when recorded.

At this review point, **hold the final launch gate pending the actual positive
workspace edit and outside-denial fixture results**, and resolution or explicit
scope exclusion of symlink/project-root escape. No inference was performed by
this investigator. Credential output remains an exposure if arbitrary external
read or subprocess execution becomes available: the process holds the key, even
though its generated config contains only the environment placeholder.
