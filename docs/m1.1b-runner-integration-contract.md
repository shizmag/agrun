# M1.1b runner integration contract (provisional)

This is an offline infrastructure contract, not an official-score claim. The
authenticated NL2Repo grader remains unavailable; no mock score is substituted.

## Intended boundary

- Register the built-in NL2Repo adapter in the existing CLI registry and pass the
  same Store to it. Use ExperimentRunner, Submission and Store unchanged as the
  persistence/evidence boundaries; do not introduce a second orchestrator.
- Admit only concrete built-in offline implementations. Fixture score-writing
  solvers remain fixture-only. A separate `repository-submission` solver writes a
   deterministic placeholder repository or snapshots an explicitly selected local
   repository, without claiming to implement the task, inspecting private assets,
   invoking providers, or manufacturing score records. The source tree digest is
   part of persisted solver configuration. This is a trusted operator-controlled
   input, not permission to expose a hidden reference to a solver.
  With CLI `--repository PATH`, the same solver instead snapshots an explicitly
  supplied local repository at construction, rejects symlinks/hardlinks/special
  files, and binds its tree digest in the persisted solver configuration. It
  materializes these frozen bytes in the isolated workspace, not the mutable
  source. Callers must authorize source disclosure; confidential reference
  implementations must only enter grading controls, never this solver option.
- A verified task with an authorized public instruction may produce a submission
  even when grading is unavailable. Missing and excluded tasks must not invoke a
  solver. The adapter owns creation of its fresh solver workspace.
- Capture the returned repository with Submission before grading. Independent
  regrade verifies the same artifact and contract, creates a new attempt, and
  does not invoke the solver. An unavailable grader yields nil score/verdict.
- Persist a provisional integration qualification for NL2Repo; fixture reports
  keep their existing infrastructure-only qualification.

## Test-first acceptance

1. An imported local synthetic NL2Repo dataset, containing an authorized public
   instruction and a private oracle, runs through the generic runner with the
   deterministic repository solver. Only the instruction enters its workspace;
   execution captures a Store artifact and grading remains unavailable.
2. Regrade survives mutation of the working repository, retains submission and
   solving attempt identities, and appends independent unavailable evidence.
3. Excluded or missing tasks never create submissions. Fixture score solvers
   cannot run against NL2Repo; live profiles remain rejected before execution.
4. CLI `run` can select the registered NL2Repo adapter without import/download;
   missing data is reported unavailable, not as an unknown benchmark.

The synthetic dataset authenticates only this boundary test. It is not an
official control or benchmark quality result. No change to grader protocol or
authorization policy is intended by this contract.

## Explicit local specification use

Redistribution permission and local research use are distinct. The manifest is
never modified to infer either. `prepare --task ID
--allow-local-specification-use` records explicit local instruction-only consent
after verifying the imported pinned checkout. Its task-scoped receipt binds the
manifest, revision, task, instruction path and SHA256; a checksum detects receipt
corruption, not a hostile user who can rewrite local state. It grants no hidden
source/test access or redistribution rights. Without this receipt or existing
manifest instruction authorization, the instruction remains excluded. Dry runs
must not create consent. This operation does not acquire images or download data.

## Native diagnostic bridge

Explicit CLI `--diagnostics` allows the adapter to call the selected pinned-image
diagnostic helper using a private verified materialization of the Store artifact.
Only `retrying` is supported. The helper must enforce image readiness, clean-mode
isolation and no pulls. Its JSON response is untrusted raw grading-attempt
evidence, never an authoritative score. Execution remains unavailable, score and
evaluation verdict remain nil; the response retains explicit untrusted trust.
Default runs never launch diagnostic containers.
