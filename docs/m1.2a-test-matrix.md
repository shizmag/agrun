# M1.2a test matrix

## E — benchmark/report integration (pre-gate proposal)

Scope: contracts and test design only. No production implementation, grader
changes, downloads, image pulls or provider calls are authorized by this document.
Shared names below are proposed gate decisions, not existing APIs.

### Parent integration steering (supersedes conflicting proposals below)

- E additionally owns `lib/agent_runtime/benchmarks/solvers.rb` after the gate.
  Preserve `Result` unchanged. Adapter `logs` remains a Hash; add a versioned
  normalized `logs["execution"]` record containing raw events, usage and admission
  evidence. Runtime persists the entire logs Hash as the existing immutable log
  artifact, not duplicate raw events in SQLite. Attempt `execution` contains only
  compact summary plus its execution-evidence artifact reference.
- Use explicit model `model_profile` rather than the earlier `config` proposal.
  Legacy manifests without `model_profile` retain exact old logs/usage behavior;
  every new M1.2a integration fixture requires a strict explicit profile. Strict
  execution rejects an implicit real/default provider/model. No fallback from
  rejected/missing strict profile to legacy live execution is permitted.
- Proposed common read-only API, owned outside benchmark internals:
  `Execution::Summary.from_run(store:, run_id:) -> Hash` reconstructs the versioned
  execution summary from persisted runtime run/attempt evidence;
  `Execution::Summary.from_attempt(store:, attempt:) -> Hash` verifies the attempt's
  immutable log artifact and derives its compact normalized summary. Both return
  string-key JSON values, preserve null telemetry and raise `AgentRuntime::Error`
  for present-but-invalid evidence. Legacy attempts lacking execution evidence
  produce an explicit unavailable summary, not zero metrics or fabricated events.
  No execution, registry, environment or workspace reads are allowed.
- Benchmark cells retain `execution: {schema_version: 1, run_id: ...}` as the handle;
  run-time integration and reopen-time Reports both call `from_run`, never a
  benchmark-specific second aggregation algorithm. `from_run` validates compact
  persisted attempt summaries against evidence using `from_attempt`; raw events
  remain exclusively in the immutable log object. The independent tests inspect
  raw artifacts directly and do not use this common API as their expected oracle.
- Final gate still needs exact `model_profile` schema/routing, compact attempt
  schema (including evidence-reference key), admission/launch semantics, and
  aggregation rules for per-attempt usage and nullable cost. In particular, sum
  only comparable normalized usage dimensions, do not sum cumulative event
  snapshots, and distinguish known subtotal from complete total.

### Current integration constraints

- `ExperimentManifest` freezes normalized JSON and includes it in cell identity.
  Its model entries currently allow only `id` and optional `provider`; benchmark
  experiments currently require `execution_mode: offline` and fixture profiles.
  Preserve that offline policy; adding configuration is not live authorization.
- `ExperimentRunner` calls `solve(task:, model:, budget:, workspace:)` with a model
  ID string and records configuration before starting cells. Preserve this solver
  signature and the separate execution-status / grading-verdict domains.
- `Runtime` embeds attempts in its persisted run report and separately calls
  `Store#save_attempt(run_id, step_id, attempt, data)`. The Store has no public
  attempt reader. Terminal attempts currently omit adapter logs and session IDs.
  Never inspect `@db` from benchmark code or pretend these absent fields exist.
- Existing fixture direct/single/fixed arms invoke Fake without persisting their
  attempts. DSL uses a nested `workspace/runtime_store` and returns only its run
  ID, which the benchmark runner discards. Therefore current fixture steps alone
  do not prove persisted execution parity or provide reopenable evidence.

### Shared API gate requirements

1. **Frozen profiles:** accept optional model `config` (string-key JSON object)
   while retaining the existing `id`/`provider` schema. Deep-copy/freeze it with
   the whole manifest; absent config means `{}`. Reject non-objects and unknown
   model fields. Profile changes must change manifest digest/cell IDs. Do not
   accept credentials in persisted profiles; only explicit nonsecret execution
   options belong here. Configuration field allowlisting/redaction is owned by
   the execution contract, not delegated to report rendering.
2. **Configuration routing:** keep `solve(task:, model:, budget:, workspace:)`.
   Reserve `budget["model_config"]` for the selected frozen profile; model remains
   its existing ID string. The budget already carries solver limits. Solvers must
   not mutate it or infer `live` from provider/model/config. Snapshot the solver's
   JSON `configuration` before execution, not a later mutable registry lookup.
   Configuration must include architecture identity and deterministic program
   identity where relevant; no secret or machine-local credential material.
3. **Evidence handle:** solver result may add
   `"execution" => {"schema_version" => 1, "run_id" => String}`. The run must be
   persisted in the experiment's Store before `solve` returns, including failure
   and timeout paths. Inject/share Store at solver construction rather than add
   another solve keyword or expose a private nested Store path. A direct arm
   must persist an execution run too; DSL must use the same Store. Exact run IDs
   are opaque and must not be substituted with benchmark cell or grading IDs.
4. **Attempt access:** request a public
   `Store#attempts(run_id:, step_id: nil)` returning decoded persisted attempt
   records in deterministic step-ID/attempt-number order (not purported
   chronological order). Each returned record identifies `step_id` and `attempt`.
   An existing run with no attempts returns `[]`; an unknown run raises the same
   `AgentRuntime::Error` as `Store#report`. Persisted terminal attempt records must
   include status, duration, model, usage, cost, error, retry safety, session ID and
   raw log artifact references when supplied. Missing telemetry remains null.
   Runtime/integration owners define and test the precise log-artifact field
   shape before E writes assertions against it. Failed/running attempts remain
   observable; getters must not create, repair or mutate evidence.
5. **Derived execution summary:** persist cell `execution` separately from grading
   evidence. Its source is the referenced persisted run/attempts, not the mutable
   solver return's telemetry, a report renderer, or synthesized step names.
   Required values: run ID, run execution status, actual invocation count,
   per-step ordered attempts, terminal attempt statuses, requested and observed
   model identities, raw log artifact references, and nullable usage/cost.
   Invocation count means attempts actually launched, not static step count or
   configured retry budget. Non-invoked dependency cancellations count zero.
   Preserve running/unknown evidence on interrupted runs; do not turn missing
   evidence into success, zero usage, or zero cost. Owner must settle an explicit
   launched-attempt marker/start record if existing running rows are ambiguous.
6. **Report reconstruction:** JSON carries structured execution data. CSV appends
   an `execution` column with JSON-encoded content without renaming old columns;
   Markdown includes a separate execution-evidence section. All three derive
   exclusively from reopened persisted Store data. No solver, provider, grader,
   Docker, workspace read, or benchmark registry lookup during rendering.
   Absent execution evidence on historical cells is null/unavailable, not an
   error and not proof of zero invocations. Invalid present artifact evidence
   must be rejected/marked invalid, not silently downgraded to legacy absence.

Gate blockers for E: agree the optional model field and budget key, shared Store
ownership, attempt-reader signature, precise terminal/raw-log record shape,
launched-attempt semantics, and the execution-summary schema. No public API is
changed by this proposal. Keep audited-v2 grading request/result shapes intact.
