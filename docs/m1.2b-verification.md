## Scope qualifications

The launcher pins one HTTP-native provider and both primary/small model selectors.
Actual installed-binary probes cover allowed workspace reads/patches and rejected
outside reads/patches, shell, child sessions, retrieval and provider switching.
This is trusted local configuration isolation, **not an operating-system sandbox**.
Skill-policy enforcement has an inconclusive negative control; consequently the
pilot requires a newly created repository with no skills, symlinks or memory and
private HOME/XDG/config paths. Arbitrary user repositories are outside this proof.
No enforcement plugin is installed for the uncapped pilot: native HTTP veto works
on the tested route, but an unloaded plugin fails open and other transports are
not comprehensively mediated.

Neither request count nor tokens nor monetary spending has a numerical ceiling.
The 600-second process deadline and local concurrency of one are operational
safeguards, not financial protection. CLI observations can omit retries, title,
compaction or child usage; all-request totals and provider charges remain unknown
unless independent evidence establishes them. Requested identity, CLI-reported
identity and provider-response identity must not be conflated.

The frozen experiment binds its manifest and executable digest. The generated
launch configuration does not yet carry a separate canonical configuration
digest; it is implemented and reviewed trusted runtime code, not a remote
attestation of all effective provider behavior.
