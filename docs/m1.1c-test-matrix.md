### ASC18: measured independent offline reconstruction

On 2026-11-14 this workstream ran:

```sh
mise exec -- bundle exec ruby script/m11c_reconstruct_evidence.rb --root .agru/m11c-acceptance
mise exec -- bundle exec standardrb script/m11c_reconstruct_evidence.rb
```

Both passed. Reconstruction performed **1,198 explicit assertions**, validated
**35 distinct content-addressed objects**, and reconstructed **eight grading
attempts across six scored experiments**, including both incomplete-control
regrades. It opens SQLite read-only; it neither reruns grading nor invokes the
report renderer. It revalidates candidate and reference structured report bytes
with `AuditedResults`, uses the approved manifest's 23 IDs as denominator,
derives counts from per-case outcomes, verifies reference preflight and matching
attempt bindings, then compares the derived measurements to persisted normalized
attempts, active cells and the latest exported JSON/CSV/Markdown. For collection
absence it checks structured exception provenance and the digest-checked submitted
inventory. It also checks the reference control's submitted implementation hash.
Three isolated temporary-copy negative probes also passed: changing only exported
CSV score to 0.9 failed with `CSV: score: "0.9" != "1.0"`; changing only the
SQLite active score to 0.9 failed with `SQLite active cell: score: 0.9 != 1.0`;
removing a referenced raw report object failed with `Errno::ENOENT`. Original
acceptance state was not edited. These probes demonstrate that agreement is not
merely a comparison between copies of the same rendered report.

This checks these single-task, single-repetition controls, not all ASC18 aggregate
scenarios or the entire benchmark. It deliberately shares the specified
`AuditedResults` validator, so it is independent of promoted measurements and
report generation, not an independently implemented parser. Hash integrity is
relative to retained Store records, not adversarial authentication. Reference
source materialization/read-only mounting and inventory-before-execution are the
implemented boundary; this check does not establish a post-execution source
digest. Other workstream verification and final reviewer verdict remain separate.
