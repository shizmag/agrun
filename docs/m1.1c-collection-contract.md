## Status and authority boundary

Contract prepared 2026-11-14 using only cached sources and the existing local
immutable image, then frozen by parent approval for `nl2repo-audited-v2`.
Production validation tests were added and observed red (`LoadError` for the
absent implementation) before adding the class and manifest. No downloads,
historical evidence edits, or commits. The exact installed authority is
`benchmarks/nl2repo/retrying-test-manifest.json`, SHA-256
`3861f33b79c0b6d8f1c4a81ab382b7fe6f4ddbb9d865e3d96e5fdf0f0bb9bcc8`.
`test/benchmark/nl2repo_manifest_test.rb` checks actual production validation,
including changed pins, denominator, duplicates, invented parameters, and unknown
selection settings. The independent expected-23 fixture is in that test.

`NL2RepoTestManifest.new(path: default)` accepts only those reviewed bytes;
`digest`, `identity`, `expected_nodeids` (alias `nodeids`) are deeply frozen.
`validate_collection!(nodeids:, test_source_sha256:, parameter_ids: nil)` returns
true for exact unique set equality and the pinned source hash, otherwise raises
`ArgumentError`. An optional parameter mapping must exactly match the manifest.
Whole-artifact byte pinning rejects added selection configuration, unknown keys,
or altered valid-looking identities without an independent authority update.

Collection is privileged grading work. Never derive the authoritative manifest
from a candidate repository, its pytest output, or the metadata count alone.
Never copy hidden tests into solver workspaces. Test identities and source hashes
are not test-source exports. Directory separation is not a security sandbox.

Parent-frozen scoring protocol is `nl2repo-audited-v2`. Accepted scoped quality
uses `trust: audited` only with `trust_scope: benign_ordinary_submissions`, not an
`authenticated` flag. This version-specific model replaces the universal
authentication gate for v2 only; historical claims remain unchanged. Outer
`quality_basis` is `validated_quality_result` or `candidate_collection_failure`;
`passed`/`total` remain numerator/denominator aliases. Result evidence additionally
retains `expected`, `collected`, `executed`, `failed` and `skipped` as defined in
`docs/m1.1c-scoring-contract.md`. Collection/preflight alone promotes no score.

## Canonical pytest identities and parameter mapping

Use the actual `item.nodeid` / `report.nodeid`, not human terminal output,
`originalname`, or a reconstructed `classname + name`. Canonicalization changes
**only the file component before the first `::`**: require it equal the exact
configured grading test path, then replace that file component with
`test_retrying.py`. For example `private/test_retrying.py` relative to the chosen
pytest rootdir maps to `test_retrying.py`. Accepting an absolute path requires a
separately configured exact absolute path; never infer it from an arbitrary
basename. Do not use global substitution, `basename`, slash normalization,
substring matching, bracket stripping, Unicode normalization, or case folding.

Final collector transport uses `--rootdir=/tmp/private` with the private test at
`/tmp/private/test_retrying.py`, yielding `test_retrying.py::...` directly. The
production manifest validator expects that canonical form, and rejects both
`private/test_retrying.py::...` and `/tmp/private/test_retrying.py::...` rather
than guessing the caller's root mapping.

Preserve every byte after the first `::`. Parameter IDs may themselves contain
`::`, `/`, brackets, or traversal-looking text: these are opaque identity
characters, not filesystem paths. Get `parameter_id` from `item.callspec.id`
when collecting the reference; do not parse the last brackets from the nodeid.
No parameter IDs exist for this selected official test source. In particular,
`test_defaults` or unittest subtests must not be invented as parameterized cases.

Synthetic examples below exercise mapping boundaries; they are **not** claimed
official reference identities. Configured raw file component is
`private/test_retrying.py`.


Every canonical collected identity must belong to the frozen manifest, appear
exactly once, and have exactly the manifest's parameter mapping. Missing, extra,
duplicated, or unrecognized identities invalidate authoritative scoring, even if
the reported count is 23. Collection errors invalidate completeness. A passed
call phase alone is insufficient: setup and teardown must also be accounted for.
Do not infer skipped/xfail/error outcomes from a missing passed report. The
collector/classifier owners define the complete result protocol separately.

## Existing diagnostic script controls and gaps

`script/m11b_retrying_diagnostics.rb` actually runs only `untouched_image`,
`clean_empty`, `clean_incorrect`, and `clean_reference_release`. It does **not**
run the cached original revision. `script/m11b_retrying_original_reference.rb`
only downloads the original revision and requires `--allow-download`; it must
not be invoked for this offline work. Existing original-reference diagnostic
JSON is historical evidence, not a reproducible invocation in that script.

The diagnostic script copies private tests into container tmpfs, hashes test and
setup sources, runs offline `pip install --no-index --no-deps --no-build-isolation
-e .`, and invokes `pytest -v --continue-on-collection-errors`. The script writes
human stdout diagnostics and passes a cached release archive to the transport;
it does not establish a complete canonical identity manifest or structured
phase-complete score. Its regex `passed` count cannot be an authority. The
release baseline is 1.3.4, not image metadata's 1.3.4-dev.

Independent reference validation here intentionally avoided editable install:
trusted original code was imported directly from `/reference`, and the module
origin/hash verified. This proves reference collection and execution, not full
parity with an eventual submission installation procedure. Procedure owners
must bind the final install/import strategy and isolation controls separately.
