# M1.1 acceptance and oracle plan

Statuses must be recorded from actual executions in `m1.1-verification.md`.
This document defines expectations, not successful evidence.

| Scenario | Offline oracle | Official gate |
|---|---|---|
| BENCH-01 identity | exact pin/task IDs and digest round trip | pinned upstream assets |
| BENCH-02 resources | unavailable contains reason, no score | image inspection |
| BENCH-03 normalization | strict public fields, empty workspace, hidden sentinel absent | authorized upstream instruction |
| BENCH-04 output | Store generation + verified digest | same artifact protocol |
| BENCH-05 grading | fixture cannot establish official compatibility | native real task required |
| BENCH-06 negative | fixture 0 is not full score | known-bad real submission |
| BENCH-07 positive | fixture 1, explicitly not official | authoritative original/reference |
| BENCH-08 infra | nonzero/malformed/timeout/unavailable => null score | native failure controls |
| BENCH-09 binding | mutate snapshot/spec/procedure/environment => reject | actual native dependencies |
| BENCH-10 isolation | traversal/symlink/forged output rejected | real process boundary |
| BENCH-11 matrix | Cartesian product, unique identities | same planner |
| BENCH-12 reporting | persisted records agree JSON/CSV/Markdown | same reports |
| BENCH-13 metrics | macro differs from pooled, asymmetric failures | official denominator |
| BENCH-14 offline | live profile rejected before execution | no paid calls |
| BENCH-15 regrade | same generation, distinct grading attempt | native repeat |

| BENCH-17 parity | four fixture categories same contract | live enforcement deferred |
| BENCH-18 preparation | cached verified assets, tamper rejected | repeated exact pin |

## Required adversarial sensitivity

Challenge scores replaced with 0 or 1, exit ignored, stale generation, wrong
revision, swapped tasks, duplicate retries/cells, lost incomplete cell, pooled
instead of macro mean, wrong image, evaluator leakage, malformed response,
cross-experiment evidence, missing usage represented as measured zero, and lost
unavailable task. Mutations must be isolated from the working implementation;
record detected and not-run controls individually. Never label a proposed
mutation as an executed mutation.

## GR controls

GR-01 valid, GR-02 empty, GR-03 incorrect, GR-04 partial, GR-05 infra, GR-06
immutable, GR-07 contamination, GR-08 protocol agreement require separate
official evidence. Missing Docker/native assets/collector means blocked, not
fixture-passed. Preserve raw execution status independently of verdict.
