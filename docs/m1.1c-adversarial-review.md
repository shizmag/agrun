### Demonstrated limitation, not a benign-scope acceptance blocker

F patched `_pytest.reports.TestReport.from_item_and_call` to change call-report
outcomes. A broken `Retrying.call` produced **15 passed / 8 failed** without the
patch; the same broken implementation plus the patch produced a structurally
valid **23 passed**, exit 0. Thus a hostile same-process submission can forge the
very evidence this parser accepts. Coherent-report validation, stdout isolation,
reference preflight and passing negative controls do **not** authenticate pytest
reports against candidate code. This is an explicit demonstrated limit of
`trust_scope: benign_ordinary_submissions`, not a claim of hostile resistance and
not a blocker for the deliberately frozen benign-only contract. Removing that
scope or extending claims to adversarial submissions would invalidate acceptance.

Source-boundary wording must remain exact: materialization and read-only mounts
were verified, with candidate inventory captured **before execution**. There is
no post-execution source-digest verification claim. Directory separation and
container policy do not authenticate same-process test outcomes.
