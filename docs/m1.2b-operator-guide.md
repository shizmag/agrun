# Controlled OpenCode pilot

The committed `experiments/retrying-live-pilot-02.json` freezes one retrying/single-agent
experiment and the exact OmniRoute upstream model `cx/gpt-6-luna-low`. The OpenCode
selector is `omniroute/cx/gpt-6-luna-low`; these are not interchangeable API IDs.
The executable path is host-specific and its SHA-256 is checked before launch.
Changing any manifest field changes its authorization digest.

## Inspect before launch

```sh
mise exec -- ruby bin/agru bench live plan experiments/retrying-live-pilot-02.json
mise exec -- ruby bin/agru bench live preflight experiments/retrying-live-pilot-02.json \
  --root .agru/m12b-live --authorization .agru/m12b-live/operator-authorization-pilot-02.json
```

Planning does not load credentials or start OpenCode. Preflight checks the frozen
scope, explicit concurrency and finite deadline, key presence, pinned executable,
fresh benchmark workspace and locally available audited grading image. It never
pulls an image or invokes a model. Its credential-free receipt is persisted.

An authorization JSON has `scope` (experiment_digest, task, solver, provider,
endpoint, route, model, mode), finite Unix-seconds `expires_at`, and
`financial_exposure: "not_hard_bounded"`. Keep it under ignored `.agru`, separate
from credentials. Record operator-instruction provenance without inventing a
signature. Editable local consent is not cryptographic approval. Credentials use
the existing `OMNIROUTE_API_KEY` environment mechanism and must never be copied
into the authorization, manifest, report or source tree.

## Explicit authorized execution

```sh
mise exec -- ruby bin/agru bench live run experiments/retrying-live-pilot-02.json \
  --root .agru/m12b-live --authorization .agru/m12b-live/operator-authorization-pilot-02.json
```

The operator amendment for this milestone explicitly accepts no artificial token,
request, run-count or monetary quotas. This is **uncapped financial exposure**,
not a hard spending guarantee. The 600-second process deadline and concurrency
one are operational safeguards, not financial ceilings. No model fallback,
automatic whole-attempt rerun, external retrieval, Serena, or child-agent tool is
enabled. Native provider retries and incompletely observed auxiliary usage remain
qualifications; stopping a process cannot undo billing already dispatched.

Configuration isolation is not an OS sandbox. The solver has only workspace
read/edit permissions; shell execution is intentionally unavailable. Grading runs
separately in the existing network-disabled Docker boundary. Neither reference
implementation nor authoritative tests are provided to the solver.

## Offline checks and independent evidence

Use `mise run m12b-test` for deterministic policy/lifecycle/report tests. Installed
OpenCode loopback probes require explicit `AGRU_OPENCODE_BOUNDARY=1` and
`AGRU_OPENCODE_BOUNDARY_BINARY`; they never contact a real provider. The mock
acceptance script uses a local fake executable and independently grades its
deliberately incomplete submission, not a reference implementation.

Use existing `bench report` and `bench regrade` commands with the same store root
and audited-scoring option. Regrading reads the immutable submission and does not
invoke OpenCode. Reports reconstruct usage from raw execution evidence; missing
provider identity, requests, tokens or charges remain unknown, never zero-filled.
The audited-v2 quality result is not an official historical benchmark score, and
one task/attempt cannot establish architecture superiority.

`experiments/retrying-live.json` is retained as the first, pre-dispatch rejected
intent: it lacked the required model-profile `id`. The second manifest records a
technically justified infrastructure retry with a new digest and authorization.
Do not reuse a completed experiment ID to overwrite its evidence or rerun merely
to obtain a better score.
