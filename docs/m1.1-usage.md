# Benchmark commands

Run through `mise exec -- bundle exec ruby bin/agru` (abbreviated below as
`agru`). Ordinary tests never download a dataset, pull images or invoke providers.

```sh
agru bench doctor
agru bench datasets
agru bench prepare nl2repo --dry-run
agru bench prepare nl2repo --allow-download
agru bench tasks nl2repo
agru bench plan experiments/fixture-infrastructure-smoke.json
agru bench run experiments/fixture-infrastructure-smoke.json --offline
agru bench report fixture-infrastructure-smoke
agru bench report fixture-infrastructure-smoke --format csv
agru bench report fixture-infrastructure-smoke --format markdown
```

`--root PATH` chooses the Store; dataset roots must have a `.agru` path component.
The import downloads the exact pinned Git checkout, verifies recorded assets and
reuses it on subsequent preparation. It does not fetch task images. Download and
disk sizes are unknown rather than guessed. Licensing/authorization is unresolved;
the import remains evaluator-side and solver instruction export is unavailable.

Experiment IDs cannot be overwritten. Use a fresh manifest ID or a distinct
`--root` for another demonstration. For repeatable fresh acceptance experiments:

```sh
mise run bench-acceptance
```

This prints a new experiment ID and writes persisted SQLite/artifact evidence plus
three report exports beneath `.agru/m11-acceptance`.

Regrade a stored cell independently, without invoking the solver:

```sh
agru bench regrade EXPERIMENT_ID CELL_ID --root STORE_ROOT
agru bench compare EXPERIMENT_A EXPERIMENT_B --root STORE_ROOT
```

Comparison currently exposes two summaries, not a scientific significance test.
The report's paired-analysis seam only matches identical task/repetition pairs.

## Official validation gate

```sh
agru bench verify nl2repo --offline
mise run bench-official-verify
```

These intentionally exit nonzero with `blocked`, null score and GR-01..08
statuses until native isolated controls can actually be established. They are
readiness gates, **not executable official-task grading tests**. The pinned
reference protocol currently overlays submissions onto reference images and
trusts regex-parsed program output. No approximate host grader is substituted.

## Scoped audited retrying protocol (M1.1c)

`nl2repo-audited-v2` is a separate, **retrying-only** procedure for benign ordinary
submissions. Its frozen 23-case inventory is
`benchmarks/nl2repo/retrying-test-manifest.json`; registry and contract are
`benchmarks/nl2repo/protocols.json` and `docs/m1.1c-collection-contract.md`.
This is not the official legacy parser, an official leaderboard run, or proof
of adversarially authenticated collection. Historical v1/legacy diagnostics and
their blocked readiness flags retain their original meaning.

Do not infer operational readiness from a registry entry, local image presence,
or the independent reference's 23 passing cases. The actual audited invocation
must complete its task-specific runtime preflight and controls, bind the actual
submission and procedure, and preserve `protocol`, `quality_basis`, and
`trust_scope: benign_ordinary_submissions` in evidence. Missing images, unhealthy
reference collection, protocol errors, timeout, or cancellation have null scores,
not invented quality zeros. An accepted complete candidate result may genuinely
score zero. Read `docs/m1.1c-scoring-contract.md` before interpreting outcomes.

Use `--audited-scoring --offline` on `bench plan`, `run`, and `regrade` to select
the supported v2 path. `experiments/nl2repo-audited-smoke.json` is a fresh
insert-only experiment template; change its ID for every subsequent run in the
same Store. The flag, not a manifest protocol key, selects audited grading.
The legacy `bench verify nl2repo` readiness path is not silently relabeled v2:
even with the flag it retains blocked GR gates and exits 1, while exposing
additive `audited_scoring` selection metadata. That metadata is not proof of
runtime readiness. See `docs/m1.1c-operator-guide.md` for exact offline commands,
persistent controls, report/regrade instructions, and evidence interpretation.

## Verification commands

```sh
mise run bench-contract
mise run bench-test
mise run bench-acceptance
mise run verify
```

Read `docs/m1.1-benchmark-protocol.md`, `docs/m1.1-isolation.md` and
`docs/m1.1-verification.md` before interpreting a result. Fixture scores measure
infrastructure consistency only. All live provider execution is unsupported and
rejected; these commands cannot establish coding-agent quality or cost advantage.
