# M1.1 contracts

Extend `AgentRuntime::Benchmarks`; preserve M0.1 APIs. Reuse `Store` for artifacts
and experiment reports; no second database.

## Adapter and public task

`Registry#register(name, adapter)` rejects duplicates; `#fetch(name)` fails closed.
Adapters implement `identity`, `list_tasks`, `load_task(id)`,
`prepare_solver_workspace(task:, workspace:)`,
`prepare_grading_request(task:, submission:, limits:)`, `grade_submission(request)`,
and `normalize_score(raw)`. Identities and tasks are JSON-compatible hashes.
Public tasks contain only `id`, `benchmark`, `instruction`, `specification_digest`,
`metadata`, `availability` and `unavailable_reason`. No grader path, original
source or hidden tests. Adapter-private grading records never cross solver API.

## Solver and matrix

Solvers implement `solve(task:, model:, budget:, workspace:)` returning the existing
status/repository/model/usage/cost contract. Four offline categories are direct,
single-agent, fixed-workflow and compositional-dsl; fixtures are not capability
measurements. Reject live execution until hard budgets and isolation are enforced.
Missing usage remains null. Manifest schema 1 includes experiment ID, benchmark
name/revision/task IDs, solver IDs, model profiles, repetitions, limits, execution
mode and subset role. Validate unique lists, positive finite limits and exact
dataset revision. Canonical manifest digest freezes configuration.
Deterministically ordered cells are tasks × solvers × models × repetitions.
Cell identity binds manifest and all coordinates; attempt IDs are independently
unique. Persist every cell as not_started before solving and each transition.
Unavailable cells are explicitly skipped with reasons. Cancellation leaves
remaining cells not_started.

## Grading boundary and evidence

Submission is a Store repository artifact, revalidated before grading. Requests
bind task ID, benchmark identity, specification digest, submission ID and digest,
authoritative procedure/environment fingerprint and resource policy. Evidence
includes actual image digest, trusted asset manifest and native dependency
identity when known; unknowns block official validation. No request selects
arbitrary host mounts or solver-provided grading commands. Docker runs fresh
nonprivileged containers, no socket, network none, read-only trusted inputs,
bounded CPU/memory/PIDs/tmpfs/time, capability drop and cleanup. No host fallback.
Reject symlinks, traversal and special submission entries. Generated code can
tamper with in-process output: parsable JSON alone does not establish an
authoritative score. Official readiness requires native protocol controls and a
documented trusted result-collection boundary.

Results separate `execution_status` (success/error/timeout/unavailable/cancelled/
not_started) from nullable `score`, `verdict`, raw evidence and errors. Non-success
never has a quality score. Success requires validated native output, finite score
in [0,1], consistent positive denominator when counts supplied. Malformed/truncated
output and nonzero exit are infrastructure failures, not zero. Regrading verifies
submission and current contract, creates new evidence without rerunning solver.
Never reuse evidence across changed contracts or generations.

## Reporting and readiness

Reports derive from persisted raw cells: macro mean per task (average repetitions
within task before averaging tasks), full-solve fraction, valid/invalid counts,
explicit incomplete cells; pooled counts separately labeled. Paired comparison
uses common tasks, no fake-model scientific delta. Costs/usage retain unknown
coverage. JSON/CSV/Markdown match coordinates and statuses.
Dataset lifecycle: missing/downloaded/verified/images/grader-ready/runnable/
excluded. Downloads/image pulls require explicit preparation; dry-run never
downloads or guesses sizes. Immutable pins/exclusions retained. No official
operational claim without a real-task strongest available positive/negative gate
and native agreement. Unavailable controls remain blocked. Acceptance BENCH-01..18
and GR-01..08 retain user definitions; fixture successes never replace official
controls. Normal tests are offline and Docker-free; grading is an explicit target.

## Independent review amendments (required for freeze)

Official score authority requires a trusted collector whose result channel,
files and process cannot be written or impersonated by submission code. Native
stdout, JSON files in the submission security domain, and exit zero are never
authenticated scores. Until such a native-compatible collector is validated,
NL2Repo grading returns blocked/untrusted with no score. Forged stdout, result
replacement, premature exit and process interference must not establish quality.
Docker, pinned assets and real native positive/negative controls are separate
mandatory readiness gates; unavailable gates remain blocked, not skipped passes.

At use, materialize and verify a private submission snapshot from Store; protect
it against subsequent solver writes. Verify source and copied snapshot digests
before/after execution. Bind actual consumed bytes, public specification, trusted
assets, evaluator and normalizer versions, image/dependencies and effective
resource policy. Regrading refuses mismatches and creates distinct evidence.
Read-only mount permissions do not protect against a malicious host owner; host
and benchmark preparation tools are trusted, concurrent host mutation is detected
where possible but not an OS-level security guarantee.

No hidden content is copied into public task/workspace/report. Raw native logs
are restricted evaluator evidence, not solver feedback. A native test process
that imports submitted Python necessarily exposes some test context to that code;
do not claim hidden-test confidentiality inside that process. Unproven native
source confidentiality or result authority blocks the strong official pathway.

Quality aggregation is by solver/model arm. A task contributes only if all its
planned repetitions have valid successful grades; incomplete tasks are excluded
with reasons, never imputed as zero. Report planned/attempted/valid/missing counts
and complete-task coverage alongside conditional quality. Fully solved means
native full-score criterion (fixture score == 1), all planned repetitions; report
fraction among complete tasks and conservative count/planned-task fraction
separately. Pair only identical task AND repetition coordinates with valid grades
in both arms, expose excluded pairs; never call unequal observations comparable.
No scientific deltas for fake fixtures. Test asymmetric failures explicitly.

Offline execution permits only registered built-in fixture solvers and fixture
model profiles; reject incompatible profiles/solvers before any cell executes.
No provider invocation is authorized by adapter preparation or offline grading.
Tests assert provider entrypoints are not reached. External public asset fetches
are a distinct explicit preparation operation, never an ordinary test side effect.
