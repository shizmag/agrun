# Mock-only Unix-socket relay helper

This is test infrastructure, not a live-provider adapter or served-model proof.
No historical live launch configuration is changed.

## API for SandboxRunner integration

`require_relative "../test/support/m12c_relay_docker"` (adjust relative path).
`M12cRelayDocker.new.start` creates two Docker-managed socket volumes and starts
the trusted relay and mock, each with `--network=none`. `relay_volume` is the only
volume permitted in the agent, mounted read-only at `/relay`. Never mount the
upstream volume, helper secret directory, Docker socket, or host config.
Always call `close` from ensure, including partial startup failures.

The shared socket is `/relay/relay.sock`. For OpenCode's ordinary HTTP transport,
run `node /helper.cjs bridge` inside the agent; mount
`test/support/m12c_mock_relay.cjs` read-only as `/helper.cjs`. Wait for the JSON
`{"ready":"bridge"}` line before starting OpenCode. Configure main and small
models to `http://127.0.0.1:18080/v1` and the exact wire route
`cx/gpt-6-luna-low`, using a dummy agent credential. The agent image must contain
Node; this is an explicit mock-helper dependency, not an automatic installation.

The relay ignores agent authorization and supplies its own mock-only credential.
Only `POST /v1/chat/completions` with the frozen exact model is accepted.
No DNS, IP upstream, external bridge, port publication, redirect following, or
host connection is required. Unix sockets remain connectable through the
read-only mount; the agent cannot replace directory entries.

`logs("relay")` and `logs("mock")` return JSON-line observations. Preserve both
outside the agent workspace. The relay records body digests, decisions and route;
the mock records the received route and credential match, never the credential.
A separate trusted bootstrap container sets volume ownership to 65534 before
any credential is mounted. Relay, mock, and acceptance agent run as uid/gid
65534 with all capabilities dropped. Cleanup aggregates Docker removal failures
and raises `mock cleanup incomplete` rather than reporting silent success.
Do not claim this helper is a production security sandbox.

## Acceptance

`mise exec -- env AGRU_M12C_MOCK_DOCKER=1 bundle exec ruby -Itest test/m12c_mock_relay_test.rb`

The explicitly opted-in test uses a locally available digest-pinned Node image,
never pulls, and verifies exact-route forwarding, route/path denial, ignored
attacker credentials, absent secret/upstream/Docker sockets, only-loopback agent
interfaces, and denied external IPv4/IPv6 and host-service connections.
These are mock transport controls; real OpenCode behavior requires a separate
verified Linux executable and integration acceptance from SandboxRunner.

The deterministic response script supports ordinary JSON and SSE. When the
request advertises a native `read` tool and contains no tool result, the fixed
script emits `read(path: "/workspace/README.md")`; after a tool result it
emits `mock ok`. Prepare that file before a real-OpenCode integration. No request
field may choose an upstream or modify this fixed tool call. With exactly one
tool-result message and an advertised `bash` tool, the second fixed call is
`shell(command: "printf 'sandbox-positive\\n' > sandbox-positive.txt && test -s sandbox-positive.txt",
timeout: 1000)`. After two tool results the mock returns final text.

`M12cRelayDocker.new(script: "native-subagent")` selects the alternative frozen
script before startup. After two parent tool results it invokes the actual
advertised `subagent` tool with agent `general`, description `Isolation canary`,
and a fixed child prompt carrying `AGRU_FIXED_CHILD_CANARY_12C`. A user message
with that marker identifies the child and suppresses further subagent calls.
Child behavior is read then shell. This mode does not yet probe a host-only file;
it must not be reported as host-file exclusion evidence.

Each Docker CLI operation uses ProcessRunner with a 15-second deadline and
process-group cleanup. Startup has a shared 45-second deadline. Cleanup attempts
each tracked resource with bounded commands, retains failed resources for retry,
and is idempotent after success. Docker CLI environment is inherited solely for
Docker Desktop connectivity; no CLI environment is passed into role containers.

The Docker acceptance also creates a test-owned bridge-network TCP/UDP canary.
A separate bridge client must receive both TCP and UDP responses before the
network-none client is tested against the same literal destination. The latter
must receive neither, and the server's received-packet log must not change.
This is a positively calibrated host-side Docker-network service, not a claim
that a physical macOS host listener was tested. UDP payload is a synthetic DNS
canary, not a query sent to a public DNS resolver. Raw CONNECT and conflicting
Content-Length requests are also rejected without new upstream observations.
