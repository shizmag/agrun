# M1.2a C: budget admission contract and test design

Status: **Implemented and integrated; offline concurrency and launch tests pass**.
C-owned implementation paths are
`lib/agent_runtime/execution/budget.rb` and `test/execution/budget_test.rb`.
Parent owns integration and shared-contract updates; adapter owner owns process

## Existing integration constraints

- `CONTRACTS.md` defines string-key config, unchanged `Request` and `Result`
  structs, explicit live opt-in, and independent execution/evaluation statuses.
- `Runtime#execute_step` creates one Request per retry, currently supervises with
  `Timeout.timeout(step["timeout"] + 0.1)`, stores `Result.logs` as a text
  artifact referenced by attempt `"log"`, and only retries a transport failure
  when `retry_safe == true`. Do not broaden that retry rule.
- `OpenCodeCLI#execute` currently accepts instance `live: true` OR request
  `config["live"] == true`. Scoped execution must replace that as sufficient
  permission, not silently inherit a global live bypass.
- `ProcessRunner#call(argv:, cwd:, timeout:, cancellation: nil, env: {})`
  supervises a local POSIX process group with a monotonic timeout and cancellation.
  It is not a remote-provider kill switch or security sandbox.
- Existing store APIs can persist JSON decision evidence without a schema
  migration. Budget code must not access Store's database or runtime internals.

## Scope and enforcement claims

One `Execution::Budget::Coordinator` contains a Mutex and counters; no scheduler,
queue, worker pool, background thread, cross-process lock or recovery ledger.
All applicable scopes are checked and reserved in one critical section. No
partial reservations on denial. Independent coordinators do not share limits.

Required hierarchy is experiment -> run -> attempt; an optional pool scope is a
parent of experiments. An isolated run still gets an explicit experiment scope.
The caller passes existing opaque Scope objects, not arbitrary scope IDs from
request config. A scope belongs to exactly one coordinator and one parent;
IDs cannot be reused within that coordinator. A closed scope cannot reopen.
Restarting a coordinator resets local accounting; persisted logs are evidence,
not restored reservations. Thus no cross-process/global spending guarantee.

| Control | Semantics | Claim |
| --- | --- | --- |
| `wall_seconds` | elapsed monotonic time since scope creation; includes idle time; attempt begins just before admission | local deadline enforcement through supervised runner |
| `max_attempts` | total admitted executor invocations, including retries and admitted invocations that fail before spawn | hard local atomic admission cap |
| `max_concurrent_sessions` | active admission leases, including resumed sessions and setup/teardown | hard local simultaneous-invocation cap |
| monetary cost / token counts | provider-reported after execution, nullable | observational only |
| model / tool restrictions | requested profile identity and declared tool policy | identity checks locally; no hard downstream model/tool guarantee |

Concurrency counts invocations, not unique provider session IDs; one process can
create remote work beyond our visibility. Wall time bounds the local supervised
invocation, with runner polling/termination grace, not instantaneous process death
at a mathematical deadline or cessation of remote charges. Existing runtime
Timeout is an emergency guard, not the primary process cleanup mechanism.

## Proposed exact Ruby surface (for approval)

Namespace `AgentRuntime::Execution::Budget`. Value objects expose readers and are
deeply immutable copies; all `to_h` values have JSON string keys. No Struct change.

```ruby
ModelProfile.new(id:, provider:, model:, execution_kind:, tool_policy: {})
ModelProfile#to_h

AdmissionConfig.new(wall_seconds:, max_attempts:, max_concurrent_sessions:,
  hard_limits: {}, observations: {})
AdmissionConfig#to_h

Coordinator.new(clock: -> { Process.clock_gettime(Process::CLOCK_MONOTONIC) })
Coordinator#open_scope(kind:, id:, config:, parent: nil) # => Scope
Coordinator#close_scope(scope:) # => nil
Coordinator#admit(scopes:, profile:, authorization: nil, request:,
  executable:, executable_sha256:) { |decision| persist_admission(decision) }
  # => Decision (denied) or Lease (admitted)
Coordinator#release(lease:) # => nil; idempotent for same lease

Decision#to_h
Lease#decision # => immutable Decision
Lease#timeout # => positive finite Float, effective local timeout at admission
Coordinator#remaining_timeout(lease:) # => positive finite Float or nil if expired
```

`Scope`, `Decision`, `Lease`, `ModelProfile`, and
`AdmissionConfig` constructors other than those listed are private implementation
details. Release rejects foreign/fabricated leases. `close_scope` rejects active
leases or unclosed children; releases remain possible after deadline expiry.
Closing is optional lifecycle cleanup, never a means to reset exhausted counters.

Profile fields `id`, `provider`, `model` are nonempty strings. `execution_kind` is
exactly `"offline_fixture"` or `"real_provider"`. `tool_policy` is JSON data with
string keys and is descriptive, never proof of isolation. Canonical profile
digest is SHA256 of `IR.dump(profile.to_h)`; include execution kind and tool policy.
Profile creation performs no model discovery or network call.

All three AdmissionConfig limits are required: wall is a positive finite Numeric
(not strings, booleans, NaN or infinity), counts are positive Integers. Attempt
scope must have `max_attempts: 1` and `max_concurrent_sessions: 1`. Ancestor caps
need not be greater than child caps; the stricter applicable cap wins.
`hard_limits` must be empty in M1.2a: any requested hard currency/token/model/tool
limit fails configuration with `unsupported_hard_limit`, rather than silently
becoming advisory. `observations` accepts only `"cost"`, `"tokens"`, `"model"`,
`"tools"` mapped to true/false. Observations request evidence, never authorize work
or block an invocation. Reject unknown config/profile keys in JSON decoding.

Scopes use `kind` strings `"pool"`, `"experiment"`, `"run"`, `"attempt"`;
parent hierarchy is strict. `scopes:` is the complete root-to-attempt chain,
including pool when present. The run scope ID must equal `request.run_id`;
attempt identity is `"#{request.step_id}:#{request.attempt}"` within that run.
Validate positive integer `request.attempt`, nonempty step/run IDs, valid timeout,
scope ownership, profile and authorization before changing counters.

Every scope stores its own start/deadline. Admit samples the injected monotonic
clock once under the lock. Remaining wall time is `deadline - now` for each scope;
zero or negative denies. Effective timeout is the minimum of positive request
timeout and all remaining wall times. Admission increments total attempts and
active leases for every scope. Release decrements only active counts, once;
attempt totals never refund. Repeated admission for the same run/step/attempt is
denied as `duplicate_attempt`, even after release. Distinct retry number requires
a fresh attempt scope and consumes fresh ancestor capacity.

No adapter execution, persistence callback, arbitrary caller code, or file I/O
occurs inside the Mutex. Injected clock is a trusted deterministic local function.
`remaining_timeout` samples the clock under the lock and returns the minimum of
the original request timeout minus elapsed lease time and all remaining scope
deadlines. It rejects foreign or released leases. This is needed because evidence
persistence/setup can consume the admission-time timeout; the snapshot must not
grant a fresh full timeout after setup. Nil means do not spawn, return `timeout`,
record completion and release without refunding the admitted attempt.

## Authorization and denied outcomes

Authorization is a trusted host-provided callable, not deserialized from solver
inputs, IR executor config, environment credentials, or a profile file. Default
authorization is absent and denies. Callable construction represents explicit host action;
trusted Ruby can manufacture authorization, so this is not an adversarial sandbox.

- Offline fixture permission binds exact profile digest and exact executable
  identity selected by the host; host must select an audited fixture, not merely
  an executable named `opencode`. Require a normalized absolute non-symlink file
  path and SHA256 content identity captured at authorization; recheck before
  execution. This detects ordinary replacement, not a hostile TOCTOU race.
  Fixture scripts and helpers remain trusted. No fallback to PATH/provider binary.
- Real providers are unconditionally denied in this milestone with
  `real_provider_disabled`, even with matching grants or live flags. Credentials
  are not consent. A future live policy requires separate approval.
- Authorization validation occurs before capacity reservation. Authorization
  secrets or environment values are never logged. Record only mode and bindings.

The callable receives keyword arguments `profile:`, `request:`, `executable:`,
`executable_sha256:` and returns nil or a string-key grant with `mode`,
`executable`, `sha256`, `profile_digest`, `experiment_id`, `run_id`. The adapter
owns executable realpath/content verification at the launch boundary; coordinator
validates normalized absolute path and SHA256 format and compares the host grant.
The coordinator performs no file I/O or process execution. Its block receives a
Decision for both allowed and denied admission, runs outside the Mutex, and must
finish before admission returns. If it raises after reservation, release active
capacity, keep consumed attempts and propagate the exception. Parent forwards
`adapter.execute(request) { |decision| save_admission(decision) }` to this block;
neither callable enters serialized config. Coordinator injection is `budget:` on
the adapter, with separate `authorization:`, `scopes:` and optional host sink.

Ordinary denials return Decision, not exceptions. Real-provider profiles first
return `real_provider_disabled`. Otherwise priority is deterministic:
`authorization_required`, `authorization_mismatch`, `duplicate_attempt`, then
root-to-leaf scope checks `wall_exhausted`, `attempts_exhausted`,
`concurrency_exhausted` (in that order per scope). Cancellation checked before
admission returns a cancelled result without admission or consumption; cancellation
racing with an admitted lease consumes the admitted attempt and releases the lease.
Invalid shape/type/config raises `ArgumentError` before side effects; parent
maps it to a `failure` with `error["type"] == "configuration"` and stable
`error["code"]` (`invalid_budget_config` or `unsupported_hard_limit`).

Parent maps denied decisions to:

```ruby
Result.new(status: "blocked", outputs: {},
  error: {"type" => "budget_admission", "code" => decision.to_h.fetch("reason")},
  logs: {"budget" => {"admission" => decision.to_h}}, retry_safe: false)
```

Never classify admission failure as transport. Concurrent-capacity denial is
terminal for this invocation; this component does not wait/requeue/retry. Actual
supervised deadline expiry remains `timeout`, cancellation remains `cancelled`.
No admission/evidence change creates or alters an evaluation verdict.

## Decision and persisted evidence schema v1

Every decision `to_h` includes exactly these top-level keys:

```json
{
  "schema_version": 1,
  "decision_id": "opaque-unique-id",
  "allowed": true,
  "reason": "admitted",
  "denied_scope": null,
  "run_id": "run-id", "step_id": "step-id", "attempt": 1,
  "profile_digest": "sha256-hex",
  "authorization": {"mode": "offline_fixture", "experiment_id": "exp-id", "run_id": "run-id"},
  "effective_timeout_seconds": 12.5,
  "scopes": []
}
```

Each scope entry has `kind`, `id`, `limits` (AdmissionConfig `to_h`),
`elapsed_seconds`, `remaining_wall_seconds` (clamped to zero), `attempts_before`,
`attempts_after`, `active_before`, `active_after`. Successful values describe the
atomic reservation; denial leaves all before/after counts equal. Denied scope is
`{"kind": "run", "id": "..."}` or null for nonscope reasons. Denied effective
timeout is null. Authorization mode is `"none"` with null bindings when absent;
otherwise record attempted grant bindings, without profile body or executable
contents. All numbers finite, no raw monotonic epochs, prompts, credentials or
environment. Counter snapshots are admission evidence, not final usage totals.

Preserve adapter logs under `logs["adapter"]` and place admission under
`logs["budget"]["admission"]`; avoid overwriting provider stdout/stderr keys.
Completion records under `logs["budget"]["completion"]` have `lease_released`,
`execution_status`, `usage_source` (`"provider_reported"` or `"unavailable"`),
`cost_source` (same enum), `enforcement` (local controls vs observational controls).
Absent usage/cost stays null in Result and must not become zero or estimated hard
spend. Observation evidence is untrusted provider data, not enforcement proof.

Parent must persist the immutable admission decision through the existing
`Store#put(type: "text", ...)` + running `Store#save_attempt` `"log"` reference
**before calling any provider-capable adapter**. If persistence fails, do not
spawn; release lease, consume admitted attempt, fail closed. Final attempt log
contains the same decision ID and merged completion evidence. A crash can leave
only a running admission record; never infer provider success/release from that.
Blocked decisions must also persist without invoking the adapter. This introduces
no new Store interface and deliberately leaves orphan evidence possible on crash.

## Parent integration handoff

1. Parent approves surface and updates shared contracts; C does not edit Runtime,
   Request, Result, Store, compiler, benchmark runner or adapter files.
2. Host creates immutable profiles, config, authorization and coordinator, opens
   experiment/run scopes before worker threads, and shares the same coordinator
   across concurrent runs when experiment/pool caps are requested.
3. Runtime creates attempt scope, checks cancellation, admits once, and persists
   admission before invocation. It constructs the supervised Request timeout from
   `remaining_timeout` immediately before supervised invocation (unchanged Request
   struct); adapter runner uses that remaining timeout, not the earlier snapshot.
   Adapter-side setup must likewise subtract elapsed monotonic setup time before
   spawning or short-circuit timeout if exhausted.
   Keep existing emergency runtime timeout as an outer guard with cleanup grace.
4. Adapter integration verifies executable/profile binding just before execution,
   rejects request model/agent/env overrides that could change approved identity,
   and never treats permission as a directory security boundary. Exact CLI model
   mapping and provider configuration isolation are adapter-owner decisions.
5. Parent encloses persistence, adapter lookup, execution, translation and output
   handling in `ensure` release, including exceptions and Timeout interruption.
   No coordinator lock may remain held on asynchronous interruption; integration
   must shield the atomic reserve/release operations from outer Timeout delivery.
6. Parent merges logs and saves final attempt, preserving transport retry safety.
   Missing scoped policy for provider-capable execution denies by default. Offline
   Fake/Shell behavior outside this provider integration is not expanded here.
