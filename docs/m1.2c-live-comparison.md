# M1.2c comparative smoke protocol

## Registered scope before dispatch

The operator approved one retained smoke cell for each of `single-agent`,
`fixed-workflow`, and `dsl` on the pinned NL2Repo `retrying` task. The route is
catalog `omniroute-luna-low`: base `gpt-6-luna`, reasoning effort `low`, exact
wire ID `cx/gpt-6-luna-low`. No suffix parsing, fallback, automatic whole-cell
retry, or quality-driven rerun is permitted. This approval does not authorize
the larger pilot. Financial exposure is explicitly **not hard bounded**.

Each cell has a 600-second solver deadline; cells run serially. These are
operational safeguards, not token/request or spending caps. All scheduled
cells, denied launches, errors, timeouts, partial submissions, and grading
failures remain in evidence. There is no best-attempt selection.

The three manifests in `experiments/m12c-smoke-*.json` specify the cells. Their
resolved digests, executable identities, full runtime commit, catalog digest,
benchmark assets, solver/program definitions, configuration, and dispatch
order must be frozen before any provider call. Run only from a clean isolated
worktree at that commit. Do not change running code.

## Common conditions and differences

All architectures receive the same public specification, initially empty
repository, model profile, permitted tools, and audited-v2 grading conditions.
Role instructions and invocation counts are architectural differences and must
be retained. Single-agent uses one OpenCode invocation. Fixed workflow uses an
imperative planner/coder/reviewer sequence. Compositional DSL uses the Ruby
compiler/runtime, explicit dependencies and typed intermediate artifacts, and
a separate verification invocation. Verification is independent invocation,
not an independent model or a security boundary.

Use fresh sessions and HOME/XDG/config state for every invocation; no prior
scores, hidden procedures, reference source, or previous-arm artifacts enter
solver inputs. The prepared repository contains only public task metadata.
Installed-binary loopback probes must establish instruction/config isolation.
Configuration isolation is **not an OS sandbox**; inspect retained tool traces
for unintended host reads and classify any affected observation explicitly.
Audited-v2 has trust scope `benign_ordinary_submissions`, not malicious Python
result-channel authentication.

## Evidence and reporting

Persist immutable submission trees, raw model/tool observations, execution and
grading status separately, wall times, original independent audited-v2 grade,
and a fresh regrade bound to the same submission/procedure/environment. Retain
all failures. Separate solver usage from grader overhead. CLI root steps and
tool events are observations, not proof of complete provider request counts.
Unknown input/output/cache totals stay unknown; known subtotals stay labelled.
Catalog pricing has no verified numerical tariff, so do not invent cost or
cost-effectiveness rankings.

Keep configured/requested, CLI-observed, gateway-resolved, and served-attested
model identities separate. Catalog gateway declarations are configuration,
not gateway observations or served attestations. Unknown identities remain
unknown. Do not reprice or relabel historical evidence: the prior 14/23 result
and historical regrade are not preregistered replicates.

## Expansion gate

Only after all three smoke cells pass methodological audit may a new protocol
select 3–5 independently validated tasks, three repetitions per task/arm, and
freeze the complete balanced/randomized matrix before inspecting outcomes.
The expanded scope requires separate operator authorization. If only retrying
has a validated grader, expansion is blocked rather than silently substituting
unvalidated tasks. Report per-task paired quality/solve rate/time/observed
requests/tokens, missingness and infrastructure failures. Do not claim
statistical conclusiveness or equivalent-compute superiority when additional
invocations explain the difference.
