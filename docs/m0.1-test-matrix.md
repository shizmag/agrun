# M0.1 contract traceability matrix

## Status and oracle rules

Frozen plan: production changes are permitted only after expected outcomes and
actual tests receive independent review. Detailed scenario inputs and positive/negative
variants are in the independently authored area plans linked below. These plans
form the scenario-level matrix: each ID records requirement, setup, observable
outcome, failure category, level, ownership and initial/final status.

Initial outcome classifications:

- **Confirmed:** original behavior satisfies the independent oracle.
- **Defect:** implementation violates a resolved contract.
- **Ambiguous:** specification needs a decision before a defect can be claimed.
- **Test defect:** fixture or oracle is invalid; correction requires review.
- **Unsupported:** outside the declared M0 boundary.
- **Infrastructure:** environment prevents observing the intended behavior.

## Independent review

See [review record](m0.1-review.md). Expected outcomes cannot be changed merely
because M0 fails. New semantic decisions must be recorded with reviewer approval.
No absent assertion is counted as verified coverage.
