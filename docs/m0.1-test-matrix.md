# M0.1 contract traceability matrix

## Status and oracle rules

Design draft: no production changes permitted until expected outcomes and actual
tests receive independent review. Detailed scenario inputs and positive/negative
variants are in the independently authored area plans linked below. These plans
form the scenario-level matrix: each ID records requirement, setup, observable
outcome, failure category, level, ownership and initial/final status.

Initial outcome classifications:

- **Confirmed:** original behavior satisfies the independent oracle.
- **Defect:** implementation violates a resolved contract.
- **Ambiguous:** specification needs a decision before a defect can be claimed.
- **Test defect:** fixture or oracle is invalid; correction requires review.
- **Unsupported:** outside the declared M0 boundary.
- **Infrastructure:** environment prevents observing the intended behavior.

## Mandatory end-to-end gates

Every gate inspects persisted history, not just a returned verdict.

| ID | Invariant | Positive oracle | Adversarial control | Owner | Initial / final |
|---|---|---|---|---|---|
| AC-01 | I-3, I-4, I-8 | Correct patch retained; evaluation completed/pass; consistent IDs | Incorrect patch cannot pass | F | pending / pending |
| AC-02 | I-4, I-5 | Generation success; evaluation completed/fail | Grader failure is not quality fail | F | pending / pending |
| AC-03 | I-1, I-2, I-3 | Evidence matches original bytes | Changed artifact cannot inherit pass | F | pending / pending |
| AC-04 | I-3 | Matching spec/procedure permits evidence match | Changed spec/procedure does not | F | pending / pending |
| AC-05 | I-5, I-8 | Grader crash/timeout visible as infrastructure error | Never pass or substantive fail | F | pending / pending |
| AC-06 | I-6, I-7 | Two steps overlap within limit; isolated writable state | Dependent cannot consume incomplete inputs | F | pending / pending |
| AC-07 | I-6, I-8 | Cancellation/timeout retained; process cleanup | No downstream execution or false success | F | pending / pending |

## Independent review

See [review record](m0.1-review.md). Expected outcomes cannot be changed merely
because M0 fails. New semantic decisions must be recorded with reviewer approval.
No absent assertion is counted as verified coverage.
