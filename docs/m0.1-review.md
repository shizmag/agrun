## Acceptance criteria and high-priority oracle risks

1. **Evaluator is not a verdict echo (critical).** Exercise genuinely distinct submitted trees with independently known pass/fail semantics against the real hidden procedure; assert `completed/pass` versus `completed/fail`, not just report shape or success. Include an intentionally wrong implementation whose common happy paths pass but boundary behavior fails. A constant-pass evaluator must be killed. Fake injected evaluators alone cannot establish grading correctness.
2. **Execution is distinct from correctness (critical).** Assert successful solver + incorrect submission gives `status=success`, `execution_status=completed`, `verdict=fail`; process timeout, cancellation, spawn failure, missing/malformed marker, nonmatching exit/marker, and abnormal exit give `not_evaluated`, not fail. Marker protocol is explicitly exit 0/pass, exit 1/fail; assess protocol cases with local fake runner and at least one real subprocess. Avoid conflating solver failure with grader fail.
3. **Dependency must gate scheduling and dataflow (critical).** Use synchronization barriers/queues, not timing-only sleeps, to prevent a downstream step from entering before every explicit `needs` and inferred input reference completes. Test inferred-only dependency separately (no redundant `needs`), and assert downstream receives the predecessor's actual distinguishable value. Independently test failure/block propagation. A scheduler that ignores dependencies or substitutes a constant must fail. Bound all waits and ensure teardown releases blocked threads.
4. **Provenance binds actual bytes, not stable-looking labels (critical).** Recompute digests from stored artifact contents using the documented canonicalization, and change one factor at a time: submitted repository contents, specification including dataset revision/base commit, exact procedure bytes, and inherited environment/overrides. Each corresponding binding must change while unaffected bindings remain stable under controlled inputs. Check that stored snapshot is evaluated, not original mutable path; avoid comparing two independently generated opaque digests only. Tests must not assume environment is secret-independent or assert raw secret values are persisted.
5. **Cancellation and timeout are operational (high).** Real local subprocess starts a descendant; verify deadline/cancel returns correct distinct status and that descendant no longer runs. Use an explicit readiness handshake before cancellation and bounded cleanup, not merely a pre-cancelled token or elapsed-time assertion. Runtime executor timeout semantics versus adapter-process timeout require separate tests; confirm contract before asserting a forced timeout on arbitrary trusted Ruby executor. Never leave child processes behind.
6. **Count mutations are meaningful (high).** Assert exact solver/evaluator call counts and unique run IDs for a nontrivial task × solver × model × repetition matrix, including non-default repetitions and error/skip pathways; verify individual cell identities, not just array size. Retries assert exact attempts and eligible classification, successful retry, exhausted budget and dependent behavior. Avoid tests that only assert `>=` or count calls from a separate stub unrelated to the actual execution.
7. **Independence and determinism (high).** Public task and solver workspace must not contain copied hidden procedure; inspect actual task/workspace, but do not claim same-user filesystem separation is a security sandbox. Use fresh temporary stores/workspaces, distinct sentinel contents, synchronization, and no credentials/network. Fake solvers demonstrate plumbing, not model ability. Check persisted evidence against reported metadata, not implementation-produced report values compared to themselves.

## Contract ambiguities to resolve before enforcing

- `CONTRACTS.md` states cancellation and timeout statuses and ProcessRunner enforcement; it does not explicitly guarantee preemption of arbitrary in-process trusted Ruby executors. Do not infer that stronger guarantee from process-adapter requirements.
- `docs/methodology.md` says the environment digest records provenance, not a lockfile; do not require reproducibility across hosts or identical environment under changing inherited variables.
- Failure verdict requires the documented matching `AGRU_VERDICT=` marker, not merely a nonzero exit. Malicious submissions are outside the sandbox/security claim.
- Git metadata exclusion and snapshot digest canonicalization need evidence from Store implementation before choosing a reference digest oracle; direct file SHA256 is not automatically the repository digest.

## Review of parent design boundaries

### High: same-content association needs a stated source of truth

`openspec/changes/m01-verification/design.md:15-16` and `openspec/changes/m01-verification/specs/verification-integrity/spec.md:10-13,20-23` correctly separate content equality from execution identity. However, define exactly which persisted IDs link a validation to its generation and run, and how a consumer determines the expected generation. Today `lib/agent_runtime/evaluation/evaluator.rb:13-15,37-44,52-60` stores an evaluation artifact and an independent UUID while its report exposes only the evaluation artifact *digest*, not its Store artifact ID or generation/attempt identity; `lib/agent_runtime/store.rb:50-51` does preserve an artifact ID and run/step/attempt. The current wording could be satisfied by writing two different UUIDs without proving that the report's verdict belongs to the intended producer. This is a contract/design gap, not yet a claim that existing evaluation falsely reuses a verdict. Resolve whether association is a new M0.1 persisted feature or an explicitly unsupported capability; do not assert it exists by construction. Preserve legitimately deduplicated content, and define whether a caller may intentionally reuse validation when the *entire* evidence tuple matches, rather than treating identical hashes as inherently stale.

**Oracle change:** create two separate generations with identical repository bytes and equal evidence hashes but distinct IDs and run/attempt metadata. Verify each persisted validation points to the matching generation and run through a public, retrievable link; swap the association while keeping every digest unchanged and require the consumer to reject it as stale/not evaluated. Also change a digest independently while holding association constant. Do not accept `validation["id"] != generation["id"]` as proof of linkage. Avoid assuming `run_id` is unique per generation when several generations can exist in one run. If there is no association-verifying API, identify the spec as unimplemented rather than silently constructing the link in the test.

### Medium: cooperative boundary needs concrete cancellation and deadline semantics

`openspec/changes/m01-verification/design.md:17-19` sensibly avoids promising safe forced preemption of arbitrary trusted Ruby; `openspec/changes/m01-verification/specs/verification-integrity/spec.md:15-18` should clarify what is actually provided to a cooperative executor: `Request#timeout` is a duration, not an absolute deadline, and cancellation is a shared token (`CONTRACTS.md` execution boundary). Define whether a returned success after cancellation remains success at step level, how pending steps and run-level cancellation behave, and whether deadline enforcement for cooperative Ruby is required only when the executor explicitly checks elapsed time. Do not demand a particular race outcome when cancellation coincides with completion. `lib/agent_runtime/runtime.rb:116-119` currently wraps every executor in `Timeout.timeout`, an asynchronous interrupt; the new design is a weaker promise, not evidence that existing code is purely cooperative or safe to interrupt. Record that discrepancy and avoid turning an implementation detail into the required oracle.

**Oracle change:** separately test token/request propagation using a cooperative executor with handshake and finite self-controlled exit; assert its explicitly returned status and no downstream launch after observed cancellation, without testing forced termination of arbitrary Ruby. For process adapters, use real parent/descendant and both cancellation and deadline, including a TERM-resistant process to exercise bounded escalation, with readiness and cleanup. Limit the descendant claim to ordinary processes in the process group, not escaped sessions. Do not require deadline and cancellation precedence in an uncontrolled simultaneous race.

### Medium: grader cancellation and timeout belong to different interfaces

`lib/agent_runtime/evaluation/evaluator.rb:8-9,31-35` accepts a timeout but does not accept a cancellation token. The initial item 2's proposed grader cancellation case is therefore not an existing evaluator API requirement; test evaluator timeout/infrastructure classifications and cancellation where the contract actually supplies a token, or make a separate explicit API decision before requiring evaluator cancellation. Similarly, marker/exit fixtures should return proper ProcessRunner-shaped status; tests for evaluator protocol must not mistake its own exception path for a rejected marker.

### Lower: independent snapshot oracle details

`lib/agent_runtime/store.rb:83-91` canonical manifest excludes `.git`, serializes sorted relative paths, executable state and base64 file contents. A reference digest test should construct expected canonical bytes independently from a tiny known tree and verify content and executable-bit changes, while ensuring `.git` changes do not change repository digest. Ordinary content-hash consistency alone cannot prove evaluator graded that snapshot: mutate the submitted original after the store snapshot at a controlled barrier, and verify the grader receives snapshot content, not the now-mutated source; ensure mutation occurs after snapshot materialization, not during its non-atomic walk. Environment tests should control inherited ENV in an isolated process rather than mutate global ENV concurrently.

## A plan review and proposed compiler decisions

**Conditional approval to write tests.** The parent decisions align with `docs/architecture.md:5-21` and the trusted DSL boundary. Unknown adapter *names* must remain valid while unknown executor *references* remain errors. No cross-namespace uniqueness or hash-object identity should be asserted. Zero retries and positive finite timeout are valid; retries 0–10 inclusive, with -1 and 11 invalid, should be explicit boundary controls. These are newly clarified contracts where previous docs were underspecified, not claims of existing behavior.

**Required oracle clarifications:**

- `docs/m0.1-a-plan.md` proposes asserting Error message categories. Make those only stable, semantic contextual fragments explicitly agreed by contract, not implementation wording or exception backtraces; otherwise require class plus helpful nonempty message and case-specific positive controls. Avoid prescribing a single error when one malformed IR violates multiple rules.
- Define JSON compatibility before tests: allow JSON null, booleans, strings, finite numbers, arrays, and string-keyed objects in raw IR; clarify DSL's intentional normalization of symbol keys/values, as existing valid `outputs: {answer: :text}` uses symbols, and executor config conventions use JSON string keys. Decide explicitly whether symbol values in *config* are allowed/converted or rejected; arbitrary objects must never be silently stringified. Reject non-finite numbers and key collisions introduced by key normalization (e.g. `:x` and `"x"`) rather than choosing silently; don't accidentally require rejection of ordinary DSL symbol identifiers/types.
- `input_types` orphan keys are not forbidden by `CONTRACTS.md` or `docs/architecture.md:14` (which only says optionally constrains a binding's type). The A plan labels these invalid; either parent explicitly adopts the stronger schema rule, or mark that case unresolved/omit its negative assertion. Likewise choose whether omitted optional `input_types`/top-level `config` and unrecognized keys are valid before asserting rejection; DSL always supplies them but hand-authored IR need not necessarily do so.
- Missing or wrongly typed nested maps must raise `AgentRuntime::Error` without accepting `NoMethodError`, `TypeError`, JSON errors or arbitrary coerced values. Do not broadly rescue arbitrary exceptions from trusted Ruby source: native Ruby syntax errors and exceptions raised by authored code remain outside this clarification. Distinguish JSON parser errors before an IR reaches `validate!`, if any, from malformed Ruby IR objects.
- `Float::INFINITY`, `-Float::INFINITY`, `Float::NAN`, numeric strings and booleans deserve timeout negatives; finite positive integer and fractional float positive controls. JSON-compatible raw IR excludes Ruby-only `Rational`/`Complex` even if Ruby's `Numeric` accepts them. Ensure the positive JSON sample's exact canonical expected bytes and SHA-256 are independent of `AgentRuntime::IR.dump`; array reordering must compare values that are actually distinct.
- Separate empty step `outputs` and empty top-level `outputs`, references to missing artifacts, valid forward references, true cycles, and cycles hidden by inferred dependencies. Dependency normalization expected ordering/dedup can be asserted as value, not returned identity. Type mismatch tests should show both directions (`text`→`string`, `string`→`text`) and same-type positive control.
- `docs/m0.1-a-plan.md` lists duplicate executors and emits but should cover duplicate input declarations and duplicate program declarations too; literal duplicate hash keys cannot be observed after Ruby parsing and are correctly excluded. Explicitly test a same-spelled input, executor, step and output that is otherwise valid to prevent accidental cross-namespace uniqueness.

## B and D plan review / freeze recommendations

**B: approve with changes.** Parent's mixed-status, malformed Result and partial artifact decisions are sound. Gate-based scheduler and process tests are appropriate; distinguish a fixture watchdog from the behavior under test. A `Result#retry_safe` boolean default false is a reasonable minimal extension to `CONTRACTS.md:8`, but only an executor that *knows* no side effects occurred (or whose operation is actually idempotent under the same request) may set true; neither a transport label, timeout, status, exception, nor caller assumption alone proves safety. Strictly require `retry_safe == true`; nil, absent, strings and malformed flags fail closed. Require `status == "failure"` AND transport classification AND true flag AND remaining budget AND no cancellation, and ensure unsafe errors are still recorded. Decide whether custom adapters using old transport-only semantics intentionally lose retries; this is a behavioral regression requiring contract/release note and migration of existing tests/adapters, not just a test implementation detail. A per-request caller idempotency declaration is an alternative but is less reliable without stable idempotency keys/provider support; do not imply exactly-once. Test identical side-effect-counting failure scenarios safe vs unsafe, budget bounds and cancellation before retry; do not use a deliberately side-effecting result flagged safe as evidence safety is guaranteed. Coordinate D-11/D-12 and B-07/B-08/B-10/B-11, which still assume transport label alone. If no built-in adapter can establish pre-effect safety, it is correct for none to opt in.
