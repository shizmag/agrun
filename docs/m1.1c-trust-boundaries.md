# M1.1c trust boundaries: scoped `nl2repo-audited-v2`

This is the trust-model companion to `docs/m1.1c-scoring-contract.md`. It freezes
the **benign-submission** scope, not a claim that adversarial isolation or an
authenticated collector has been implemented or validated.

## Claims and non-claims

The permitted claim, after the scoring gates actually pass, is: a specified
submission was evaluated by the recorded `nl2repo-audited-v2` procedure under an explicit
benign/non-interference assumption. It is not an official NL2Repo paper score,
an unconstrained-solver capability measurement, or evidence of secure execution
of hostile Python. Call this **scoped audited evaluation**, not authenticated or
candidate-resistant authoritative grading.

For `nl2repo-audited-v2` only, `trust: audited` with mandatory
`trust_scope: benign_ordinary_submissions` permits scoped quality results in place
of the old universal authentication gate. There is no `authenticated` flag.
The stronger historical M1.1/M1.1b claim boundary remains unchanged for historical
protocols/evidence and for claims of adversarial authority. A same-process pytest
plugin, structured report or random filename does not establish that authority.
The public-contract amendment must encode this version-specific exception before
implementation. Do not reuse a general `validated` or `official_ready` flag to
obscure the difference.

## Trust and data-flow table

| Component/data | Boundary and obligation |
| --- | --- |
| Operator configuration, pinned procedure and preflight | Trusted inputs; validate hashes and scope. Operator mistakes remain possible. Cached assets are not automatically authorized assets. |
| Solver | Receives only public task/instruction and its fresh workspace. Never receives reference source, hidden tests, grader paths or private preflight fixtures. |
| Submission artifact | Snapshot and verify actual submitted bytes before grading/regrading. Reject unsafe paths/link/special-file forms according to the submission contract. A submitted repository is code, not a trusted report. |
| Grader-only reference and tests | Separate from solver workspace and public task. Used only for authorized controls/grading; never copied to the solver to make controls pass. |
| Candidate execution | Assume no deliberate interference with collection, test assets, results, interpreter state or grading procedure. Enforce recorded resource/network policy; host/container separation is not proof of this assumption. |
| Pytest/collector | Trusted procedure code, but potentially shares interpreter/process privileges with candidate imports. Structured lifecycle records improve benign accounting, not adversarial authenticity. |
| Result artifacts and Store | Host validates schema, identity bindings, completeness and outcomes, then stores immutable evidence. Candidate-written files/stdout alone cannot establish a stronger trust claim. |
| Reports | Carry protocol/trust-model labels, coverage, environment and limitations. Never upgrade diagnostic evidence by dropping qualifiers. |

## Clean submission and import provenance

Build evaluation from a clean task-specific tree: frozen grader-owned tests and
explicit permitted support assets plus the captured candidate. Never overlay the
candidate on an original implementation tree and assume omissions mean absence.
Inventory the allowed support files and bind their digests and materialization
policy. A cleanup filename blacklist is not a clean-tree proof.

Use a frozen working directory, `PYTHONPATH`/import policy and isolated temporary
state. Inspect relevant import origins in controls and submitted runs. Reject
reference backups, original workspaces, host checkout/site-package copies or
other unintended implementations that can satisfy candidate imports. An installed
package with the task's name can be reference fallback even when the working tree
looks empty. A pinned image is necessary for reproducibility, not proof of clean
contents. Environment-specific allowed dependencies must be explicit.

Negative controls must exercise missing/partial implementation paths, not only a
single empty candidate. Passing these controls supplies bounded evidence; it does
not prove absence of every fallback route or every import hook manipulation.

## Deliberately out of scope

`nl2repo-audited-v2` does not claim resistance to a candidate that:

* Prints forged summaries, writes/replaces result files or tampers with reports.
* Monkeypatches pytest/Python, plugins, test discovery, import hooks or collector
  functions; changes marks/outcomes; fabricates lifecycle events.
* Calls `os._exit`, signals processes, forks interfering children, exhausts the
  runtime or tampers with writable tests/collector state.
* Reads hidden tests at runtime, searches for a reference copy, retrieves source
  over the network, or exploits the host/kernel/container boundary.

These are limitations, not acceptable ways to earn a score. If detected, reject
the attempt as untrusted/incomplete with no quality score. The benign assumption
cannot be used to accept known tampering. Some interference may be undetectable
in a shared interpreter; schema validation, digests and a passing reference
control do not eliminate that risk. A malicious submission can mimic legitimate
structured results when it shares collector privileges.

Ordinary incorrect implementations, assertion failures, missing modules, syntax
errors, skips and expected failures are **inside** the evaluation scope. Handle
them according to the scoring contract rather than calling all candidate bugs
infrastructure failures. Conversely, a timeout or vanished collector cannot be
turned into a semantic zero merely by assuming the candidate caused it.

## Infrastructure and operational policy

Use a fresh execution per attempt and record effective mounts, user privileges,
network policy, platform, resource/time limits and teardown outcomes. Do not mount
the Docker socket, Store database, secrets, unrelated host repositories or solver
session state into candidate execution. Private assets stay outside public
reports except for non-disclosing identities/digests and approved summaries.

Directory separation alone is not a security sandbox. Read-only mounts protect
file bytes only within their effective permissions; they do not authenticate
Python events or prevent in-memory monkeypatching. Containers reduce some host
exposure but do not establish hidden-test confidentiality or hostile-code safety.
No local control result justifies broad security guarantees.

Offline tests must remain deterministic, credential-free and Docker-free. The
operator must separately opt into live execution, provider use and any asset
downloads. This workstream authorizes none of those operations. Mere image/cache
presence does not authorize redistributing or disclosing private assets.

## Evidence labels and future promotion

Keep static audit, untrusted diagnostic observations, scoped `nl2repo-audited-v2`
evaluation and future candidate-resistant authority separate. Historical M1.1b
controls remain diagnostics even if their numerical outcomes match a new run.
Persist limitations with evidence so independent regrades and aggregate reports
cannot lose them. Missing results remain explicit coverage gaps.

Promotion beyond the benign scope needs a new reviewed trust/protocol contract,
validated independent collection and result-channel protection, clean-import
controls, adversarial probes, and evidence for the effective runtime boundary.
Do not obtain promotion by changing a report label, setting `validated: true`, or
adding a JSON serializer. Claims must follow demonstrated properties.
