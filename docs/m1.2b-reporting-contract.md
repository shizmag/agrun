## Existing authority and boundaries

Extend `Execution::Summary`, immutable attempt logs, and `Benchmarks::Reports`;
do not introduce a telemetry subsystem or change `Request`, `Result`, or the DSL.
The authoritative reconstruction input is the content-addressed log artifact,
with raw process stdout preferred over copied parsed events. Cached SQLite
execution summaries, usage, cost, and requested configuration cannot establish
observed usage, provider identity, routing, or billing. Corrupt evidence remains
an error and must never be repaired by rendering a report.

Keep execution status separate from evaluation verdict. Reuse independent audited
grading, evidence binding, and immutable-submission regrade integration. The E
integration fixture supplies independent hand-authored grading results to the
existing runner; it does not claim to revalidate the audited collector itself.
Existing audited collector/binding tests remain required regressions.

Cleanup evidence is projected separately: `process_cleanup` reconstructs
`execution.process.cleanup`; `cleanup` reconstructs adapter artifact cleanup.
Both expose derived `status`, allowlisted error classifications, and (when
Boolean) `reaped`. Missing evidence is `status: unknown`, not success. Arbitrary
messages, paths, and extra error fields are omitted. Immutable raw evidence
remains available through the existing evidence artifact. The reporting test
`test_cleanup_failure_classifications_survive_reconstruction_without_messages`
first failed with `KeyError: key not found: "process_cleanup"` and now requires
failure classifications to survive both attempt and persisted run reconstruction.

## Proposed additive compact attempt fields

- `identity.requested`: `provider`, `model`, `route` copied from persisted
  `model_profile`. Exact model spelling is retained, including
  `cx/gpt-6-luna-low`; it is not evidence that this model served the request.
  Provider/model come from the profile itself; route and endpoint come from
  canonical `model_profile.tool_policy`, with top-level legacy fallback only
  when the policy does not contain that key. New fixtures use the canonical
  shape rather than inventing a top-level route accepted by ModelProfile.
- `identity.observed`: unique provider/model/route observations reconstructed
  from authoritative native root-step events. Native `providerID`/`modelID` map
  to provider/model. Missing fields remain `null`; requested values never fill
  missing observations. Native OpenCode identities are not proof of upstream
  provider routing. Route stays `null` without actual route evidence.
- `identity.observation_basis`: `native_root_step`. No fabricated provider
  request identifier or inferred routing attestation.
  `identity.verification` remains `unknown` even when native fields are present.
  An actual native/requested difference is disclosed as
  `discrepancy: observed_requested_mismatch` with `mismatched_fields`; absent or
  matching observations do not prove a route match and stay `unknown`.
  Enforcement of identity mismatch is the adapter's responsibility, not a
  retrospective report projection. Step-finish streams normally omit these
  identity fields; their absence must not be filled from requested configuration.
- `preflight`: sanitized persisted preflight evidence, including failure reason,
  executable identity and finite deadline when supplied by the producer. An
  admission or passing preflight is not a launch observation. Preserve separate
  `admission`, `launch_observed`, and process outcome fields.
- `accounting_coverage`: `provider_requests`, `provider_retries`,
  `auxiliary_usage`, `provider_charges` are `unknown` for the root-step protocol;
  `reported_cost_basis` is `native_step_observations`, and `billing_status` is
  `not_provider_billing`. These are coverage disclosures, not extra counters.

Keep these fields nested in existing execution summaries and report execution
columns. JSON/CSV/Markdown expose the same evidence without copying raw events.
Run summaries retain each attempt's identity/preflight/accounting coverage;
transport attempt count must not be renamed provider request or retry count.

## Accounting invariants

Existing `Execution::Usage` deduplication stays authoritative: scope + identity
kind + native step ID, not a guessed provider request ID. Duplicate identical
observations count once; conflicting/missing identities cannot establish totals.
Cache-read/cache-write and reasoning token categories remain distinct, with
unknown category relations preventing unsupported price arithmetic.

Unknown totals remain `null`, never zero. Root-step completeness does not prove
provider-request completeness, auxiliary title/summary usage, hidden provider
retries, or billed charges. Native cost observations, model-price estimates,
and provider invoices are different evidence classes. Existing `cost` remains
unknown when coverage is incomplete, even when a native observation reports
`0.25`. Regrading must not add another solver request, overwrite solver usage,
or promote a copied report cost to a charge.

No token, request, run, or monetary quota is required by this proposal. Finite
deadlines and explicit live authorization remain producer responsibilities;
an absent optional quota is not a telemetry failure. All E tests are offline.

## Proposed production patch after review

1. In `Execution::Summary.reconstruct_attempt`, project requested identity from
   the persisted model profile, observed identity from reparsed raw events, and
   sanitized preflight from the immutable record. Include preflight/requested
   identity for nonlaunched blocked attempts without fabricating observations.
2. Add explicit root-step accounting-coverage disclosures. Retain existing usage
   normalization and compact/remove detailed request observations as today.
3. Continue using `Summary.from_run` in `Reports.summary`; existing nested
   execution rendering should carry additive fields without a new report model.
4. Coordinate the raw `preflight` and `model_profile.route` producer shapes with
   adapter ownership before implementation. No secret, prompt, credential,
   hidden procedure, or unrestricted raw config belongs in compact identity.
