Status: adapter integration implemented and tested offline. No provider request
was made by the workspace/lifecycle owner. The authorized pilot is limited to
OmniRoute upstream `cx/gpt-6-luna-low`, without provider/model fallback.

## Implemented admission boundary

`Request`, `Result`, and ProcessRunner's signature remain unchanged.
`OpenCodeCLI` adds constructor `authorization_scope:` and `launch_config:` while
retaining `authorization:`, `budget:`, and `scopes:`. Real-provider execution
requires constructor `live: true`, a concrete `Execution::LiveAuthorization`, a
concrete `Execution::OpenCodeLaunch`, and supplied shared coordinator/scopes.
An arbitrary authorization callback cannot authorize live execution. Fixture
registration and SHA-256 checks remain intact for fixture execution.

`live_authorized?` checks concrete authorization identity, expiry/preflight,
executable identity and SHA-256, and the concrete launch object. Dispatch also
compares profile provider/model, authorization scope, endpoint, route, and
`tool_policy["model_fallback"] == false` against the launch object. ModelProfile
keeps its existing strict fields. Request configuration and inputs are copied
and frozen before admission. Coordinator admission receives the independently
supplied actual authorization scope, not one extracted from the grant.

## Environment and launch configuration

C owns `lib/agent_runtime/execution/opencode_launch.rb`. The adapter consumes
its `with_environment(workspace:)`, `argv`, `scope`, and `to_h` interfaces rather
than accepting arbitrary live environment/configuration hashes. C provides
private HOME/XDG/config/data/cache/state roots outside the repository and removes
them after the launch block. The adapter explicitly sets every ambient ENV key
to nil before merging C's allowlist, preserving ProcessRunner's inherited-env
signature without inheriting user overrides, preload settings, or credentials.
Observed fixture launches also use private HOME/XDG roots and scrub ambient ENV.

The credential is supplied through C's environment mapping, not a literal in
solver-readable config or persisted receipts. Sensitive values from the actual
yielded environment are added to adapter redaction before CLI output collection.
The trace records C's redacted `to_h` launch identity. A canonical digest of the
complete effective launch configuration is **not yet implemented/verified** by
this adapter; executable SHA-256 is not a substitute for that digest.

Source and loopback checks belong to A/C. `--standalone` alone must not be treated
as proof of config, auth, plugin, MCP, or ancestor isolation. Configured tool
restrictions are not OS egress controls. Directory separation and trusted Ruby
programs are not a sandbox. Native hook absence/malformed loading can fail open;
outer adapter admission is not a pre-dispatch provider-request enforcement hook.

## Workspace, collection, and observations

The specification-only layout initializes an empty solver repository, with
`INSTRUCTION.md` outside that repository. It must not copy hidden procedures,
grader/tests, dataset checkout, memory, or benchmark support files into solver
material. Workspace materialization and immutable submission capture are owned
by the benchmark/runner boundary, not established merely by accepting a path.

Git patch collection remains around actual execution. Collection failure cannot
be promoted to success and retains available admitted execution/session evidence.
Successful CLI completion is not an evaluation verdict. Timeout/cancellation
take precedence over successful terminal events, and truncated protocol cannot
establish success. Process cleanup/reaping behavior remains in ProcessRunner.
Leases are released in ensure. Live errors are not implicitly retry-safe.

Actual native `providerID`/`modelID` observations are retained. An observed
mismatch fails execution with discrepancy evidence; timeout/cancellation retain
precedence. Missing native identity remains unknown, never fabricated from the
requested profile. This is post-execution detection, not pre-dispatch blocking.

Partial repository/text/patch outputs may exist after failed execution. They
must not be labeled successful submissions. When a failed solver supplies an
actual repository output, ExperimentRunner now validates/captures it into
`partial_submission`, without grading or changing solver status/error. Capture
failure is recorded separately as `partial_capture_error`. Direct OpenCode
solves no longer substitute their original workspace when no output exists.
Strict direct OpenCode execution opts into Runtime's separate
`partial_outputs` attempt evidence. Only actual repository outputs are captured;
failures remain absent from normal step/report outputs and downstream bindings.
Capture errors have their own attempt evidence. The solver recovers the last
attempt's validated Store artifact rather than its original mutable workspace.
The solve result carries that original `partial_repository_artifact` reference;
the runner verifies and retains it directly as `partial_submission`, preserving
its runtime run/step/attempt identity and input lineage instead of recapturing a
new unlinked artifact. Artifact/path disagreement fails partial capture only.
This opt-in is not automatically enabled for arbitrary DSL programs.

## Limits and validation

The pilot has no invented token/request/run-count/monetary cap. Finite timeout,
local concurrency, expiry, cancellation and per-attempt single-lease accounting
remain mandatory. B supports nil experiment/run max_attempts; an attempt scope's
single lease is an accounting invariant, not an experiment quota. Local process
termination cannot revoke an already accepted upstream request or guarantee cost.

Original test-first baseline: 7 runs, 20 assertions, 3 failures (live admission,
ambient overrides, private HOME/XDG). Existing tests were updated to the concrete
B/C interfaces; no duplicate lifecycle test file was created.

  9 runs, 51 assertions, no failures/errors.

  31 runs, 169 assertions, no failures/errors.

These tests use recording runners and synthetic JSONL, not provider calls.
