# M0.1 C: scientific-integrity verification plan

Design only. Initial status of **every C-xx case: UNTESTED**. No test or production
change is authorized by this document. Later test ownership is exclusively
`test/m01_integrity_test.rb`; changes to shared contracts, Store, evaluator, runner,
or existing tests require the parent/owning stream. No child commits.

## Requirements and evidence basis

- **R1 — submitted bytes are authoritative.** A solver's successful generation,
  claimed patch, public checks, or earlier passing result do not establish
  correctness. Evaluate the actual submitted tree with an independently authored
  oracle. Preserve the original input and submitted snapshot.
- **R2 — evidence identifies its experiment.** Bind repository, specification,
  exact procedure, and environment, and associate their artifact identities with
  the current generation/run. Equal bytes permit content deduplication, not reuse
  of another generation's provenance or verdict.
- **R3 — fail closed.** Missing, malformed, corrupt, stale, or mismatched evidence
  must never become a pass. It is an evaluation/evidence error, not proof that a
  candidate is incorrect. Preserve diagnostic/error class without requiring exact
  platform-dependent text.
- **R4 — independent statuses.** Keep generation status, evaluation execution,
  and correctness verdict separate, including when an evaluator fails after
  successful generation.
- **R5 — bounded offline independence.** All probes are local deterministic
  fixtures without credentials, network, paid providers, or copying hidden
  procedures into solver workspaces. Do not claim OS isolation.

## Actual boundary and safe minimum semantics

The public submission seam is
`Evaluator#evaluate(task:, repository:, run_id:, timeout: 30)`. Runner passes a
redacted `Task` to `solve(task:, model:, budget:, workspace:)`, then evaluates a
successful returned repository. Evaluator snapshots the submission, copies its
materialized tree to a temporary target, and executes copied evaluator-owned
procedure bytes in a separate Ruby process. This is procedural separation, not
an adversarial security boundary: trusted Ruby/submitted code runs under the same
host user, inherits environment, can access host paths, and may write stdout.
In particular, a verdict marker is not a cryptographic attestation against
malicious submitted code. Do not promise resistance to arbitrary same-user
tampering, hidden-test discovery, marker spoofing, or environment escape.

Store SHA-256 content and UUID artifact records are different identities.
Repository manifests exclude `.git`, include file paths/bytes/executable bits,
reject symlinks, and do not represent empty directories. `Store#value(artifact)`
rehashes supplied-path content; this is not validation of artifact metadata
against an authoritative database record. Read-only permissions are an accident
guard, not immutability against the owning user. `Store#report(run_id)` reads
stored report JSON; there is no public verify/replay/reuse API.

Current four bindings contain repository, spec plus revision/base commit,
procedure bytes, and environment (Ruby/platform/executable, normalized LANG/TZ,
inherited-environment digest). They do not explicitly bind evaluator source,
marker-parser version, full runner configuration, or timeout. Runner separately
records `configuration_digest`. An unchanged hidden-test file is not evidence of
unchanged evaluator semantics. These are contract decisions below, not excuses
to change expected outcomes to match current output.

Minimum outcome table:

| Condition | Generation | Evaluation execution | Verdict |
| --- | --- | --- | --- |
| Generation succeeds; valid passing oracle completes | success | completed | pass |
| Generation succeeds; valid failing oracle completes | success | completed | fail |
| Generation blocked/fails/times out; no eligible submission | original status | not_started | not_evaluated |
| Generation succeeds; grader crashes/protocol/evidence error | success, retained independently | error (or explicit equivalent) | not_evaluated |
| Generation succeeds; grader times out | success | timeout | not_evaluated |

Existing protocol accepts exactly matching exit 0/pass or exit 1/fail markers;
exit 1 alone does not prove an assertion failure. A thrown infrastructure
exception may propagate from the standalone evaluator if that is the agreed
public contract, but must never return pass/fail. Runner must retain successful
generation separately even if its top-level execution status becomes failure.
No exact exception class for evidence verification is currently specified.

For future evidence acceptance, require current content bindings, authoritative
artifact metadata/provenance, and current run/generation association. Historical
reports may remain readable as historical records after source changes; merely
reading them must not imply current validity. Without a validation API, mark
acceptance/reuse tests contract-blocked rather than inventing an internal API.

## Fixture strategy and independent observations

Use fresh temporary fixture/store/run roots per test, fixed model-free solvers,
and hand-written good/bad `Clamp.call` implementations, not production Fake's
patch algorithm as the oracle. Independently assert lower/upper bounds,
in-range preservation, fractional and negative inputs, equal bounds, and
`ArgumentError` for inverted bounds. Use a local owned procedure with known
outcomes, not a copy of evaluator parser logic. Record expected SHA-256 from
independently read procedure bytes; inspect stored spec/environment JSON and
submitted tree bytes. Do not use `Store#value` as its own integrity oracle or
assert a digest only equals itself through two report fields.

For protocol-only cases inject a tiny ProcessRunner-compatible object at the
documented constructor seam, capturing argv/cwd/env/timeout. Also retain real
Ruby subprocess cases for good/bad/crash/deadline so fake statuses do not stand
in for actual process behavior. No sleeps without a bounded parent deadline;
timeout fixtures use a blocking child and a small positive explicit timeout.
Restore any temporary ENV change with `ensure`; never serialize secret values.
Fault injection touches only temporary artifacts created by the test, never the
checkout or shared `.agru`. If metadata corruption needs SQL, flag missing public
seam; do not quietly reach into `@db` or create production hooks.

Legend: **+** positive control; **−** adversarial/negative case. “Error category”
is semantic unless an exact existing Ruby class is explicitly named. Each ID
below has initial status **UNTESTED**, including contract-blocked proposals.

## Ambiguities and parent decisions required before implementation

1. **Evidence acceptance API absent.** Define the public operation, expected
   context, required schema, and error category for validating a report for a
   current experiment. Store report retrieval is not that API. C-12 and
   C-18–C-23 acceptance variants cannot be honestly completed without it.
2. **Metadata authority and provenance.** Decide which fields are authenticated
   against stored records, whether every evaluation artifact must carry current
   run association, and how legitimate cross-run input lineage is represented.
   A UUID/string equality check alone is not authenticity; do not claim malicious
   same-user database rewriting is prevented.
3. **Execution/generation schema.** Runner currently catches evaluation exceptions
   in a broad rescue and writes top-level failure/error/not_evaluated
   (`lib/agent_runtime/benchmarks/runner.rb:69-76`), potentially losing the
   successful solution. Agree where generation status lives for that path.
4. **Identity scope.** Specify evaluator source/version, timeout and config versus
   scientific four-binding identity. Changing solver/model does not necessarily
   change mathematical correctness, but changes run provenance. Specify whether
   instruction/public tests are normative specification or generation-only data.
5. **Missing redundant storage.** Repository `Store#value` verifies materialized
   tree content, not necessarily existence/integrity of the separate manifest
   object. Decide whether evidence completeness requires both or permits verified
   reconstruction; never silently accept mismatched tree/manifest.
6. **Protocol robustness.** Specify duplicate markers, allowed extra keys,
   structured error fields and whether malformed runner hashes are errors or
   exceptions. Current JSON parser rescue handles parse errors, not every
   well-formed non-object value. Preserve fail-closed intent without demanding
   implementation-shaped rescue logic.
7. **Failure ownership.** Unexpected candidate exceptions currently cause the
   owned demo grader to exit 2 and therefore not_evaluated. Do not relabel these
   as assertion failure without an explicit procedure-level contract.
