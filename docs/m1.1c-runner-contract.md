# M1.1c audited runner/report integration proposal

Status: proposed interface; production changes require parent freeze approval.
This document does not define grading policy or authorize an official score.

## Existing integration (reuse, do not fork)

- `ExperimentRunner#grade` already stores the bound grading request, complete
  adapter result in `grading_attempts[].raw`, normalized result in
  `grading_attempts[].result`, and execution status independently of verdict.
- The runner checks finite scores and positive, integer, score-consistent counts.
  Do not weaken that check or derive a denominator from the score.
- `Store#save_report` persists the report envelope. JSON reports retain cells and
  attempts without a schema migration. CSV and Markdown use `Reports::COLUMNS`.
- Failed regrades append their attempt and a `regrade_failed` transition while
  restoring active result fields. The original submission and request bindings
  remain authoritative; graders own protocol acceptance and score semantics.

## Proposed adapter-to-runner boundary

An accepted scoped successful adapter result may additionally return `protocol`
and `quality_basis`, alongside existing `score`, `verdict`, `passed`, `total`, and
`evidence`. Protocol and basis values are opaque grader-owned strings; agreement
on their exact literals is recorded below. The runner
must not label an untrusted diagnostic as audited or invent either field.

Frozen protocol is `nl2repo-audited-v2`. `quality_basis` is
`validated_quality_result` or `candidate_collection_failure`. Quality-bearing
results require `trust: audited` and `trust_scope: benign_ordinary_submissions`,
not an `authenticated` flag. Existing `passed`/`total` are numerator/denominator
aliases; evidence additionally retains `expected`, `collected`, `executed`,
`failed` and `skipped` counts as defined by the scoring contract. The explicit
scoped trust model replaces the universal authentication gate for this version
only; it does not change historical claims. Preserve that scope in reports.

Minimal production delta after approval:

1. Promote `protocol` and `quality_basis` to active cells together with existing
   verdict/count fields. Absent values remain nil, including after a successful
   replacement of an older result; no stale identity may survive replacement.
2. Include both fields in the active snapshot/reset/rollback logic. A failed
   regrade must preserve score, verdict, counts, protocol, basis, active error,
   execution status, lifecycle status, and active grading duration. Its raw
   result/error and elapsed duration remain visible in the appended attempt.
3. Add `protocol`, `quality_basis`, `passed`, and `total` to `Reports::COLUMNS`.
   Keep `grading_attempts` in every format, preserving raw evidence rather than
   projecting away its request/provenance/artifact bindings. Nested structures
   should be JSON serialized in CSV and Markdown (with Markdown escaping).
4. Retain complete-task-repetition macro scoring and existing
   `evaluation_completion` and `arms[].pooled_counts.coverage`. Count coverage is
   the number of valid cells with known counts, not the number of tasks/tests.
   Suggested additive identity coverage is `arms[].protocol_counts` and
   `arms[].quality_basis_counts` (known nonempty string values only), with
   `protocol_known_cells` and `quality_basis_known_cells`. These names are proposed,
   not frozen. Show coverage in Markdown; JSON already includes summary data.
5. Preserve explicit grader-supplied `expected`, `collected`, `executed`, `passed`,
   `failed`, and `skipped` counts in active results and all report formats. Retain
   existing `total` compatibility without inventing a second passed count or
   assuming total means expected/collected/executed; the grader freezes that
   meaning. Missing fields remain nil. Include every promoted count in rollback.
6. Partition aggregate arms by `(solver_id, model, protocol, quality_basis)` so
   v1/v2 or different quality bases cannot blend macro scores or pooled counts.
   Unknown identity is its own partition. Keep repetition completeness checks
   within each partition; do not combine split repetitions across protocols.

Frozen field names: `protocol` (not `protocol_identity`) and `quality_basis`
(not `score_basis`). E owns changes to existing `experiment_runner.rb` and
`reports.rb` only after freeze; D owns adapter translation and grading owners
define count semantics. Until freeze, changes are limited to this proposal and
the initial tests.

## Missingness and interpretation

- An unavailable/error/timeout/cancelled evaluation is not a failed test suite:
  score, verdict, and unavailable counts are unknown, not zero.
- A successful evaluation with zero passing tests is a measured zero. Preserve
  its positive denominator and failing verdict; it contributes to valid-cell
  and count coverage.
- Missing count evidence yields null pooled passed/total and zero count coverage.
  Existing CSV blank fields mean missing; JSON/Markdown use null. Never output
   an invented `0/0`, audited label, quality basis, usage, or cost.
- Identity coverage describes observed cells; it is not a license to pool
  incompatible score bases or to claim official/scientific capability evidence.
  Mixed protocol/basis arms must stay visibly distinguishable.

## Initial test boundary

`test/benchmark/nl2repo_audited_runner_test.rb` exercises the real generic runner,
Store persistence/reload, and report rendering using the built-in offline
fixture adapter with scripted grader results. It is transport/representation
contract coverage, not proof that NL2Repo accepts a protocol. No providers,
downloads, containers, alternate runner, or grading-policy implementation are
needed. Promotion/rendering expectations are intentionally red until the parent
authorizes and implements the production delta; raw persistence, failed-regrade
rollback, measured zero, and unknown-count coverage guard existing behavior.
