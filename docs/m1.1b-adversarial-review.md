## Native diagnostic evidence and cleanup challenge

Separately from the stub tests above, the team ran the pinned retrying image locally as an explicitly untrusted diagnostic. The image inventory contained `setup.py`, `requirements.txt`, and `test_retrying.py`, but no `retrying.py`: baseline and empty candidate collected zero tests with missing-module errors; an incomplete candidate collected 23 tests and yielded 22 failures and one pass. These observations do not establish that original-source retention, collection isolation, denominator integrity, or official scoring is protected. The candidate and pytest share the diagnostic environment; printed counts and exit values are not independent authority. Image substitute remains untested against the native run; the transport's pinned digest is not an adversarial substitute test.

`M11bDiagnosticCleanupTest#test_cleanup_failure_is_reported` initially exposed a silently discarded failed `docker rm --force`; the current implementation reports the injected failure and this test passes. Cleanup remains best effort: reporting failure does not remove a leaked container. No real container was deliberately leaked. `M11bDiagnosticAuthorityTest#test_spoofed_diagnostic_fields_do_not_become_protocol_score` injects score 1.0, pass, success and official trust in diagnostic observations and checks the adapter protocol remains unscored, unavailable and untrusted; it does not test native grading authority.
