# M1.2b independent adversarial review

## Phase 1 — architecture risks and acceptance gates

Status: **pre-implementation assessment, not approval**. No provider calls were made. The authorized pilot is limited to OmniRoute `cx/gpt-6-luna-low`, retrying, without numerical token/request/run/monetary limits. Timeouts and concurrency controls remain mandatory; model/provider fallback is prohibited. Absence of numerical limits does not authorize bypassing admission, identity, expiry, concurrency, or evidence requirements. Directory separation is not a sandbox; trusted Ruby code and external tooling remain inside the trust boundary.

Highest-risk transition: the existing `lib/agent_runtime/execution/budget.rb` unconditionally denies `real_provider`, and `lib/agent_runtime/adapters/open_code_cli.rb` validates fixture identity before any dispatch. Enabling live execution must preserve both fail-closed properties for every other route and not silently fall through the legacy fixture path. The existing callback-shaped authorization is not itself a single-use capability: authorization verification, expiry, exact route/model/executable binding and consumption need an atomic admission boundary, including concurrent calls and retry attempts. Authorization alone cannot establish the actual provider model or prove that no implicit child/title/compaction requests occurred.

Required safety properties to review in delivered contracts and code:

- Authorization must be explicit and type-checked at its boundary, scoped to the experiment/run/attempt and exact provider/model/route, time-limited, replay-resistant, and fail closed on missing hook, stale grant, malformed data and independently constructed grants. Retrying requires a distinct admission and no concurrent duplicate dispatch. Denied decisions must not launch or mutate a workspace.
- Invoke the selected exact model with fallback disabled in the actual effective CLI/provider configuration, not merely an audit label. Account for all potentially billable auxiliary, child, retry, title and compaction paths, or demonstrate they are disabled; do not claim full coverage where the tool cannot expose them. Never manufacture an observed model from the requested profile.
- Track actual versus unknown usage, deduplicate only genuinely identical scoped observations, retain conflicting records, provenance and cache components, and never substitute zero or turn estimates into actual charges. No numeric spending cap is promised. Preserve timeout/cancellation precedence and avoid retrying ambiguous post-dispatch failures as if launch definitely failed.
- Bind evidence to the actual submitted repository, specification, procedure and environment, including the effective frozen manifest, and distinguish observed from requested data. Validate resulting artifacts before success; no hidden procedure or test-only material enters a solver workspace. Protect credentials and avoid storing sensitive raw configuration. Cleanup failures must remain visible and cannot be relabeled successful.
- Deterministic offline tests must exercise the actual production boundary with controlled fake processes and injected clocks, not call a provider. Negative cases must assert dispatch count, not just returned status, and include concurrent races and side effects. Redaction and persisted reports need separate assertions.

## Contract review — initial B/D/E and parent proposal

The concrete authorization type is a programming boundary, not cryptographic proof of consent: this is trusted local Ruby, not a hostile-code sandbox. Require a concrete scoped `LiveAuthorization`, validated at the production admission boundary, rather than an arbitrary callback or self-asserted profile; the trusted operator/runner owns its creation. A persisted preflight decision and a live manifest are configuration/evidence, not independently sufficient launch authority.

**Blocking integration conditions:**

1. B's proposed authorization scope covers the manifest digest, task, solver, provider, endpoint, route, model and mode, but does not by itself bind a particular run/attempt, workspace, or executable and is reusable. The shared `Coordinator` must enforce the existing attempt-key single-admission invariant atomically across all adapters for the same live run; each distinct retry uses its own attempt key. B/D/parent must agree which concrete object owns one coordinator for the run, and the adapter must not silently create a new ledger per invocation. D's executable/workspace binding needs independently checked actual values, not reconstructed from authorization evidence. Expiry must be checked at launch, not just at an earlier manifest preflight. No global run quota is required.
2. `ExperimentRunner.run(manifest:, live_grant:)` must validate the actual frozen manifest digest and the exact one-cell task/solver/profile against the grant and actual effective launch settings before any subprocess. `regrade` may accept a live manifest without a grant only if the entire path is provably offline and cannot instantiate/invoke a solver or provider; use a test with a launch-raising spy, not just a successful regrade. Configuration or evidence supplied by callers must never be treated as an observed launch/model.
3. A no-fallback claim needs source-verified effective OpenCode configuration and a runtime mismatch check when native observed model/provider is present; unavailable observed identity must remain unknown, not be represented as a match or as proof of no fallback. A synthetic test for mismatch and a missing-identity control are necessary. The reporting proposal correctly distinguishes native observations from upstream attestation.
4. D's process environment clearing must match actual `ProcessRunner` inheritance semantics, including ambient values not known by name; enumerating a fixed set of nil keys alone cannot guarantee an allowlist. Project/ancestor config discovery and plugins need source-backed controls; private HOME is insufficient by itself. Redaction tests must include exceptions, logs, stored preflight and reports.
5. E's unknown coverage is honest but cannot itself establish the D contract's disablement of title/compaction/children/retries. Those paths must be disabled in verified effective configuration, or the contract must explicitly acknowledge the exposure and avoid asserting their absence. Neither incomplete accounting nor a local timeout is a monetary limit.
6. Ensure test coverage targets actual composition, not only individual fake grant/adapter units: mutate manifest after preflight; use wrong/expired authorization; race duplicate attempt admissions; force denied dispatch; cause cleanup and artifact collection failures; assert process call counts and persisted evidence. A frozen manifest must be recursively immutable or its digest must be revalidated against actual content immediately before launch.

The proposed one selected retrying/single-agent cell and separately identified justified repeats are consistent with the stated amendment. A finite timeout and concurrency of one are operational controls, not a request/run/token/monetary quota. These are contract observations pending delivered code and controlled tests, not demonstrated implementation defects.

## Reviewer verdict — conditional, not launch approval

On the offline snapshot reviewed, the concrete unapproved-dispatch paths exercised by the recording-runner tests did not dispatch: missing or spoofed authorization and coordinator denial were blocked, and the duplicated-attempt boundary test recorded one dispatch. The surviving #1 and #8 mutations reflect redundant defenses in these probes, not proof that the removed guards are independently tested. This is not an exhaustive security proof: local trusted Ruby can construct or alter grants, the executable and dependencies operate within the local trust boundary, and there is no per-HTTP hook. Neither a class check nor an editable grant is cryptographic consent.

A narrowly scoped uncapped pilot is **conditionally reasonable only after the pending C isolation work is delivered and independently verified**, including effective child environment/configuration, no unauthorized models or fallback, timeout and concurrency enforcement, credential containment, and offline tests of failure cases. No approval is given for provider dispatch before that review. The financial exposure is explicitly not hard-bounded; timeouts and concurrency limit duration and simultaneity, not total provider charges, requests, or tokens. No live provider behavior has been observed or validated here. The 21/2/1 result above must not be represented as all 24 mutations killed.
