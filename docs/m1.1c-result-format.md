# M1.1c proposed audited pytest result contract

Status: frozen interface/schema including the collection-failure amendment;
not authority to promote a score. This contract deliberately does not
use stdout summaries or JUnit testcase names as test identity.

## Ruby boundary

```ruby
AgentRuntime::Benchmarks::AuditedResults.parse(
  bytes:, expected_nodeids:, expected_binding:, process:
)
```

Returns a JSON-compatible hash. Valid evidence has `status: "valid"`, `tests`
(nodeid-keyed derived outcomes), and `counts` (all six outcome keys, including
zeroes), plus integer `executed` counting identities with a validated `call`
phase. Setup failures/skips without call reports do not increment `executed`;
this cannot be inferred solely from terminal outcome. Invalid evidence has
`status: "invalid"` and a nonempty `reason`, but
no `tests` or `counts`. Invalid input does not raise or yield a partial score.
The result contains no score, pass verdict, or authority promotion.

Parent-frozen outer protocol is `nl2repo-audited-v2`, independent of this wire
schema version. Promotion, not parsing, assigns `quality_basis` as
`validated_quality_result` or `candidate_collection_failure`. A quality-bearing
outer result requires `trust: audited` and `trust_scope: benign_ordinary_submissions`,
never an `authenticated` flag. The benign trust model replaces the universal
authentication gate for this protocol only, not historical claims. Existing outer
`passed`/`total` alias numerator/denominator; evidence includes `expected`,
`collected`, `executed`, `failed` and `skipped` with the scoring contract's meanings.
Structured parsing does not establish adversarial authenticity.

Collection-failure amendment: `status: "collection_failure"`
is a third, scoreless result with `collection_errors`, explicit `collected`
(the validated actual collection array, including an empty array), and no
`tests` or `counts`.
Its errors carry raw structured metadata, not a candidate-failure verdict:

```json
{"nodeid":"test_retrying.py", "exception": {
  "type":"ModuleNotFoundError", "module":"retrying", "message":"No module named 'retrying'",
  "frames":[{"path":"/candidate/test_retrying.py", "lineno":7, "name":"<module>"}]
}}
```

The helper captures actual collection `call.excinfo` through the
`pytest_exception_interact(node, call, report)` hook for failed collection
reports, not a parsed longrepr. Missing exception metadata fails closed. `module` is
the exception's `.name` for ModuleNotFoundError, otherwise null. Each frame is
structured traceback metadata. D's policy must distinguish missing candidate
modules from missing grading dependencies using independent task controls;
the parser must not classify arbitrary ModuleNotFoundError as candidate failure.
Collection errors permit pytest exit 1 (continue-on-collection-errors) or 2
(collection interruption), matched to the actual process with status failure.
The binding, encoding, size, schema, and termination checks still apply. Any
collected items and test reports must remain unique subsets of the independent
allowlist; incompleteness is allowed only on this branch. The branch discards
all partial test outcomes rather than exposing partial counts. The successful
collection rules below apply to the `valid` branch, not this amendment.

`expected_nodeids` and `expected_binding` come from independently verified task
controls, never from the candidate or this document. Binding is compared exactly
and must include submission, specification, procedure, environment and collector
identities in the caller's agreed representation. The parser does not authenticate
that representation; the runner and evidence gate own provenance.

## Wire version 1

One UTF-8 JSON object, maximum 4 MiB, with no duplicate JSON object keys, trailing
bytes, or unknown fields. A terminal newline is allowed. Required fields:

```json
{
  "schema": "agru.pytest-results.v1",
  "pytest_version": "8.4.1",
  "binding": {"submission_digest": "..."},
  "collected": ["test_retrying.py::TestRetrying::test_stop"],
  "collection_errors": [],
  "tests": [{
    "nodeid": "test_retrying.py::TestRetrying::test_stop",
    "reports": [
      {"when": "setup", "outcome": "passed"},
      {"when": "call", "outcome": "passed"},
      {"when": "teardown", "outcome": "passed"}
    ]
  }],
  "exit_code": 0,
  "finished": true
}
```

Object field order and test/collection order are immaterial. Nodeid strings are
the exact `item.nodeid` emitted by pinned pytest, including parameter suffixes;
do not reconstruct them from classname/name or normalize punctuation. The
independent allowlist and collection must each be nonempty and unique. Their
sets must match exactly. Each collected nodeid must have exactly one test entry;
unknown, missing, duplicated, or deselected identities invalidate the evidence.

Reports have only `when`, `outcome`, and optional nonempty string `wasxfail`.
`when` is setup/call/teardown and `outcome` is passed/failed/skipped. Reports are
in phase order with exactly one setup and teardown. A passed setup requires a
call report. A failed/skipped setup prohibits a call report. Duplicate phases,
retries, reruns, interruptions and incomplete reports are not accepted on the
successful-collection branch. Collection errors use the separate scoreless
branch above. Teardown may fail even after a passing call: this is an error,
not a passing test.

Derived outcomes (each identity counts exactly once):

* failed setup/teardown => `error` (takes precedence over call outcome);
* skipped setup/teardown => `xfailed` with `wasxfail`, otherwise `skipped`;
* failed call => `failed`;
* skipped call => `xfailed` with `wasxfail`, otherwise `skipped`;
* passed call with `wasxfail` => `xpassed` (not an ordinary pass);
* otherwise => `passed`.

`wasxfail` is valid only on skipped reports or passed call reports. Pytest strict
XPASS is a failed call and remains `failed`; do not parse its human-readable
longrepr to invent an xpass flag. Non-strict XPASS is `xpassed`, consistent with
pytest exit zero, and never contributes to ordinary passed count. XFAIL and
SKIP are not failed executions and never count as ordinary passes.

For successful collection only exit codes 0 and 1 are accepted. Exit 1 is required iff at least one derived
failed/error outcome exists; otherwise exit 0 is required. The wire exit code
must equal the actual process exit code. Process status must be `success` for 0
or `failure` for 1. Timeout/cancelled/unknown status, stdout/stderr truncation,
signals, missing termination marker, invalid JSON/encoding, or mismatch reject
the complete result, even if some reports passed. Process stdout text is not
examined for pass/fail counts. The runner must separately propagate structured
artifact truncation/size errors; lack of stdout truncation does not authenticate
an artifact.

## Pinned collector design

Implemented helper entrypoint:

```sh
python /trusted/nl2repo_audited_collector.py \
  --binding /trusted/binding.json --output /tmp/results/report.json -- \
  --rootdir /tmp/private /tmp/private/test_retrying.py \
  -p no:cacheprovider --confcutdir=/tmp/private -c /dev/null
```

The output directory must already exist. The launcher sets candidate cwd,
candidate-only `PYTHONPATH`, and `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`. Arguments
after `--` are passed unchanged to pytest. The helper returns pytest's actual
exit code; writing/collector failures instead abort without a valid artifact.
The actual pinned image was checked offline: Python 3.10.11 / pytest 8.4.1.

Use a tiny trusted Python plugin with an immutable collector digest,
loaded explicitly with plugin autoload disabled and a controlled pytest command.
Record `pytest_collection_finish` item nodeids, `pytest_collectreport` errors,
and `pytest_runtest_logreport` phase, outcome and optional `wasxfail`. Finalize
after `pytest.main` returns, when pytest's final exit code is settled. Write one
JSON document to a dedicated bounded file via temporary-file + atomic rename;
do not multiplex candidate stdout with the protocol. Collector version and
plugin bytes belong in the pinned grading image/procedure identity.

The trusted launcher must check pytest's real return code against the document
and fail closed when plugin teardown or transport fails. The runner owns binding
and retrieves the artifact before container cleanup. JUnit may be retained as
diagnostics, not identity evidence: parametrized tests and repeated names can
collide under lossy classname/name mappings.

This preserves pytest report semantics, not a hostile-code sandbox. Programs
and pytest tests execute trusted Python; pinned plugin alone cannot prevent
arbitrary Python from forging files or monkeypatching pytest. Provenance,
submission isolation and policy are separate runner/gate obligations.

## Offline behavioral verification

`mise exec -- ruby script/m11c_collector_checks.rb --allow-local-grading` is an
explicit opt-in local Docker check, not part of the default offline test suite.
It invokes the actual parent transport against a scratch genuine reference
candidate augmented with a raising same-named `test_retrying.py`, a failing
extra test, raising `conftest.py`, collection-changing `pytest.ini`, and raising
`setup.py`. On the pinned image the structured validator accepted exactly the
23 pinned canonical nodeids, all passed, with process exit 0. Candidate tests,
configuration, hooks, and preparation did not affect that controlled execution.
This is filename/config isolation evidence, not authentication against hostile
Python or a security-sandbox claim.

The first real run exposed that `/tmp` tmpfs artifacts disappear after container
termination, so post-exit `docker cp` could not retrieve the report. Parent
transport now writes to a fresh per-attempt writable `/results` host bind and
copies `/results/report.json` after exit. The repeated check validated the
retrieved structured artifact; no stdout summary was used for its result.
