# M1.2c-S1 sandbox comparison protocol — draft

Status: proposed protocol, not an implemented or frozen environment. No live
dispatch is authorized by this document. Production changes and shared API
changes require separate implementation and coordination under `CONTRACTS.md`.

Current integration limitation: the runner accepts no repository export because
writer quiescence for quota-tmpfs capture is unsupported. Otherwise-successful
runs become blocked with
`writer_quiescence_unsupported: tmpfs archive collected before container pause`;
diagnostic archives are discarded. Passing mock and fail-closed controls cannot
satisfy submission, installed three-arm acceptance or final identity freeze.

## Scientific question and historical quarantine

The intended question is whether architecture changes outcomes under the same
tested execution boundary, task, requested model route, and operational budget.
An initial smoke is a feasibility gate, not evidence of architecture superiority.

Preserve `docs/m1.2c-smoke-results.md` unchanged: historical single-agent executed
successfully and scored **14/23** (evaluation verdict `fail`); fixed workflow
timed out with observed host-context contamination and original null score;
its partial snapshot scored **13/23** only as supplemental evaluation; DSL was
**not dispatched**. These are not a valid three-arm comparison, controls, or
replicates of the new environment. Do not relabel the fixed timeout as completion,
pool supplemental grading with completed cells, or rerun historical failures for
a better score. Historical M1.2b 14/23 is separate as well.

The prior file-tool denial did not constrain shell `cat`. Fresh HOME, directory
separation, ancestor-loading canaries, and file permission policy alone do not
establish a sandbox. Programs remain trusted Ruby; do not imply that directory
separation or a container alone proves security against arbitrary hostile code.

## Shared boundary, distinct treatments

All three arms SHALL use the same implemented and tested sandbox backend, image,
mount/access policy, network policy, tool capabilities, task inputs, resource
limits and independent grader conditions. Solver processes, subprocesses and
local candidate-test commands must remain inside that boundary. Provider access
must be limited to the declared route and required transport, not general host
or network access. Hidden procedures, reference solutions, other runs, host
worktrees, credentials other than explicitly scoped provider transport, and
grader state must not become solver-readable through mounts, tools or shell.

This does not flatten architecture: single-agent retains one solver invocation;
fixed retains its imperative planner/coder/reviewer handoff; DSL retains compiler
and runtime orchestration, explicit dependencies, typed intermediate artifacts,
and its separate verification invocation. Preserve role prompts, handoff
artifacts, invocation counts and stopping behavior as treatment identities.
An independent invocation is not an independent model or a security boundary.
Grading occurs outside solver visibility and binds the actual submitted snapshot.

## Candidate identity and freeze gate

`sandbox/environment.example.json` is a draft identity template, not a validated
JSON Schema or frozen record. Every null has explicit missingness and reason.
`pending` means required evidence remains to be supplied; `unknown` means the
observation is unavailable; `not_applicable` requires a justification. Required
freeze fields cannot remain pending or null. Served-model attestation may remain
unknown if clearly disclosed; it must never be inferred from the requested route.
The parent implementation must supply actual image IDs and test artifacts.

Create a machine-readable candidate identity before acceptance testing; it is
mutable and explicitly **unfrozen** until implementation and tests pass. A final
canonical identity and digest must bind at least:

| Component | Required binding |
|---|---|
| Runtime | Full repository commit, dirty-state rejection, compiler/runtime and adapter implementation identities |
| Sandbox | Backend/version, effective configuration, isolation mode, mounts and access modes, environment allowlist, network/egress rules, subprocess and cleanup behavior |
| Image | Immutable image digest, platform/architecture, language and dependency/tool versions; no mutable-tag-only identity |
| OpenCode | Actual executable/version/digest, effective configuration, instruction/plugin loading and session policy |
| Tools | Exact effective tool policy and capabilities, file/shell/test restrictions, approval behavior and escape handling |
| Catalog and route | Catalog snapshot/digest, selected entry, base model, reasoning effort, exact requested wire route and fallback policy |
| Task | Public specification, initial repository and task asset digests |
| Grader | Procedure/test identities, grader implementation and environment, submission digest and evaluation protocol/trust scope |
| Architecture | Arm name, solver/program definitions, prompts, handoff schemas, invocation/termination semantics and dispatch order |
| Resources | CPU, memory, process/storage limits, solver deadline, per-invocation limits, concurrency and any enforced request/token/spend controls |

Do not include secrets in identity artifacts. Record secret injection mechanism
and scope without values. Missing components or ineffective policy prevent freeze.
Keep requested/catalog identity separate from CLI-observed, gateway-resolved and
served-attested identity; unknowns remain unknown. A requested route is not proof
of the serving model. Store evidence must bind repository, specification,
procedure and environment as required by `CONTRACTS.md`.

No final identity may be declared merely because this draft or a manifest exists.
Freeze only after the actual installed runtime and all arms pass offline boundary
and parity acceptance tests. Any material runtime, image, policy, task, grader,
route, architecture or resource change invalidates that freeze and needs renewed
acceptance evidence and a new identity. Never backfill the new identity onto old runs.

## Offline acceptance matrix (required before a live proposal)

Tests must use fake/loopback providers without credentials or paid calls, exercise
the installed executable and effective production sandbox configuration, and
retain expected versus observed results plus configuration identities.

| Gate | Required evidence |
|---|---|
| Positive operation | Each arm can read its public task, edit its candidate repository, hand off intended artifacts and run permitted local candidate tests |
| External access | Explicit absolute/relative reads, traversal, symlink/alias paths and shell/subprocess reads cannot expose host, sibling-run, reference or private-grader canaries |
| Write/escape | External writes, mount escape and subprocess attempts are denied; legitimate candidate writes survive submission capture |
| Ambient context | Ancestor instructions, host config/plugins, old sessions and environment secrets are absent from solver context |
| Network | Undeclared egress is denied, declared fake provider transport works, and denial is not silently bypassed by another tool |
| Lifecycle/resources | Timeout, cancellation, resource exhaustion and cleanup preserve execution status, partial evidence and bounded descendants |
| Arm parity | All three effective environments have identical shared-boundary fields; only registered architecture fields differ |
| Evidence integrity | Submitted repository and grader inputs match recorded digests; identity drift blocks dispatch; missing evidence cannot be treated as a passing gate |

Test one effective policy end-to-end rather than composing unrelated primitive
probe successes into a sandbox claim. Record limitations and the tested threat
scope; a passing canary suite is evidence within that scope, not universal proof.

### Selected transport and reconstruction gate

The selected S1 design uses solver `network=none`, an agent-local HTTP bridge,
and a narrowly scoped UNIX socket relay volume (selected C transport). The relay
holds provider credentials outside solver visibility and enforces route/API
allowlisting. This describes the selected design, not a verified implementation.
Record bridge and relay identities, socket permissions, exact mounted volume,
allowed endpoints/methods, request validation, credential handling and lifecycle
in effective configuration evidence. No general network interface or provider
credential is granted to the agent. Test bypass attempts and cleanup explicitly.

The offline reconstruction script checks an explicit manifest of
**24 unique required categories**, exact expected IDs, duplicates, missing/extra
IDs and per-category expected/observed outcomes against digested artifacts. A
count of 24 alone is insufficient. Missing, skipped, unknown, malformed or
contradictory evidence cannot yield PASS. Keep test-process exit status distinct
from acceptance verdict; a successful JSON parse is not acceptance. Do not create
a nominal passing reconstruction without actual artifacts.

Stable IDs are registered in `sandbox/m12cs1-categories.json` in mission order.
Run `mise exec -- bundle exec ruby script/m12cs1_reconstruct.rb REPORT.json`.
Report schema version 1 contains a `categories` array of objects with `id`,
`status`, and nonempty `artifacts`, each having report-directory-relative `path`
and lowercase SHA-256 `sha256`. Paths must stay within that directory, including
after symlink resolution. The script emits JSON and exits zero only when all 24
IDs occur exactly once, all statuses equal `pass`, and every artifact digest
matches an existing regular file. Other outcomes exit nonzero. It verifies
reported statuses and file integrity, not the truth of artifact claims; parent
review must map actual test evidence to each category. It does not freeze an
environment or authorize dispatch. Synthetic test fixtures are not S1 evidence.

A pending report can be prepared without fabricating results:

```ruby
require "json"
ids = JSON.parse(File.read("sandbox/m12cs1-categories.json")).fetch("categories")
puts JSON.pretty_generate({"schema_version" => 1, "categories" => ids.map { |id|
  {"id" => id, "status" => "pending", "artifacts" => []}
}})
```

That skeleton intentionally fails reconstruction until actual evidence is mapped.

## Registration, dispatch and reporting

After acceptance, register exact cells, order, immutable identities, resource
budget, stopping rules, missing-result handling and analysis before seeking
explicit live authorization. Previous smoke authorization does not authorize a
new environment or larger pilot. No fallback, whole-cell retry, quality-driven
rerun or best-attempt selection unless separately preregistered and authorized.
A deadline is not a hard spending cap; report actual enforcement and unbounded
financial exposure where applicable. Baseline Serena remains disabled.

Retain every scheduled cell, blocked launch, error, timeout, cancellation,
partial submission and grading failure. Separate execution status from evaluation
verdict, original cell outcome from supplemental snapshot grading, and solver
duration from grader overhead. Report quality only against validated grader
integrity evidence; report incomplete usage/cost as incomplete, never zero.
Boundary contamination or identity drift blocks comparative interpretation and
further dispatch pending review; it does not erase already collected evidence.
One task/cell per arm cannot support a general architecture-effect claim. Any
larger study needs a separately validated task scope, analysis and authorization.
