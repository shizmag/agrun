### Gate2 reviewer amendment (authoritative over the initial proposal below)

The parent approved `normalize(requests:, complete:, pricing: nil)` and
reported-only `Result.cost`, but production implementation is still gated.
These amendments supersede any less strict wording in the original sections:

* Canonical records additionally require `identity_kind` and `identity_scope`.
  Kind is `provider_request` or `root_step_observation`; scope is a nonempty
  caller-assigned invocation/attempt identifier. Identity is the tuple
  `(identity_scope, identity_kind, request_id)`, never bare request ID. Group
  output retains both new fields. Sort by scope, kind, ID, then variants.
* A native root finish identifies a **root step observation**, not a provider
  request. Native mapping uses `root_step_observation`, an attempt scope, and
  `complete: false` because children and whole-invocation coverage are unknown.
  Do not infer provider request identity or completeness from root termination.
* Coverage additionally exposes `identity_kind`: the common kind or `mixed`
  (null for empty input). With root observations, known subtotals mean observed
  root-step subtotals, never whole-invocation totals. Retained groups label the
  evidence scope; downstream reports must retain that qualification.
* `reported_cost` requires `provenance: "provider_reported"` plus independently
  established currency and amount. Absent/other provenance is invalid reported
  cost, stays unknown, and produces `invalid_reported_cost`. Generic callers
  may provide independently evidenced provider charges; native mapping cannot.
* Native `part.cost` is opaque CLI-reported information: it may be a fallback
  model estimate and its currency is not independently established. Native
  canonical `reported_cost` and strict-path `Result.cost` are therefore nil.
  Keep the raw CLI cost separately in adapter-owned logs, not in provider-cost
  fields. A zero native cost is not evidence of a zero provider charge.
* Audit A establishes disjoint native input/output/reasoning/cache.read/
  cache.write buckets. Map both relations as `disjoint` only under that audited
  version contract. Upstream normalizes missing counters to zero: those zeros
  are **CLI-normalized observations**, not proof of provider-reported zeros.
  Root observation kind plus this documented source uncertainty must accompany
  downstream interpretation. The generic helper does not invent native mapping.
* All-role/retry aggregation tests use caller-scoped canonical observations;
  they do not prove native child-role capture. Repeated attempts must remain
  distinct even when their native part IDs coincide.

The test matrix and `test/execution/usage_test.rb` cover these amendments before
implementation. Parent and reviewer must approve the amended contract/tests
before any production file is created.

## Exact proposed shared Ruby interface

```ruby
module AgentRuntime
  module Execution
    module Usage
      def self.normalize(requests:, complete:, pricing: nil)
        # => {"usage" => Hash, "cost" => Numeric | nil}
      end
    end
  end
end
```

Pure, deterministic, nonmutating, JSON-compatible result. No I/O, clock, network,
global price lookup, or environment-dependent defaults. `requests` is an Array
of the canonical request hashes below, **not raw CLI events**. `complete` is an
explicit Boolean supplied by the protocol adapter: true requires evidence the
invocation's request stream is complete, not just a zero process exit status.
An empty array never establishes a free call: normalized totals/cost remain nil.
Unsupported canonical shape or price schema raises `ArgumentError`. Invalid
observed numbers, identity gaps, or contradictory observations become explicit
issues/unknown values, rather than raising away execution evidence. The adapter
owns malformed-protocol handling and execution status; this helper never chooses
execution success, retry safety, or an evaluation verdict.

The calling adapter assigns `result.usage = accounting.fetch("usage")` and
`result.cost = accounting.fetch("cost")`. Parent owns adapter wiring. The later
helper file requires its own stdlib dependencies and must be usable directly
with `require_relative`; shared entrypoint changes require parent coordination.

## Canonical request schema (version 1)

All keys below are present; absent evidence is JSON null, not an omitted zero.
Token counts are nonnegative Ruby Integers; Booleans, floats, strings, negative
values, NaN and infinities are not valid token counts.
Replace invalid observed scalar token/cost values with null in the returned
canonical observations and record the corresponding issue; never serialize
non-finite numbers. Compare duplicates/conflicts after this sanitation while
retaining validation issues, so an invalid value cannot become known evidence.
Raw invalid values remain available only in adapter-owned protocol logs.

```json
{
  "request_id": "stable-invocation-scoped-provider-request-or-audited-part-id",
  "identity_kind": "provider_request",
  "identity_scope": "fixture-invocation/attempt-1",
  "provider": "provider-id-or-null",
  "model": "observed-model-id-or-null",
  "tokens": {
    "input": 100,
    "output": 20,
    "reasoning": null,
    "cache_read": 40,
    "cache_write": 10
  },
  "input_cache_relation": "disjoint",
  "output_reasoning_relation": "unknown",
  "reported_cost": {"amount": "0.0123", "currency": "USD", "provenance": "provider_reported"}
}
```

`provider`, `model`, and `request_id` are nonempty strings or null; example null
placeholders above must be actual null values, not literal `"...-or-null"`.
Relations are `"disjoint"`, `"subset"`, or `"unknown"`. `reported_cost` is null
or a nonnegative finite decimal amount string plus nonempty currency string.
Currency is explicit audited evidence; do not infer USD from an unlabelled native
number until the protocol audit establishes that unit. Requested model alone
does not establish observed model identity for pricing.

Input is the audited native input counter; its cache relationship is separately
declared. Output is likewise the audited native output counter. Reasoning is
not automatically added to output. No provider-specific field names or inference
belong in this helper. The adapter retains raw events in existing logs, not a
second copy of potentially sensitive full messages inside usage.

### Identity, repeats, and conflicts

Deduplicate only by stable request identity **within this invocation**. The
adapter must scope a native ID with session/message identity if necessary;
session ID, model, equal counts, event position, and finish reason alone are not
request identities. Distinct requests with equal counts both count. IDs do not
deduplicate across runtime attempts or benchmark cells.

* Identical canonical records for one ID count once (Hash key order irrelevant).
* Same ID with any differing canonical evidence is a conflict. Do not sum,
  overwrite, choose a maximum, merge missing fields, or let event order decide.
  Retain all distinct variants; exclude that identity from numeric aggregation
  and estimates; mark accounting incomplete with `conflicting_request`.
* A null identity is `unidentified_request`: retain the observation but exclude
  it from aggregation because replay versus distinct request is unknowable.
* Sort identified groups lexically by ID and variants by canonical JSON;
  unidentified observations retain input order. Repeated identical observations
  increase the duplicate count, not the unique-request count.

### Normalized output

`normalize` returns `{"usage": envelope, "cost": number_or_null}`. The envelope
has exactly these keys:

* `schema_version`: `1`.
* `requests`: groups `{"request_id": String | nil, "observations": [canonical
  request, ...]}`. One nonconflicting group has one observation. Identical
  repeats are collapsed; unidentified records each have their own group.
* `coverage`: `{"stream_complete": Boolean, "complete": Boolean,
  "observations": Integer, "identified_requests": Integer,
  "accepted_requests": Integer, "duplicate_observations": Integer,
  "conflicting_requests": Integer, "unidentified_observations": Integer}`.
  `complete` means stream complete, nonempty, no conflicts/unidentified records,
  and all five token fields valid/known for all requests. Relations can remain
  unknown even when raw counter coverage is complete; pricing has extra checks.
* `tokens`: each of the five token keys maps to
  `{"total": Integer | nil, "known_subtotal": Integer | nil,
  "known_requests": Integer}`. A total exists only when the stream is complete,
  identities unambiguous, nonempty, and that field is valid for every request.
  A known subtotal excludes invalid/missing/conflicting/unidentified evidence.
  No known values means null, not zero. Different requests may have different
  relations: raw counter sums are not a combined billable-token total.
* `reported_cost`: `{"total": String | nil, "known_subtotal": String | nil,
  "currency": String | nil, "known_requests": Integer}`. Same completeness
  rule as field totals, independently of missing token counters. Mixed known
  currencies yield null total/subtotal/currency and a `mixed_currency` issue;
  never silently add or convert currencies. Decimal arithmetic is exact.
* `estimate`: null unless explicit pricing was supplied; see below.
* `issues`: stable sorted unique hashes `{"code": String,
  "request_id": String | nil, "field": String | nil}`. Codes:
  `incomplete_stream`, `empty_stream`, `unidentified_request`,
  `conflicting_request`, `invalid_token_count`, `invalid_reported_cost`,
  `mixed_currency`, `unknown_cache_relation`, `unknown_reasoning_relation`,
  `inconsistent_subset`, `pricing_identity_mismatch`, `missing_pricing_evidence`.
  Missing token/cost values are conveyed by coverage, not per-field issue spam.

Legacy returned `cost` is the complete reported decimal total converted to a
finite Float, or nil if unavailable/unrepresentable. The authoritative decimal
is retained in `usage.reported_cost.total`. Explicit reported zero remains 0.0.
An estimate never fills missing reported cost. Reported cost can remain known
even when tokens are unknown, and token evidence can remain known without cost.

## Cache/reasoning normalization and pinned estimates

The helper does not publish a synthetic `total_tokens` counter. For estimating
one request, derive **disjoint billable buckets** only with explicit relations:

* `disjoint` input: uncached input = `input`; read and write are additional.
* `subset` input: uncached input = `input - cache_read - cache_write`.
  Require both cache counters known and their sum <= input. This relation also
  asserts read/write counters are mutually exclusive; an audit unable to prove
  that must supply `unknown`, not `subset`.
* `unknown` input relation: no estimate, even if a provider name seems familiar.
* `disjoint` output: ordinary output = `output`; reasoning is additional.
* `subset` output: ordinary output = `output - reasoning`; require reasoning
  known and <= output. `unknown` output relation prevents an estimate.

Every priced request requires all five valid counters and exact observed
provider/model match. Unknown reasoning/cache counters are not implicitly zero.
An adapter may emit zero only when protocol evidence explicitly establishes it.

`pricing:` is null by default or exactly this versioned JSON-compatible hash:

```json
{
  "schema_version": 1,
  "id": "fixture-provider-model-2026-11-15",
  "provider": "provider-id",
  "model": "observed-model-id",
  "currency": "USD",
  "source": "https://example.invalid/pinned-price-source",
  "effective_date": "2026-11-15",
  "rates_per_million": {
    "input": "2.00", "output": "8.00", "reasoning": "8.00",
    "cache_read": "0.20", "cache_write": "2.50"
  }
}
```

All identity/provenance strings are nonempty; date is a valid ISO date. Rates
are finite nonnegative decimal strings, all five keys required, even for zero
buckets. This is a test fixture, not actual provider pricing. No fetching latest
prices, fuzzy model aliases, provider defaulting, or time-based price selection.
Canonical JSON SHA256 binds the entire supplied table (`IR.digest` equivalent).
Multiple-model invocations cannot use one model's rates for other requests.

The estimate object is exactly `{"kind": "estimate", "amount": String | nil,
"known_subtotal": String | nil, "currency": String,
"known_requests": Integer, "pricing": supplied_table,
"pricing_digest": canonical_sha256}`. Complete `amount` requires complete
identity/stream coverage and all requests priceable. A known subtotal covers
only eligible requests, explicitly not an invocation total. Sum disjoint bucket
counts times their decimal rates, divide by 1,000,000, with no intermediate
rounding. Canonical decimal strings have no exponent or unnecessary trailing
zeros (`"0"` for zero). Changing rates or provenance changes the digest;
historical usage is never repriced automatically. Provider reported cost and
this offline estimate coexist without being presented as interchangeable.
