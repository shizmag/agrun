# M0.1 frozen contract clarifications

These decisions precede implementation corrections. The independent review is
recorded in [m0.1-review.md](m0.1-review.md). New interfaces below are **additive
M0.1 contracts**, not claims that M0 already supplied evidence reuse or replay
safety. Their initially absent implementations are classified accordingly.

## Language and IR

Malformed known IR fields fail with `AgentRuntime::Error`, not incidental Ruby
exceptions. Configurations are JSON objects; DSL symbols normalize to strings,
but arbitrary Ruby objects and collisions introduced by key normalization are
rejected. Ruby syntax errors and duplicate literal Hash keys are not validator
responsibilities. Unknown adapter names remain valid compilation inputs because
the runtime registry is extensible. Program names are nonempty strings; separate
namespaces may share names. Existing closed types and exact type equality remain.
Timeouts are finite positive numbers; retries are integers 0..10. No new rule for
unknown IR keys, orphan `input_types`, or omitted optional fields is inferred.

## Replay and execution

`Result` gains optional `retry_safe`. A retry requires `error == "transport"`,
`retry_safe == true`, remaining budget and no cancellation. This deliberately
tightens transport-only replay: custom executors must explicitly establish safe
repetition. Neither classification nor a new writable workspace proves that an
external side effect is safe to replay. Built-in adapters must not invent safety.
Malformed executor results become retained failed attempts, never successful
dependencies. Partial unreferenced Store objects need not be rolled back.

Mixed terminal-status precedence is not newly prescribed; exact individual
statuses and aggregate non-success are tested. Arbitrary trusted Ruby execution
has a timeout fallback but no safe-preemption guarantee. Custom cancellation is
cooperative; subprocess cleanup is bounded process-group cleanup, not containment
of deliberately detached hostile descendants.

## Evidence identity and verification

`Evaluator#evaluate(task:, repository:, run_id:, timeout: 30, generation: nil)`
accepts canonical stored repository metadata as an explicit producer generation.
Without it, evaluation has explicit `standalone` identity mode and its submitted
snapshot is the generation. A report records `generation`, `identity_mode`, and a
fresh `evaluation_id`. Equal bytes never erase generation identity.

`Evaluator#verify!(report:, task:, repository:, run_id:, timeout: 30,
generation: nil)` returns the report only when its stored evidence matches the
current context, otherwise raises `AgentRuntime::Error`. Submitted mode requires
the expected producer metadata; swapping another same-run, same-bytes generation
is invalid. Standalone mode is explicitly not an implied solver provenance claim.
Standalone verification checks the original stored evaluation snapshot and current
content only; it cannot identify an independently supplied byte-identical path.

`Store#artifact(id)` reads canonical metadata or raises. Reads validate caller
metadata against canonical records, object/tree digests, and referenced provenance
existence. Verification reads rather than repairing missing or corrupted evidence.
An intervening same-content write must also fail closed instead of recreating
historical objects/trees; M0.1 does not introduce content-store recovery.
Malformed references and cyclic provenance are rejected. Every evaluation-owned
evidence record carries the same unique evaluation ID; producer metadata does not.
It checks the authoritative stored evaluation report (excluding its self-reference),
evidence artifact types and identities, evaluation/run associations and current
repository/specification/procedure/environment bindings. Parent input artifacts
may legitimately originate in another run; no blanket same-run ancestry rule.

Specification binding includes instructions and public-test bytes in addition to
the existing specification, dataset revision and base commit. Environment binding
includes evaluator version, evaluator source SHA-256 and normalized Float timeout.
Source identity is captured at class load; a changed or unavailable source file
at evaluation/verification time is rejected rather than binding non-running code.
`evaluator_version:` defaults to the runtime version and supports explicit version
identity. A source digest does not fingerprint transitive behavior; maintainers
must bump the evaluator version for relevant dependency/semantic changes.
Unavailable evaluator source, unreadable public tests, and nonfinite/nonpositive
timeouts fail closed rather than silently omitting a binding.

Historical reports remain inspectable but are not assertions of current validity.
Reuse requires `verify!`; no cache or automatic promotion is introduced. Validation
is point-in-time and does not prevent later filesystem changes (TOCTOU). Canonical
metadata consistency is not cryptographic authentication against a same-user
attacker who can rewrite the database and all evidence. No OS sandbox is claimed.

## Evaluator and adapter protocols

Exactly one captured `AGRU_VERDICT` marker with an object payload and a consistent
exit/verdict pair establishes completed evaluation. Primitive, duplicate, empty or
malformed results are infrastructure errors, not quality failures. Process capture
reports truncation explicitly; truncated evaluator/OpenCode output cannot establish
success. A timeout or cancellation cannot be promoted by a permission event.
`stdout_truncated` and `stderr_truncated` are Boolean process-result fields: exactly
the capture cap is complete; cap-plus-one is truncated. Interruption takes precedence.

Runner preserves generation status when evaluation raises, records evaluation
execution error and `not_evaluated`, and retains generation evidence. No cancellation
API for benchmark Runner, crash recovery, transactional artifact rollback or
hard-kill terminal persistence is added. Read-only SQLite inspection in tests is
allowed where no public attempt-reader exists.
