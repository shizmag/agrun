## Fixture, levels, and oracle discipline

Use a tiny, hand-authored valid DSL/IR pair: text input `issue`; fake executor
`worker`; step `a` consumes `issue`, produces text `answer`; step `b` consumes
`a.answer`, produces text `answer`; emit `b.answer`. Explicitly spell all schema
fields in the independent IR fixture, including `input_types`, limits, configs,
and dependencies. Do not manufacture the expected IR by compiling the subject.
Use fresh deep copies for each mutation. Pair every negative with its nearest
valid control, not just a single global smoke test.

Levels: **D** public DSL compile through a temporary source file; **V** direct
`Compiler.validate!` boundary; **S** `IR.dump`/`IR.digest`; **P** a fresh local
Ruby process. All are offline, deterministic, and credential-independent.
Process tests serialize/compile locally; they do not exercise process-adapter
timeouts, cancellation, shell interpolation, or providers (other ownership).

For established static invalidity require `AgentRuntime::Error` and the semantic
category plus offending identifier/reference where applicable. Do not accept
arbitrary `StandardError`, incidental `NoMethodError`, or mere nonzero exit.
Exact full English messages are not contractual. Diagnostic categories below are
independent expectations; current message fragments are useful evidence, not a
license to bless current behavior. Ambiguity-tagged cases must be resolved with
the parent before turning a proposed category into a normative assertion.

## Parent decisions — pending E challenge review

Parent supplied the following intended semantics after this design was delivered.
They resolve the corresponding proposed expectations below, subject to E review;
no tests are to be written until that review returns.

- Malformed nested IR maps, arrays, references and configuration reject with
  `AgentRuntime::Error`, not incidental `TypeError`/`NoMethodError`. Configuration
  must be a JSON-compatible object; arbitrary Ruby objects are not JSON data.
- Unknown adapter names may compile for an extensible runtime registry. `via`
  must be a nonempty string; add paired valid unknown adapter / empty or
  malformed adapter subcases to A-27. A-06 still concerns missing executor names.
- Program name must be a nonempty string, without additional identifier-pattern
  restrictions. No cross-namespace uniqueness requirement.
- The listed type vocabulary is closed; `text` and `string` are distinct.
- Retries are integers 0..10; timeout must be a finite positive numeric value.
- Dependencies are deduplicated and sorted deterministically. Validate returned
  contents, not Ruby object identity (A-34 revised accordingly).
- Native Ruby syntax errors and duplicate literal Hash keys are outside validator
  scope. No tests should imply that the compiler can recover collapsed keys.

A-11/A-19/A-20/A-22/A-25/A-27/A-34 should use these decisions when E clears
implementation. All scenario statuses remain **untested**. Unused `input_types`
keys, unknown extra IR keys, and any other unaddressed details below remain open;
do not invent additional acceptance criteria.

## Original ambiguity inventory (historical proposals)

1. **Malformed IR/config boundary:** docs promise validated JSON IR but do not
   define every nested shape, executor adapter identifier/registry validation,
   config object requirement, unknown-key policy, or serialization of arbitrary
   trusted Ruby objects. JSON generation alone may coerce objects. Propose explicit
   JSON-compatible object configs and domain errors for malformed shapes; do not
   silently codify current incidental Ruby exceptions. Keep A-25/A-27 unresolved
   until agreement. Missing executor declaration (A-06) is not unknown adapter.
2. **Identity/namespaces:** program name syntax, whitespace, cross-namespace name
   reuse, unused `input_types` keys and direct nonstring IR names are not fully
   specified. Test established identifier positions; do not require global name
   uniqueness across inputs/executors/steps/emits without a decision. A-22's
   nonstring/whitespace cases are pending.
3. **Limits:** positive timeouts/retry bounds are documented, but upper retries
   value 10 and numeric subtype acceptance come from `lib/agent_runtime/ir.rb:41`.
   Confirm 0..10 as intended contract before normative assertions. Nonfinite
   timeouts should not produce valid JSON IR; exact diagnostic stage is unsettled.
4. **Types:** implementation lists `text string integer number boolean json file
   directory repository patch evaluation_report` in `lib/agent_runtime/ir.rb:21`.
   Confirm this closed vocabulary and whether `text`/`string` are strict distinct
   declarations (current exact comparison) rather than semantic aliases. Avoid
   claiming JSON config/application payload schemas are statically validated.
5. **Mutation/order contract:** dependency set union follows the contract; sorted
   needs, in-place validation and declaration-array preservation are current
   normalization/API interpretations. Canonical object-key sorting and significant
   array order are documented; confirm sorted `needs`/object identity rather than
   deriving expected normalization from the implementation under test.
6. **DSL syntax errors and partial declarations:** trusted Ruby is not a parser
   sandbox. Native Ruby `SyntaxError` need not become `AgentRuntime::Error` absent
   an explicit API decision. Reusing one Language instance across files is not a
   promised public workflow. Duplicate literal Hash keys cannot be observed after
   Ruby/JSON parsing; use declaration-level duplicates, never fake a detectable
   duplicate by examining already-collapsed Hashes.
