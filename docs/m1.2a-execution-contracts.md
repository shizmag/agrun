### Observed lifecycle gaps

* `lib/agent_runtime/adapters/process_runner.rb:34-43` records cancellation before
  timeout, sends process-group TERM, then escalates after 0.2 seconds.
* `lib/agent_runtime/runtime.rb:117-120` wraps execution in
  `Timeout.timeout(step["timeout"] + 0.1)`. That deadline can interrupt the
  runner during TERM grace. `lib/agent_runtime/adapters/process_runner.rb:83-84`
  closes pipes in `ensure` but does not kill/reap a still-owned child. This is a
  cleanup race even though ordinary runner timeouts have descendant tests.
* The runner drains both pipes and polls the direct child. EOF alone does not
  prove child exit; direct-child exit alone does not prove descendants have
  closed inherited pipes. Descendants that keep pipes open must remain governed
  by the same deadline and process-group cleanup.
* `lib/agent_runtime/adapters/process_runner.rb:50-60` caps retained bytes per
  stream at 1,048,576, keeps draining, and appends a truncation marker. Therefore
  the returned string may exceed the cap by the marker length; tests must not
  mistakenly require total returned size <= the retained-byte cap.
* `lib/agent_runtime/adapters/process_runner.rb:73-82` turns argument/spawn
  failures into failure hashes. A successfully spawned child interrupted by an
  unexpected exception must still be cleaned up before propagation/translation.

## Proposed lifecycle guarantees

1. **Ownership:** spawn a new process group, retain the owned direct PID/group
   until termination handling is complete, and always reap the direct child.
   Do not signal a group when spawn never succeeded. No PID guessing or global
   process matching is permitted.
2. **Pre-cancel:** an already-cancelled token returns cancelled without spawning.
   Cancellation wins when cancellation and deadline are first observed together.
   Once a terminal cause is latched, do not relabel it during cleanup.
3. **Bounded stop:** cancellation/deadline sends TERM to the owned group, allows
   the existing 0.2-second grace, then sends KILL if necessary. Await direct-child
   reaping and close every pipe on every exit path. Cleanup must also apply when
   Ruby raises `Timeout::Error` or another exception after successful spawn.
4. **Outer watchdog compatibility:** the runtime watchdog must not strand a
   process by interrupting cleanup. Prefer runner-local interruption-safe cleanup
   without changing the shared runtime timeout contract in this scope. Merely
   extending the runtime margin is insufficient proof of cleanup safety.
5. **Output:** retain bounded per-stream prefixes, continue draining overflow to
   prevent pipe deadlock, and preserve independent stdout/stderr truncation flags
   plus aggregate `truncated`. A syntactically valid event prefix plus discarded
   tail is not complete protocol evidence.
6. **Precedence:** successful protocol events cannot override timeout/cancelled;
   malformed/truncated output cannot promote any result to success. Process exit
   success and provider semantic completion are distinct observations.
7. **Limits:** ordinary descendants remaining in the spawned process group are
   covered. Descendants deliberately escaping with `setsid`/another process group
   are not a security-sandbox guarantee. Do not claim arbitrary process-tree
   containment. Reap the direct child; grandchildren may be reaped by their
   parent or the OS, not necessarily this Ruby process.

Implementation detail to approve: exception-safe group termination/reaping must
avoid a second asynchronous timeout aborting cleanup. Keep the protected region
small and bounded; do not mask exceptions across normal execution. Tests need an
external watchdog so a cleanup regression cannot hang the suite.

### Minimal ProcessRunner change proposed for the gate

Track successful spawn ownership and normal completion separately from
`status`/`killed` (the leader may already be reaped while a descendant still owns
a pipe). In `ensure`, if spawn succeeded but supervision did not complete:

* Run cleanup in `Thread.handle_interrupt(Timeout::Error => :never)` so the outer
  runtime watchdog cannot abort a cleanup already in progress. Restore the mask
  immediately after cleanup; do not swallow the pending original timeout.
* Send group KILL directly on this exceptional path, tolerating ESRCH, rather
  than restarting a TERM grace that the watchdog has already interrupted.
* Reap the direct child if not already reaped, tolerating ECHILD; always close
  pipe ends in an inner ensure even if signaling/reaping raises. Preserve the
  original exception rather than replacing it with expected cleanup races.
* Keep the ordinary timeout/cancellation TERM→0.2s→KILL path unchanged except for
  necessary state tracking. Never infer that a reaped leader means its group is
  empty, and never signal after a normally completed supervision path.

The gate must settle whether to mask only `Timeout::Error` (minimal current
watchdog fix) or all asynchronous `Exception` delivery inside this tiny cleanup
region (broader guarantee, with thread-shutdown implications). No Ruby-level
cleanup can promise recovery from SIGKILL or uninterruptible kernel waits;
external test watchdog bounds are not proof of real-time OS scheduling guarantees.

## Minimal telemetry and persistence contract

### Preferred path: existing `Result#logs`, no Struct/schema change

`Result` already has optional duration, usage, cost, logs, session_id and model.
`lib/agent_runtime/runtime.rb:124-127` persists these fields and stores logs as an
immutable text artifact; a Hash becomes JSON. Therefore add structured bounded
execution telemetry inside logs, not a new Result member or mutable sidecar.

Contract-freeze proposed log shape (actual versioned implementation uses the
immutable `logs.execution` envelope and compact attempt references):

```json
{
  "stdout": "bounded captured text",
  "stderr": "bounded captured text",
  "execution": {
    "status": "timeout",
    "exit_code": null,
    "duration": 1.2,
    "stdout_truncated": false,
    "stderr_truncated": true
  }
}
```

Preserve existing stdout/stderr log keys and put new keys under `execution`.
Duration is monotonic elapsed seconds, nonnegative; no exact timing equality is
required. `exit_code` is the runner's observed exit status or null, not invented
from a provider event. Absence/null of usage, cost, observed model or session must
not become fabricated zero/empty values. Do not persist environment values,
credentials, or full argv/prompt by default. Bounded logs are still potentially
sensitive local evidence; this proposal does not assert automatic redaction.

Both normal and malformed/truncated protocol paths must retain lifecycle facts.
In particular, adapter parse rescue must not throw away truncation/exit evidence.
The existing adapter currently keeps only stdout/stderr in logs
(`lib/agent_runtime/adapters/open_code_cli.rb:56-62`). Parent owns that change.

An optional top-level execution record/Result member is **not necessary** for this
milestone. Reconsider only if a concrete consumer needs queryable structured
fields outside the log artifact; that would require explicit shared API agreement,
runtime serialization tests and compatibility coverage, not silent expansion.

### Precise current persisted state

For each actually invoked attempt:

* Before invocation: SQLite attempts row keyed by `(run_id, step_id, attempt)`
  has `attempt`, `status: "running"`, `started_at`.
* At normal runtime completion: that row is replaced with `attempt`, terminal
  `status`, `error`, `duration`, `usage`, `cost`, `session_id`, `model`, plus `log`
  artifact descriptor when logs are non-nil. Terminal data currently **does not
  retain `started_at` or add `ended_at`**. Tests must not promise those fields.
* The same terminal attempt data appears in
  `report["steps"][step_id]["attempts"]`. Reopening Store must recover the same
  final report and immutable log contents.
* Log artifacts are type text, bind run/step/attempt metadata, have digest-checked
  bytes, and currently use empty input lineage. Output artifacts bind the input
  artifact IDs. Do not silently alter log lineage in an adapter-only change.
* Only successful, validated declared outputs enter step/run bindings. Failed,
  cancelled, timeout, unknown and blocked attempts may have logs but no accepted
  outputs. Output-validation failures change the attempt status to failure.
  Earlier individual objects may already exist when later validation fails;
  absence from accepted bindings is the guarantee, not atomic artifact insertion.
* Runtime materializes repository/directory inputs per attempt. Successful
  repository outputs pass through existing Store snapshots/digest checks; do not
  bypass Store with adapter-owned mutable repository pointers or evidence files.
* No crash recovery/transactional completion guarantee is added: a host/process
  crash, or persistence failure outside executor rescue, may leave a running row.
  Terminal-row assertions apply to normally completed runtime calls with healthy
  storage, not killed harness processes.

### Retry safety

Preserve the exact runtime gate:

```ruby
data["status"] == "failure" && data["error"].is_a?(Hash) && data.dig("error", "classification") == "transport" && result.retry_safe == true && index < step["retries"] && !cancellation.cancelled?
```

OpenCode execution is not replay-safe merely because its response is missing,
truncated, malformed, nonzero-exit, or transport-like: it may have edited the
workspace or performed external actions. Keep `retry_safe` unset/false unless
there is explicit evidence replay is safe. Fresh per-attempt repository copies
do not make provider/external side effects idempotent. No retries for timeout,
cancelled, unknown, blocked or semantic failures. Exhaustion persists every
actual invocation as a separate terminal attempt, with independent logs.

## Independent offline test matrix (proposed)

Use Minitest and local Ruby child fixtures (`RbConfig.ruby`), never real provider
calls, credentials or the user's installed OpenCode. Reuse the handshake patterns
from `test/m01_scheduler_test.rb:435-485`; do not rely on startup sleeps. Each child
publishes readiness/PID through a pipe or UNIX socket. A controller waits for
readiness before cancellation; a generous external watchdog bounds every test.
Test teardown closes sockets, kills known surviving fixture processes and joins
threads even after assertion failure. A cleanup assertion must happen **before**
fallback teardown, so the test cannot pass because teardown fixed the leak.

| ID | Stimulus | Required independent oracle |
| --- | --- | --- |
| L01 | Already-cancelled request | cancelled, no spawn marker, empty bounded streams, nil exit code; no child created |
| L02 | Child emits stdout/stderr and exits 0 / nonzero | exact streams, success / failure, actual exit code, nonnegative duration, all pipes closed and direct child reaped |
| L03 | Timeout; child and ordinary descendant ignore TERM | timeout, observed TERM then eventual KILL/group quiescence, direct child reaped; bounded wall time, no live fixture after return |
| L04 | Cancellation after readiness; same descendant fixture | cancelled, no retry, same cleanup proof as L03 |
| L05 | Cancellation and expiry both visible at observation | cancelled precedence using controlled token/clock seam if needed, not a scheduler race |
| L06 | Leader exits but descendant holds inherited output pipe | no early success/deadlock; timeout/cancelled cleans remaining group and returns boundedly |
| L07 | Child closes both output streams then remains alive | EOF does not establish exit; deadline still enforced and child reaped |
| L08 | Runtime outer watchdog interrupts TERM grace | actual runtime timeout path; child ignores TERM; no survivor, no stranded running row after healthy completion; logs absent if outer rescue synthesizes Result |
| L09 | Inject asynchronous Timeout::Error after readiness | runner cleanup executes before exception is propagated/translated; direct child reaped and descendants no longer running |
| L10 | Missing executable, invalid cwd/argv/env/timeout | failure without leaked descriptors/children; no assumption that validation raises to caller; repeat bounded runs to detect descriptor growth |
| L11 | stdout only / stderr only / both exceed cap | exact prefix and marker semantics, correct per-stream flags, aggregate truncation; simultaneous draining cannot deadlock |
| L12 | Exact cap and cap+1 byte boundaries | exact cap is not truncated; +1 is truncated; cap excludes marker bytes; binary/invalid UTF-8 behavior explicitly exercised at serialization boundary |
| P01 | Inject adapter Result carrying proposed logs | report attempt fields equal SQLite row; log artifact parses to expected execution facts; fresh Store reopens same report; digest detects tampering |
| P02 | Each non-success status with partial outputs | one terminal row, no accepted step/run outputs, logs retained when supplied, no transport replay inferred |
| P03 | Safe transport failure then success / exhausted budget | explicit retry_safe true only; numbered terminal rows and separate log artifact IDs; allowed attempts <= retries+1 |
| P04 | Transport classification with retry_safe nil/false | exactly one invocation despite retry budget; transport label alone never authorizes replay |
| P05 | Repository mutated during attempt, then after completion | stored input remains original, accepted successful output remains submission-time snapshot, later workspace mutations cannot rewrite evidence |
| P06 | Success Result with invalid/missing declared output | terminal failure/output_validation, logs preserved, accepted bindings empty; do not assert artifact table is globally empty |
| P07 | Cancellation between safe retry attempts | previous terminal attempt retained, no later invocation/attempt row; preserve existing status aggregation rather than invent cancellation semantics |
