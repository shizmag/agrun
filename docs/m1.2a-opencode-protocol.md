## Actual JSON-lines contract

Every record has `type`, numeric millisecond `timestamp`, and root `sessionID`.
There is no envelope event ID, schema version, model identity, or request ID.
Recognized record types in this renderer:

| Type | Payload and meaning |
| --- | --- |
| `step_start` | `part:{id,sessionID,messageID,type:"step-start",snapshot?}` |
| `step_finish` | `part:{id,sessionID,messageID,type:"step-finish",reason,snapshot?,cost,tokens}`; one model step, not execution terminal |
| `text` | `part:{id,sessionID,messageID,type:"text",text,time:{start,end}}`; emitted text is a suffix/delta, not necessarily a full replacement |
| `reasoning` | Similar to text with optional metadata; emitted only with `--thinking` |
| `tool_use` | `part:{partID,sessionID,messageID,type:"tool",id,tool,state}`; `id` is tool-call identity, `partID` is display-part identity |
| `retry` | `messageID,attempt,nextRetryAt,error`; internal retry is not itself terminal failure |
| `background_wait` | `jobs:[{id,kind,title}]`; not completion or tool execution proof |
| `error` | `error:{type,message,...}`; may have empty session ID before setup succeeds |

Step IDs are `prt_` plus source event ID without `evt_`; reconciliation fallback
is `prt_` plus message ID without `msg_`, plus `_step-finish` or another suffix.
Deduplicate finish accounting by `(sessionID,messageID)` with compatible part
identity; do not deduplicate solely by timestamp or globally by part ID. A
conflicting second finish for the same message must fail closed, not silently
overwrite usage. Text can reuse an identity for suffixes: do not apply generic
whole-record deduplication to text deltas.

Tool states emitted are completed or error, not the full running-state API
schema. Completed state has `status:"completed",input,output,title,metadata,time`;
error state has `status:"error",input,error,metadata,time`. `output` and `error`
are rendered strings. Metadata may contain raw structured content, provider
call/result details, and raw input. Tool errors may be recovered by the agent;
they do not independently mean adapter failure. The renderer can fall back to
`tool:"tool"` with empty input if it did not observe earlier call events.
Reconciliation skips unfinished running/streaming tools.

Usage is nested at `part.tokens`, with independent buckets `input`, `output`,
`reasoning`, `cache.read`, `cache.write`; cost is `part.cost`. Sum unique current
root-session assistant steps, not historical session messages, text events,
tool records, retry errors, or arbitrary numeric metadata. Preserve nested
buckets. `output` excludes reasoning here. A reported zero does not prove no
provider usage: upstream normalization can turn unavailable data into zero.
CLI root usage is not demonstrated to include child/background provider calls;
label it root-step usage, not complete invocation billing.

## Proposed M1.2a adapter contract

1. Keep the CLI backend for this bounded execution milestone. Existing argv
   `opencode run --format json --standalone ... -- <prompt>` matches installed
   help. Do not silently switch to the experimental HTTP/SDK transport or use
   the shared user service. `--standalone` isolates server lifecycle, **not**
   filesystem, credentials, configuration, plugins, network, or persistent state.
2. Preserve live opt-in and existing `Result` fields/statuses. Version/capability
   inspection must use help/version only and never invoke a provider-capable
   probe. Pin/support this audited version explicitly, or classify unsupported
   versions as blocked before admission; do not claim an exhaustive supported
   range from one binary. No new public config/Result API is approved here.
3. Execution success requires successful process termination/exit 0, complete
   nontruncated valid JSONL, coherent session/part identities, no terminal
   `error`, and a valid finish for the admitted root stream. This combines the
   CLI's internal execution-outcome check with observable protocol evidence.
   A `step_finish` alone, a successful tool alone, or text alone cannot succeed.
   Missing terminal evidence/identity/conflicting records is `unknown`, never
   success. A trustworthy explicit CLI error/nonzero exit is failure. Define
   malformed-protocol classification consistently with current public contract.
4. Timeout/cancellation take precedence over all prior parts, even after a
   finish. Truncated stdout can never establish success. Preserve partial logs,
   usage and patch evidence if valid, but mark it partial; do not retry a live
   invocation automatically (`retry_safe` must not become true by inference).
5. Do not require a particular last finish reason such as `stop`: continuation,
   output-limit recovery and background work are owned by CLI execution state.
   Preserve reasons as evidence, and test that intermediate `tool-calls` or
   `length` cannot independently succeed. Exit 0 alone also cannot succeed.
6. Preserve observed session ID and configured model selection distinctly from
   actual resolved model evidence: this JSON stream cannot prove actual provider,
   variant or model. Do not manufacture an observed model from the last part.
7. Default permission requests are rejected; questions are cancelled and the
   solver may continue. Do not silently append `--auto`: it expands permission
   approval. If future requirements require tools to be permitted, use an
   explicitly approved policy/configuration contract. Read-only/denied tool
   runs may still complete successfully; solver success is not task verdict.

### Termination and transport limitations

The CLI has explicit internal cancellation logic: cancel unpromoted admission,
interrupt root and known subagents, remove shell jobs, then wait; image jobs can
be exempt from that wait. This is **not evidence** that agru killing a process
group invokes that path or stops external remote effects. Source audit did not
establish signal-handler wiring or end-to-end descendant reaping. Do not claim
hard cancellation, sandboxing, zero leaked children, or complete tool tracing.
Public `ProcessRunner` timeout/cancellation status is the execution boundary;
provider-side cessation needs separate verification, never a live audit probe.

Choose a separately versioned transport workstream if requirements demand
admission IDs, explicit terminal events, resolved model identity, running tool
states, full descendant usage, or server-side interrupt acknowledgement. The
experimental API exposes useful building blocks but requires location/auth,
subscription-before-admission, correlation, reconnect/replay, permissions,
background-drain and lifecycle contracts; simply replacing argv with HTTP would
not fix these guarantees. Adjacent 1.17.6 SDK types are not a safe shortcut.

## Independent offline test matrix

All cases below use source-derived synthetic JSONL and a fake runner; no
credentials, installed-provider calls, or live sessions. Clearly label fixtures
as synthetic, never as captured real-provider traces.

| Area | Cases / required assertion |
| --- | --- |
| Admission | No opt-in blocks before runner; explicit opt-in invokes once; empty/missing/nonstring prompt fails configuration; argv uses standalone and literal prompt after `--`; no implicit `--auto` |
| Capability | Audited version/help accepted; unsupported version/missing JSON/standalone capability blocked before run; probe uses only help/version; executable absence is not success |
| Happy path | start/text/finish, exit 0 yields execution success and patch; multiple model steps succeed only after process completion; zero-token valid finish remains valid |
| Completion traps | Finish then nonzero, finish then error, finish then timeout/cancel, text-only, tool-only, empty output, start-only, finish with missing identities never succeeds |
| Continuation | tool-calls then second step; length then recovered step; intermediate finish followed by failure; final reason is evidence, not an allowlisted terminal marker |
| Correlation | Envelope/part session mismatch; configured session mismatch; mixed sessions; missing message/part ID; empty setup-error session; no envelope event ID expected |
| Accounting | Two unique messages sum five token buckets and cost; duplicate finish counted once; conflicting duplicate rejected; malformed/nonnumeric/negative/nonfinite cost/token values cannot be silently coerced to trustworthy totals |
| Accounting scope | Historical/foreign-session parts rejected; tool metadata numbers ignored; reasoning and output not conflated; child usage absence not represented as complete billing; absent usage differs from explicit zero where observable |
| Text | Reused part ID with suffix deltas appends in order; interleaved tool/retry/step events do not discard text; reasoning absent by default; UTF-8 and escaped newlines parse |
| Tools | Completed input/output, error string, partID distinct from call id, fallback tool name, structured metadata; tool error followed by successful execution is not adapter failure; unfinished tool not treated as completed |
| Retry/background | retry alone not terminal error or extra usage; background_wait alone cannot succeed; final root finish after background processing parsed without counting jobs as usage |
| Framing | Blank lines policy explicit; malformed middle/final line, scalar/array JSON, unknown types, truncated stdout, truncated stderr, partial final record, no trailing newline, oversized bounded capture never create false success |
| Failure precedence | timeout vs prior finish; cancellation vs prior finish; nonzero vs valid JSON; structured error on exit 0 fails; truncated stderr policy documented separately from stdout completeness |
| Replay | Failure/timeout/cancel/unknown never authorize transport replay; `retry_safe` absent/false; resumed sessions not automatically reused by a second invocation |
| Evidence | Session and requested model retained without asserting observed model; raw logs/partial patch preserved under failure as allowed; execution status remains separate from evaluation verdict |

Open integration decisions: exact malformed-record error type, unknown-event
policy (ignore compatible extensions vs block unsupported schema), duplicate
finish equivalence rules, version-probe caching/injection seam, and placement of
partial/root-only usage metadata inside existing result/log contracts. These
need coordination before implementation rather than an unreviewed API change.
