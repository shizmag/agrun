## Acceptance coverage and known limits

`script/m11_acceptance.rb` persists a fresh 16-cell matrix (two fixture tasks ×
four solver architectures × one fixture profile × two repetitions), immutable
submissions, a separate regrade, and JSON/CSV/Markdown exports in SQLite/Store.
It explicitly records official acceptance as blocked. Contract/negative tests
exercise identity, missing resources, public fields, submissions, failures,
binding, traversal/symlinks, matrix preservation, interruption, report aggregation,
offline rejection, parity and repeat preparation. This is not a claim that all
18 official acceptance scenarios have passed.

Sequential scheduling is explicit (`effective_parallelism: 1`), not a distributed
queue. Live solvers and paid models are disabled. Fixture budgets are not evidence
of enforceable real-agent token/cost budgets. Missing usage remains unknown.
Paired reporting is a seam; confidence intervals, significance tests and research
comparison are not implemented. No quality advantage is inferred from fixtures.
Same-user host access is trusted; directory separation is not an OS sandbox.

Independent review findings, repairs and isolated mutation results are recorded in
`docs/m1.1-adversarial-review.md`. Not all suggested mutations have been attempted.
