# M1.1c audited NL2Repo promotion contract

Status: **policy and integration implemented; real persisted local controls pass**.
This is scoped audited quality, not authenticated official scoring. Existing
diagnostic evidence must remain untrusted.

Unscored audited results retain `protocol: nl2repo-audited-v2`, nil score, and nil
`quality_basis`. The additive `failure_category` distinguishes
`protocol_violation` (rejected receipt/binding or explicitly invalid structured
report), `infrastructure` (complete but failing fresh reference control), and
`unavailable` (ambiguous or missing evidence, timeout, or unattributed transport
error). Missing reports or transport errors alone do not establish setup
attribution. The existing `reason` preserves diagnostic detail.

The procedure digest binds the transport, validator and promotion source hashes,
in addition to the protocol and pinned tests. Collector source is independently
bound by `collector_digest`; neither validator nor promotion source may be omitted.
Ruby transport, validator, promotion and adapter source hashes are captured at
load. Source changes after load fail closed with a restart-required diagnostic;
the adapter hash is also included in the procedure digest. Transport rechecks
loaded-source freshness before execution and after candidate execution. The
copied Python collector must match the request's `collector_digest` before a
container is launched, preventing request-to-execution source drift.

## Minimal integration API

Keep `prepare_grading_request`, `grade_submission`, and `normalize_score` as the
public adapter API. Parent's current ownership split proposes D-owned policy in
`lib/agent_runtime/benchmarks/nl2repo_audited_promotion.rb`:

```ruby
NL2RepoAuditedPromotion#call(request:, evidence:)
```

`grade_submission` invokes it only for the audited grading procedure. `request`
is the adapter-created frozen grading request, not a solver-created hash.
`evidence` is an opaque in-memory transport-issued token, not candidate stdout or
a decoded hash. `transport.consume_evidence(request:, evidence:)` returns a
privately issued record once, only for the identical adapter-issued request.
Forged, serialized, copied-request and replayed tokens cannot establish trust.
No candidate/infra outcome enumeration is needed. C owns exact collector
field names; B owns manifest/preflight shape; E owns report plumbing.

Preserve the existing result dimensions: `execution_status`, `score`, `verdict`,
and explanatory evidence/reason. The adapter currently uses `trust`, while the
container transport uses `result_authority`; reconcile those fields with C rather
than introducing another classification. Diagnostic/native-regex
output remains `untrusted`, even if it claims the right identities or counts.
`normalize_score` alone cannot authenticate a hash supplied by a caller. It
currently returns `nil`, not an unavailable result hash; preserve that scalar
normalization contract. Existing unavailable grading uses `status: unavailable`
and `verdict: untrusted`; the table's unavailable verdict is a policy description,
not authorization to silently change the parent-frozen verdict vocabulary.

Proposed grading result uses `status: completed`, `execution_status: success`,
`verdict: pass|fail`, `trust: audited`, and native numeric `score` for supported
quality outcomes only with `trust_scope: benign_ordinary_submissions`; no
`authenticated` flag is permitted. Set `protocol: nl2repo-audited-v2` and
`quality_basis: validated_quality_result` for complete accepted case results or
`quality_basis: candidate_collection_failure` for the supported missing-module
rule. Existing `passed`/`total` alias numerator/denominator; evidence also retains
`expected`, `collected`, `executed`, `failed` and `skipped` as defined in the
scoring contract. This scoped model replaces the universal authentication gate
only for this protocol, without revising historical claims.
Unscored output keeps `status: unavailable`, `verdict: untrusted`,
`trust: untrusted`, `score: nil`, and the actual `execution_status`. Include reason
and private evidence/artifact references. Parent decisions freeze these literals.

Transport API: `grade(submission:, binding:, expected_nodeids:, request:,
cancellation: nil)` returns the opaque token. Consumed private record keys:
`protocol`, `binding`, `expected_binding`, `expected_nodeids`, `candidate`,
`reference`, `candidate_inventory`, `execution_status`, `candidate_evidence`,
`reference_evidence`. Binding and identities
must match request `audited_binding` and `expected_nodeids`. Candidate/reference
are C-parsed results. Transport verifies fresh same-clean-path reference binding
before issuance. `candidate_inventory` contains `submission_digest`,
`missing_required_module: true`, and `checked_paths: ["retrying.py", "retrying"]`
for supported absence. It is derived from the verified snapshot before execution,
with dangling symlinks counted as present. Candidate/reference evidence carries
immutable raw artifact references. Collection-zero also requires explicit empty
`collected` and no `tests`/`counts` payload in the parsed collection-failure result.

Parent owns `NL2RepoAuditedGrader` transport, Docker, preflight, and raw artifacts.
C's proposed `AuditedResults.parse(bytes:, expected_nodeids:, expected_binding:,
process:)` returns valid tests/counts or invalid reason, never a score; its
structured collection-failure branch supplies attribution evidence. D owns
promotion policy and `adapters/nl2repo.rb` integration only after freeze.

## Binding and preflight, before executing candidate code

Verify the stored submission bytes/tree, adapter-issued request identity, task
ID, specification digest, benchmark revision, manifest digest, audited procedure
digest, immutable image digest, platform/environment policy, and control evidence.
Compare against expected values from the current verified adapter/task, not only
against values echoed by the collector. Bind controls to the same procedure,
image, protected test bytes, and environment policy. Reject stale receipts,
changed manifests, unknown tasks, substituted repositories, missing bindings,
and unsupported procedures before launching candidate evaluation.

Required controls are known-good, deliberately broken, empty, and output-spoofing
submissions. Controls establish channel/procedure behavior; they do not prove a
security sandbox. Trusted Ruby and candidate Python remain outside such a claim.
Preflight and collector artifacts are private evaluator material, never solver
workspace inputs. A valid-looking stdout JSON object is not a collector artifact.

## Decision table (not another enum)

| Evidence | Existing result dimensions | Authority |
| --- | --- | --- |
| Exact-bound complete evaluator-owned per-test results | Completed execution; native score; `pass` only at full score, otherwise `fail` | Audited procedure only |
| Exact-bound missing-required-candidate-module proof | Completed evaluator execution; score `0.0`; `fail` | Audited procedure only |
| Missing dependency, grader bootstrap/install failure, image/container failure, invalid preflight or binding | Failed/blocked execution as appropriate; score `nil`; `unavailable` | No quality authority |
| Collection error with no supported attribution | Preserve execution fact; score `nil`; `unavailable` | No quality authority |
| Timeout/cancellation, truncated/malformed collector record, incomplete results | Preserve timeout/cancellation/error; score `nil`; `unavailable` | No quality authority |

Test failures and collection-zero are quality outcomes, not infrastructure
failures. A nonzero pytest exit is not enough to select either row. A successful
transport is not enough to establish a score. Do not synthesize zero from empty
counts, a missing summary, or an exception's spelling.

For the selected task, use the frozen audited native denominator; do not silently
change it to the number collected or the manifest's differently defined count.
Reject duplicate test identities, impossible/nonfinite counts and scores, and
unsupported mixtures of partial results and collection errors. Collection-zero
must be an explicit supported procedure rule, not generic rescue behavior.

## Missing required candidate module: sufficient evidence

The evaluator, before any candidate import/code execution, observes the verified
submission snapshot using a fixed task-owned required-module inventory. For
`retrying`, the audited procedure must explicitly pin the accepted module/package
locations and semantics; it must not infer them from candidate error output.

Record an evaluator-owned inventory/probe tied to the submission digest, required
module name, checked locations, and trusted procedure version. Prove absence of
every location allowed by that version. Reject symlink/path escapes. Do not use
`find_spec`, candidate-controlled import hooks, candidate `sys.path`, package
installation output, or `ModuleNotFoundError: retrying` text as absence proof.
If discovery supports generated modules, editable installation, extensions, or
other unenumerated import forms, a missing-file probe is not conclusive: leave
the result unscored until that form has a supported evaluator-owned check.

The proof is a privileged collector observation, not a Boolean the candidate can
print. Candidate-created structured-looking files or stdout markers must fail
closed. If the required module is present but its import raises an exception,
that is **not** absence; score only under a separately audited attribution rule.
Missing third-party dependencies are not missing candidate modules.

For the parent-selected `retrying` procedure, collection-zero requires all of:

* Neither `retrying.py` nor the `retrying/` directory exists in the verified
  submitted artifact, observed before candidate code runs.
* C's trusted plugin reports the actual collection exception as
  `ModuleNotFoundError` with `.name == "retrying"`, not parsed traceback text.
* The known-valid local reference passes a fresh preflight for this attempt,
  using the same clean evaluation path and exact procedure/environment binding.
* Candidate and reference results pass the complete exact-binding gate.

Absent files alone or the exception alone is insufficient. A nonempty defective
module's import failure remains ambiguous/unscored. Unsupported alternative module
forms remain outside this policy until explicitly audited.

## Timeout rule

Timeouts remain unscored even if stdout contains a passing summary, the module
appears absent, or some tests finished. A future timeout-to-zero policy requires
an explicitly pinned, controlled procedure change and new acceptance tests; it
is not enabled by this proposal.
