## Thin fixture and oracle boundary

Create a local, deterministic miniature Ruby repository with one function
`clamp(value, lower, upper)`. A correct patch implements inclusive lower/upper
bounds; a wrong patch passes a middle-value public example but mishandles an
out-of-range/boundary case. A separate hidden procedure has literal table cases,
including negative bounds and both clipped ends, and emits the documented
`AGRU_VERDICT=` marker with matching exit 0/pass or 1/fail. Invalid-bound behavior
is explicitly excluded unless the fixture specification defines it.

The repository, public specification, good/wrong source strings, hidden-procedure
bytes, and literal expected tuples are test-owned, not imported from production
`Benchmarks::Fixture` or `Solvers::Fake`. A trivial local solver writes those
literal patch bytes into its supplied workspace and returns the public solver
result hash. At least one acceptance variant uses a tiny compiled Runtime DAG
through `AgentRuntime.compile` / `Runtime#run` so attempts are genuine runtime
records, not invented benchmark attempts. Reuse public test setup patterns only;
do not reuse an existing expectation or production verdict classifier as oracle.

Separate three responsibilities in the helper:

1. Build fresh temp stores, task/workspaces, controlled environment, barrier-based
   local executors/solvers, and bounded teardown. No production-private methods.
2. Observe execution and reopen persisted artifacts/reports; return plain data.
3. Compare with an explicit case descriptor: expected execution status, verdict,
   solver status, expected file bytes, required binding changes, and exact
   attempts. Do not calculate expected statuses from actual status/exit/marker.

Use `Store.new`, `Store#report`, `Store#value`, `Runtime#run`,
`Evaluation::Evaluator#evaluate`, and `Benchmarks::Runner#run` as public seams.
Queue/pipe readiness handshakes establish overlap or cancellation points; timeout
guards bound every wait and teardown releases barriers and terminates children.
Random IDs/paths/timings are observations, not deterministic golden strings.

## Persisted inspection protocol (all acceptance criteria)

The returned Ruby hash is not sufficient evidence. After each operation, create
a new Store instance on the same root and read `Store#report(run_id)` when a run
report is required. Parse the matching benchmark `result.json` and `result.csv`
and compare semantic fields and IDs, not formatting or float timing. A direct
Evaluator call stores an evaluation-report artifact, not a benchmark run record;
do not demand `Store#report` for such a call unless the contract changes.

Resolve artifact references via persisted metadata, verify UUID/run/step/attempt
and input provenance, then read content with `Store#value`. For attempts, use
read-only SQLite queries against the documented `attempts` table because Store
currently has no public attempt reader (`lib/agent_runtime/store.rb:79-81`). This
is an explicit persistence-format dependency for tests, not permission for
production components to reach into Store internals. Confirm the schema choice
at freeze; prefer a parent-approved public read API if one is added.

Compare exact attempt keys/statuses to case-owned counts, including absence of
attempts for gated dependents. A benchmark solver with no Runtime run need not
manufacture attempt rows: output `attempts: []` and record its actual benchmark
run; DSL-backed cases expose the linked Runtime run ID separately.

Recompute SHA-256 independently from stored bytes. Repository digest oracle is
a fixture-built canonical sorted manifest of relative paths, executable boolean,
and Base64 file bytes; exclude `.git`, not arbitrary dotfiles. Do not call
`Store.manifest` or `IR.digest` to build the expected digest. Specification and
environment JSON use independently canonicalized key ordering; procedure is
exact bytes. Cross-check object bytes, materialized tree bytes and metadata,
rather than comparing two fields produced by the same production function.

The evaluation artifact contains bindings and execution evidence but does not
contain its own `report_artifact` reference; avoid demanding recursive equality.
Current creation point: `lib/agent_runtime/evaluation/evaluator.rb:54-59`.

## Later offline output and exit contract

Proposed script runs the same descriptors without parsing Minitest text and emits
JSON plus a short human table. A descriptor result contains:

```json
{
  "case_id": "HC02.valid-fail",
  "expected": {"solver_status": "success", "execution_status": "completed", "verdict": "fail"},
  "actual": {"solver_status": "success", "execution_status": "completed", "verdict": "fail"},
  "match": true,
  "error": null,
  "artifact": {"repository": "artifact-id", "evaluation_report": "artifact-id"},
  "run": {"benchmark_run_id": "run-id", "runtime_run_id": null},
  "attempts": [],
  "evidence_paths": {"store": "retained-root/store", "result_json": "retained-root/run/result.json"}
}
```

`match` is the independent comparator's result, not production success. A
deliberate wrong patch is a matching harness case. `error` means harness/setup or
observation error; expected evaluator diagnostics remain under `actual`, not
silently converted to harness failures. Suggested exit 0: all match; 1: oracle
mismatch; 2: harness/setup error (priority over 1). Summary lists planned,
executed, matching, mismatched, and errored variants; no silent skips count as
passes. Output records schema/version and offline mode. Do not print full ENV or
secret-bearing logs. Retain evidence under an explicit output directory outside
versioned source; paths must remain usable after the command exits. Default test
temp directories can still clean up normally.

## Freeze questions and blockers (do not normalize bugs into expectations)

1. **Stale evidence boundary:** architecture requires all four versions to match
   for reuse, but no reuse method exists. Accept evidence-inapplicability proof,
   or explicitly define a public reject/re-evaluate API with its owner.
2. **Interrupted operation durability:** `docs/architecture.md:69-71` excludes
   resumability. Runner currently persists only after evaluation or Ruby rescue
   (`lib/agent_runtime/benchmarks/runner.rb:48-69`); hard kill may leave no terminal
   run report. Decide whether AC07 requires cooperative terminal persistence only,
   durable in-progress records, or crash reconciliation. A missing hard-kill report
   must not be called a passing terminal-persistence test. New guarantees need
   parent-approved contract/production work, not an F test workaround.
3. **Status vocabulary:** freeze per-boundary spawn-error/exception expectations
   (`failure` versus `error`), dependent cancellation precedence, and interrupted
   run terminal status. Preserve valid `success` + `completed/fail` combinations.
   Evaluator has no cancellation argument today; do not invent one in HC08.
4. **Attempts:** approve read-only SQLite inspection or supply public read API;
   confirm how a DSL-backed solver exposes its Runtime run ID. Never fabricate
   benchmark attempts to satisfy a report column.
5. **Environment scope:** inherited ENV digest is provenance, not environment
   isolation or a lockfile. Hold inputs stable within one process, test one benign
   sentinel change, and restore it. Do not require identical host environments.
6. **Safety and ownership:** temporary directory separation is not a security
   sandbox. Trusted Ruby, local subprocesses and read-only evidence checks only;
   no network, live models, hidden-test copying into solver workspaces, or claim
   of containment. Parent approves later script/task paths with CLI owner.
