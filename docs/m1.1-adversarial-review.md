## Findings

1. **P1 — Regrade binding:** `lib/agent_runtime/benchmarks/experiment_runner.rb:50-60` and `lib/agent_runtime/benchmarks/experiment_runner.rb:126-136` reload the current task and prepare a new request without comparing its specification, procedure, evaluator/normalizer, or environment bindings to the original grading attempt. Dataset revision and adapter identity alone do not ensure the original evidence remains valid. Fix: persist and compare the original effective bindings, fail closed on mismatch, and test each independently.
2. **P1 — Failed regrade overwrites active result:** `lib/agent_runtime/benchmarks/experiment_runner.rb:126-131` and `lib/agent_runtime/benchmarks/experiment_runner.rb:153-163` clear score and verdict before the new grade succeeds. A failed regrade overwrites the cell fields used by summaries even though historical attempts remain. Fix: preserve the previous valid result and record failed attempts independently; test persistence and summary behavior.
3. **P1 — Container deadline, provisional:** `lib/agent_runtime/benchmarks/container_grader.rb:23-32` and `lib/agent_runtime/benchmarks/container_grader.rb:36-55` appeared to lack a deadline and cancellation at the process boundary. This finding requires verification: C reports that `@runner.call` may already receive timeout/cancellation, and is investigating. Do not treat this provisional observation as confirmed.
4. **P2 — Fixture request-authentication mutation survived original adapter tests:** `lib/agent_runtime/benchmarks/fixture_adapter.rb:56-57` and `lib/agent_runtime/benchmarks/fixture_adapter.rb:97-103` authenticate prepared requests, but removing the validation survived the original fixture adapter test file. 5. **P2 — Runner offline guard mutation survived original runner tests:** Removing the explicit offline mode check at `lib/agent_runtime/benchmarks/experiment_runner.rb:65-70` survived the original runner test file. Other fixture-only restrictions remain, so this does not establish an actual provider call. E is adding coverage; verification pending.

## Follow-up verification after E and B changes

- **Failed regrade preservation: resolved for the tested failure case.** Updated `ExperimentRunner#grade` saves/restores active result fields on failure and records the failed grading attempt; `test_failed_regrade_preserves_prior_active_evaluation` exercises persistence and summary. Binding drift checks compare task, benchmark, specification, submission, procedure, environment and limits; the procedure-drift test confirms rejection and preserved score. **Remaining binding concern:** evaluator and normalization implementation versions are not independently included in the compared bindings (`lib/agent_runtime/benchmarks/experiment_runner.rb:145-148`); a change in `normalize_score` with identical procedure/environment digests is accepted. Regrade also permits `original_request` to be absent, so an initial failed preparation can later be graded without an original request to compare. Add version/source digests covering actual evaluator and normalizer, and fail closed when a regrade has no original binding.
- **Fixture request authentication coverage: resolved.** Repeated the mutation against B's updated inline `raise ArgumentError, "unrecognized or modified grading request"` guard in a fresh copy: 8 runs, 71 assertions, 3 failures. In particular, the forged-token/cross-request substitution test killed it.
- **Offline mode:** `test_live_mode_is_rejected_before_solver_work` now proves a live manifest is rejected before the solver runs. The runner-only guard mutation still survives (14 runs, 83 assertions) because `ExperimentManifest` independently rejects live mode first. This is defense in depth, not a demonstrated offline bypass; a direct runner-guard mutation test would need an already constructed/tampered manifest or a different boundary test.
- **Container deadline finding withdrawn:** current `ContainerGrader#call` supplies `timeout: timeout` and `cancellation: cancellation` to `@runner.call` (`lib/agent_runtime/benchmarks/container_grader.rb:33-35`). I did not verify Docker cleanup behavior; timeout/cancellation precedence is checked at lines 63-66. No native official validation was performed.
