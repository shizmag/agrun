# M0.1 D — adapter and reporting verification plan

## Status and scope

Parent freeze received; local fixture verification implemented in
`test/m01_adapter_reporting_test.rb`, with no production changes or commits.
The original design table below is retained; execution results follow at the end.
Existing tests are evidence of baseline
coverage, not fresh M0.1 acceptance. Parent baseline: `54ddacf`, branch
`feat/m0.1-verification`, 42 runs / 182 assertions green (parent-supplied).

This plan covers the local OpenCode CLI boundary, subprocess termination,
attempt/run persistence, and benchmark JSON/CSV reporting. It excludes crash
recovery, live provider compatibility, capability scoring, hostile-process
containment, and broader compiler/evaluator redesign. Coordinate shared API
changes with the parent; do not repair production code before freeze.

## Existing evidence versus new coverage

`test/integrations/adapters_test.rb` already exercises direct argv/cwd, bounded
output, missing executable, timeout/cancellation, opt-in, basic event translation,

repository cwd and one untracked patch. Extend with adversarial streams, process

## Freeze questions / explicitly untested limitations

- **U-01 — interrupted status precedence.** CLI translation can overwrite process
  timeout/cancelled with permission `blocked` when a matching event exists. Freeze
  whether interruption must dominate; regardless, never accept success or a pass.
- **U-02 — cap/framing uncertainty.** ProcessRunner caps each stream at 1,048,576
  bytes without a truncation flag; retained complete-prefix JSON could omit a
  later error. Test incomplete-tail unknown deterministically; acceptance of a
  complete-looking truncated prefix is a separate explicit defect hypothesis.
- **U-03 — generation meaning.** Store schema has artifacts, runs and attempts,
  not a generations table. Interpret generations as attempt-qualified lineage
  unless parent defines another requirement. No schema/API expansion in this plan.
- **U-04 — report completeness.** Benchmark rescue persists failure/error but may
  omit evaluation/solution and therefore metrics; CSV blanks are observable, not
  necessarily a contract violation. Freeze whether every exceptional report must
  explicitly carry `not_evaluated`. No crash recovery expectation.
- **U-05 — cancellation surface.** Runtime accepts a token; benchmark Runner does
  not. Cover graceful runtime cancellation with a real local process and benchmark
  cancellation with an injected returned status. Do not pretend this proves
  benchmark CLI signal handling or restart semantics.
- **U-06 — local protocol scope.** Generated event fixtures verify the current
  decoder's assumptions only. Nested malformed token/cost/model shapes need parent
  decisions before claiming a comprehensive OpenCode schema. Live usage accuracy,
  provider cost correctness, real agent execution and service transport remain
  untested.
- **U-07 — deterministic termination.** POSIX PID checks need bounded retries and
  ensure cleanup, handling zombies separately from live workers. Use wide timing
  bounds and marker readiness; no exact duration assertion or security sandbox
  claim. Adapter Git snapshots add fixed 10-second operations outside provider
  timeout and runtime's outer timeout may interact with them: test integration,
  report the result, do not infer cleanup solely from runner unit results.
- **U-08 — idempotency boundary.** Existing report/attempt upserts and byte-store
  deduplication support D-18; matrix reruns intentionally create new run IDs.
  There is no general replay/exactly-once/crash-recovery contract.

After freeze, implement only the agreed D subset, run targeted Minitest via mise,
then coordinate full `mise run test` and `mise run lint` with parent. Report each
D-ID as pass/fail/blocked/untested with observed evidence and any independent
oracle limitations; do not turn this design document into an acceptance record.
