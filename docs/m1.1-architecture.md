# M1.1 benchmark architecture

The benchmark extension lives in `AgentRuntime::Benchmarks`. It preserves the M0.1
compiler, DAG scheduler, executor, artifact generation and evaluation APIs. Read
`docs/m1.1-contracts.md` for the frozen interfaces and trust gates.

## Data flow

1. A registered adapter supplies a pinned identity and public task information.
2. `ExperimentManifest` freezes a canonical configuration and expands the full
   task × solver × model × repetition matrix into stable, unique cells.
3. The experiment runner persists that matrix before executing a cell. Every
   attempt gets a fresh workspace and a unique attempt identity.
4. Offline fixture solvers exercise four architecture categories. Their scores
   demonstrate infrastructure only, not agent capability. Live providers are
   rejected, rather than silently exceeding an unenforceable budget.
5. Generated repositories enter the existing immutable Store. A grading request
   binds the submission, task specification, procedure, dataset and environment.
6. An adapter grades independently. The fixture adapter only reads inert data;
   it never executes submitted code. Official NL2Repo execution requires a
   separate container boundary and validated score collector.
7. Experiment records and raw grading records remain in the existing SQLite
   Store. Reports derive aggregates from cells, preserving unavailable and
   incomplete cells. Regrading refers to a stored generation, not solver state.

## Deliberate limits

This is a local runner, not a distributed queue or crash-resume service. Effective
parallelism may be lower than the configured upper bound and is reported. Model
usage that is not observed remains unknown, never measured zero. Repetitions on
one task are not independent benchmark tasks.

Source pinning is necessary but insufficient for reproducibility. Official
operational readiness also needs immutable image references, dependency and
platform evidence, protocol agreement and real positive/negative controls. A
missing prerequisite yields an infrastructure outcome without a quality score.
There is no fallback to executing untrusted submissions on the host.
